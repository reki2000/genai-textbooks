# エージェント間の書面協議

Codex と Claude が `/discussion/` 配下のファイルを交換して議論し、`conclusion.md` で合意を残す。人間が両者の発言をコピーして往復させる必要をなくす。

## プロトコル

```
/discussion/
  CURRENT              ← 進行中の議論ディレクトリ名を1行だけ書いたファイル
  {yyyymmdd-hhmiss}-{topic}/
    1.to-claude.md     ← Codex が書き、Claude が読む
    2.to-codex.md      ← Claude が書き、Codex が読む
    3.to-claude.md
    4.to-codex.md
    ...
    conclusion.md      ← 合意後に、合意を検知した側が書く
```

**ディレクトリ名は開始日時＋話題。** `date +%Y%m%d-%H%M%S` の値に `-{topic}` を付ける（例：`20260802-143012-sidebar-layout`）。`{topic}` は英字ハイフン区切りの短い語。日時を先頭に置くことで、`/discussion/` を並べたとき議論そのものが時系列に並ぶ。

**ファイル名は「通番＋宛先」。** 通番は議論全体で1本の連番で、往復ごとに1ずつ増える（自分と相手で別々に数えない）。`{N}.to-<相手>.md` を書き、`{N}.to-<自分>.md` を読む。ファイル名を並べ替えれば発言順になるので、途中参加でも `ls` だけで文脈を復元できる。10通を超える議論が見込まれるなら最初から `01.` `02.` と2桁ゼロ詰めにする。

`/discussion/` は `.gitignore` 済み。議論の過程はコミットしない。成果物（スキルやコードの変更）だけをコミットする。

## 進行中の議論の特定（`discussion/CURRENT`）

**過去の議論ディレクトリを読みに行ってはならない。** どれが生きているかは `discussion/CURRENT` だけが決める。日時が新しい順・更新時刻順といった推測で選ばない。

```bash
cat discussion/CURRENT     # 例: 20260802-143012-sidebar-layout
```

これにより、ユーザーは相手側エージェントに「議論して」とだけ言えばよい。ディレクトリ名を伝える必要はない。

- 議論を**開始**した側が `CURRENT` を書く（上書き）。
- `conclusion.md` を書いた側が `CURRENT` を**削除**する。以降その議論は過去のものになる。
- `CURRENT` が無い状態で「議論して」と言われたら、進行中の議論は無い。過去ディレクトリを漁らず、新しい議論を始めるのか（話題は何か）をユーザーに確認する。
- `CURRENT` があるのに新しい議論を始めるよう求められたら、その議論を打ち切ってよいかユーザーに確認する。同時に2本は走らせない。
- `CURRENT` の指すディレクトリが存在しない、または中身が空なら、勝手に直さずユーザーへ報告する。

## 絶対の禁止事項

**相手宛のファイル（`N.to-<相手>.md`）以外を書いてはならない。**

特に、自分が読む側のファイル（`N.to-<自分>.md`）を自分で作成することは、相手の発言を捏造する行為にあたる。相手の返信が来ないときは待つか、ユーザーへ報告する。相手が何と答えるかを予測して先へ進めない。

## 開始する（自分から議論を始める場合）

1. `discussion/CURRENT` を確認する。存在するなら上記のとおりユーザーに確認する。
2. `{topic}` を決め、ディレクトリを作って `CURRENT` に登録する。`.gitignore` に `/discussion/` が無ければ追加する。

```bash
D=$(date +%Y%m%d-%H%M%S)-{topic}
mkdir -p "discussion/$D" && printf '%s\n' "$D" > discussion/CURRENT
```

3. `discussion/$D/1.to-<相手>.md` を書く（構成は下記）。
4. **ユーザーに、相手側エージェントを起動するよう依頼する。** 渡す起動プロンプトはこれで足りる。ディレクトリ名は `CURRENT` から相手が読む。

```
このリポジトリでは <自分> と共同作業をしています。/discuss で議論に参加してください。
```

（相手が discuss スキルを持たない場合の雛形）

```
discussion/CURRENT に書かれたディレクトリで <自分> と議論しています。
そのディレクトリの N.to-<相手>.md を通番順に読み、返信を {N+1}.to-<自分>.md に書いてください。
通番は議論全体で1本の連番です。合意できたら、気づいた側が conclusion.md を書き、
discussion/CURRENT を削除してください。
```

5. 相手の返信を待つ（下記「待つ」）。

## 参加する（相手から提示された場合）

1. `D=$(cat discussion/CURRENT)` で進行中の議論を特定し、`ls discussion/$D/` で並びを確認する。`N.to-<自分>.md` を通番順にすべて読む（過去の往復も含む）。
2. 議論の対象となっている実体（コード、スキル、設計文書）を**自分で確認する**。相手の記述を鵜呑みにしない。
3. 通番を1つ進めて `{N+1}.to-<相手>.md` を書く。
4. 相手の次の返信、または `conclusion.md` を待つ。

## 待つ

相手が書き終えるまでポーリングする。1回のコマンドで待ち切るほうが、短い待機を何度も繰り返すより安い。

```bash
D=discussion/$(cat discussion/CURRENT)
for i in $(seq 1 110); do
  [ -f $D/{N}.to-<自分>.md ] && { echo FOUND; exit 0; }
  [ -f $D/conclusion.md ]  && { echo FOUND_CONCLUSION; exit 0; }
  sleep 5
done
echo TIMEOUT; ls $D
```

タイムアウトしたら勝手に議論を進めず、ユーザーへ「相手からの返信がまだない」と報告する。

## 書き方

議論の価値は往復数ではなく、**1通あたりに何が確定するか**で決まる。

- **論点ごとに、同意・修正・反対を明示する。** 「おおむね同意」で済ませない。表形式で項目ごとに態度を示すと、相手が差分だけを扱える。
- **主張は測って裏づける。** 「多いと思う」ではなく実際に数えた値を出す。相手の測定値は再現を試み、一致・不一致を報告する。数字が議論を最も速く収束させる。
- **自分の誤りは明示的に撤回する。** 「撤回する」「これは不正確だった」と書く。曖昧に言い換えて残すと、相手が過去の主張が生きていると誤認する。
- **相手の指摘が正しければ、根拠ごと採用する。** 結論だけ合わせて理由を自分の元の論法で書き直さない。
- **未解決の論点を末尾に列挙する。** 次に何を決めるかが相手に分かる状態で閉じる。
- **末尾に `合意` または `継続協議` を明記する。** 相手がループを終えてよいかを判断できるようにする。
- 相手に返してほしい内容を、番号付きで具体的に依頼する。

## 提示ファイルの構成（目安）

```markdown
# <自分>から<相手>へ：{題名} N

## 目的 / 総括
何を決めたいか。前回からの立場の変化。撤回した主張。

## 一致していると理解する点
番号付きで列挙する。相手が「そこは違う」と言える形にする。

## 論点1 …
現状の対立、自分の案、根拠（測定値・コードの該当箇所）、相手に判断してほしいこと。

## 提案する暫定合意
番号付き。そのまま conclusion.md の骨格になる粒度で書く。

## 返信してほしい内容
1. …
2. …

**合意** または **継続協議**
```

## 合意したら

双方が `合意` を明記した時点で、気づいた側が `conclusion.md` を書き、**同時に `discussion/CURRENT` を削除する**（`rm -f discussion/CURRENT`）。消し忘れると、次に「議論して」と言われた相手が終わった議論に返信してしまう。相手は `conclusion.md` を読んで検証し、相違があれば次の往復で指摘する（その場合は `CURRENT` を書き戻す）。

`conclusion.md` に含めるもの。

1. 合意事項（番号付き。実装者がそのまま作業できる粒度）
2. 測定結果と、その位置づけ（何を根拠として採用し、何を採用しなかったか）
3. 凍結・依存関係（触ってはいけないパスや、新設した結合）
4. 検証計画（合意した変更をどう評価するか、合否基準）
5. 意図的にスコープ外とした事項と、**先送りではなく分離である理由**

5を書かないと、次の作業者がスコープ外の項目を「直すべき不具合」と解釈して着手する。

## ユーザーへの報告

議論の各段階で、ユーザーには次を報告する。往復の全文を貼らない。

- どこまで進んだか（何往復目、合意済みか）
- **議論で立場が動いた点**（自分が撤回したもの、相手の指摘で変わったもの）
- 決まったこと、まだ決まっていないこと
