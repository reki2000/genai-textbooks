# やる夫式教材 書式整形スキル

対象は `yaruo-rediscovery` が生成した会話形式の教材（`docs/books/*/README.md`）。これは**公開前の機械lint**であり、書式の予防そのものは `yaruo-rediscovery` の「Markdown書式」指定が担う。

主眼は、執筆時の指定を守っても混入する CommonMark/GFM のレンダリング崩れ（処理2・処理3）にある。処理1・処理4 は保険。

**すべてスクリプトで機械的に行う。手作業でやらない。** モデルが本文を読み直して書き直すより、バイト単位で修正するこの機械lintのほうが安く確実である。

## 手順

順番は 1→2→3→4（会話表記を先に確定させる）。どのスクリプトも冪等で、`--check` を付けると変更せずに対象行を報告する（対象があれば終了コード1）。

各処理について次を回す。

1. `--check` を実行する。
2. 対象があれば `--check` を外して適用する。
3. 再度 `--check` を実行し、0件になることを確認する。
4. warning は目視で判断する（下記）。
5. 全処理の後、`git diff --stat` の変更行数がスクリプトの報告と一致することを確認する。

```bash
S=.claude/skills/yaruo-format/scripts
F=docs/books/<id>/README.md
python3 $S/format_dialogue.py       $F --check   # 処理1: 発言外枠のカギカッコ・行頭全角空白の除去
python3 $S/fix_emphasis.py          $F --check   # 処理2: 約物に隣接して壊れた ** の修正
python3 $S/fix_tables.py            $F --check   # 処理3: 表の区切り行の挿入
python3 $S/fix_dialogue_periods.py  $F --check   # 処理4: 発言末の句点補完
```

## warning への対応

スクリプトが自動修正せず報告するものは、該当行を目視して手で直す。

| warning | 対応 |
|---|---|
| 壊れた発言外枠（対応する `」` が見つからない） | 先頭の `「` だけ削除済み。閉じ位置を手で確認する |
| `**` が奇数個 | 多くは強調が行をまたぐケース。同一段落内なら有効なので、開き直後・閉じ直前が約物で壊れていないかだけ確認する |
| 長さ2以外の `*` の連続 | `*italic*`・`***`・区切り線。意図されたものならそのまま |
| `**` の直後（直前）が空白 | `** 重要**` 型の書き間違い。空白を内側から外側へ移す |
| 区切り行の列数がヘッダと不一致 | GFM では表にならない。区切り行の列数をヘッダに合わせる |
| 表の直前が空行でない | 段落の続きと解釈される。空行を1行入れる |
| 読点・コロン・セミコロンで終わる発言 | 句点を自動補完していない。文が途中で切れていないか確認する |

## 補足（なぜ壊れるか）

- **処理2**：CommonMark の flanking 規則により、`**` の外側が文字で内側が約物（`。「」（）『』：` など）に接していると強調として解釈されず、`**` がそのまま表示される。日本語はスペースを入れずに書くため頻発する。スクリプトは壊れている側の外側へ半角スペースを1つ挿入し、正常な箇所には触れない。
- **処理3**：GFM の表はヘッダ行の直後に区切り行が必須。`|` で始まる行が2行以上連続するブロックを表とみなし、2行目が区切り行でなければヘッダの列数に合わせて挿入する。
- コードブロック・インラインコード・TeX数式内はいずれの処理も対象外。

## 完了報告

ファイルごとに、各処理の修正行数、warning の一覧と各々への対応（手で直した／問題なしと判断した）、`git diff --stat` との整合を報告する。
