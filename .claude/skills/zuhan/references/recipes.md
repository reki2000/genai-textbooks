# 手段の選び方と実装

## ルーティング

| 対象 | 手段 | 理由 |
|---|---|---|
| 実物・装置・顕微鏡像・実測データ・歴史的な製品 | **外部引用一択** | 生成できない。生成すると嘘になる |
| 標準記法があるもの（回路・化学構造・状態遷移） | 専用ツール（SchemDraw / circuitikz / SMILES+RDKit / Graphviz） | 自然言語→標準記法はモデルが得意 |
| 空間的な模式図（断面・臓器・装置・格子） | **SVG直書き＋グリッド座標** | コード生成が最も破綻する領域。座標を自分で決めれば破綻しない |
| 量的関係 | 実データがあれば引用、モデル式なら matplotlib | 「式を見れば形が分かる曲線」は描かない |
| 概念の対比・系譜（ポンチ絵） | SVG直書き | 標準記号で並べると要素の位置が揃わず比較にならないことがある。機能ブロックに統一し、中身のグリフだけ変える |
| 生物・流体・自然現象・数学的対象など、幾何学的な作図では本質を損なうもの | **画像生成** | 箱と線に落とすと対象が別物になる。適切な引用元が無いときの受け皿でもある |

描画コードは、座標・数値・曲線・接続の再現性が教育価値を持つときだけ使う。ただの説明図をコードで無理に描かない。

**Codex から使うときは、この表の「SVG直書き」を画像生成へ読み替えて先に検討する。** 座標・数値・接続の正確さが教育価値そのものである図（格子、回路、アルゴリズムの状態遷移、寸法の比較）だけは、Codex でも SVG直書きへ落とす。生成画像は座標を保証しないので、その手の図を任せると数値が嘘になる。

## SVG直書き

`scripts/figs/svgkit.py` を使う。手順は必ずこの順。

1. **グリッドを宣言する。** キャンバス寸法と、各要素の座標をコメントで先に書き出す。
2. **その座標だけを使って描く。** コメントに座標を書いていない要素を描かない。
3. 検査 → PNG目視 → 直す。

宣言と実装を分けると、レイアウトの破綻が目に見えて減る。**Mermaid は使わない。** 自動レイアウトなので折れ曲がりと交差を制御できない。

svgkit が持つもの：`rect / line / path / circle / text / arrow / dim / electron / hole / fixed_ion / cross`。色定数と、太さに依存しない矢印の頭。接続線には `role="connector"` を付ける（検査器が接続線どうしの交差だけを咎められるようになる）。

```python
from svgkit import SVG, E_BLUE, H_RED, INK, SUB, N_TINT, P_TINT
s = SVG(900, 340, "順方向では障壁が下がり、電子がベースへ流れ込む")
s.rect(40, 60, 250, 90, fill=N_TINT)
s.electron(70, 90)
s.arrow(60, 100, 300, 100, stroke=E_BLUE, sw=6)
s.dim(150, 190, 170, "ベース幅")
s.save(OUT_DIR / "A2.svg")
```

生成物の置き場所、本文への埋め込み方、ビルド検査はこのリポジトリ固有の約束がある。`references/repo.md` を読むこと。

## 画像生成

Codex から使うときの第一候補。Claude Code から使うときも、対象が幾何学的な作図に馴染まないなら選んでよい。

- **配色は `conventions.md` と同じにする。** 手段が変わっても教材のトーンは変えない。プロンプトへ色を明示する（電子＝青 `#1f6fd0`、正孔・注意喚起＝赤 `#cf3b2d`、固定電荷＝灰 `#8d8d8d`、制御・入力＝橙 `#e07b1f`、地は白、淡い地色は `#e6eefb` / `#fbeae8` / `#f2f2f2`）。SVGの図と並べて同じ教材に見えなければ作り直す。
- 用途は科学教育。対象・視点・ラベル・正確性の制約・避ける表現をプロンプトへ固定する。**装飾目的の3D・遠近法・影・光沢・レンズ効果を明示的に禁止する**（`conventions.md` の規律は生成画像にも効く）。
- 長い説明文や数式を画像へ焼き込まない。ラベルは名詞か短い句だけにし、詳しい説明は本文とキャプションへ置く。
- 生成後は見た目の自然さではなく、**本文と形態・因果・スケール・ラベルが矛盾しないか**を検査する。科学的に重要な細部をモデルが創作した疑いがあれば採用しない。粒子の個数や比率が量を表しているように見えるなら、本文の量と合わせるか、合わせられないなら数を出さない構図にする。
- 採用した画像の最終プロンプトと生成手段を、その教材の生成スクリプトへコメントとして残す（`references/repo.md`）。再現できない画像を本文へ置かない。

### 外部サイトの画像を貼り込むとき

生成画像の中に外部サイトの画像を取り込む場合（背景・素材・参考図の合成を含む）は、次を必ず守る。

- **引用元のサイト名とURLを図の直下へ併記する。** 生成画像だからという理由で出典を省かない。合成した素材が複数あるなら全部書く。
- **引用元サイトの引用ルールに従う。** 利用規約・ライセンス・帰属表示の指定（表記文言、リンク先、改変の可否）をファイルページで確認し、その指定どおりに書く。**改変を禁じているサイトの画像は、生成画像へ貼り込むこと自体が改変にあたるので使わない。**
- ルールが確認できない、権利者が特定できない、期限付きURLしかない画像は使わない。別の資料か、完全なオリジナル生成へ切り替える。

```markdown
*出典：作者・提供者「資料名」[サイト名](https://example.org/original-page)。CC BY 4.0／本文の装置構造を示すため引用し、本図へ合成した。*
```

## グラフ（matplotlib）

```python
matplotlib.rcParams["font.family"] = "Noto Sans CJK JP"
matplotlib.rcParams["axes.unicode_minus"] = False
```

- 値そのものではなく、**曲線の形・傾き・閾値・飽和・領域の違い**が理解対象のときだけ描く。
- 多段の波形はサブプロットを縦に積み、x軸を共有する。周期は疎に（1画面に20〜30周期以内）。密すぎると塗り潰しに見える。
- 最終段には元の信号を破線で重ねるなど、そのパネルでしか分からないことを載せる。前段と同じ形のパネルを2枚並べない。
- 目盛りの数値に意味が無いなら軸の目盛りを消す。
- matplotlib のSVGは文字がパスになるので、check_figure.py の文字検査が効かない。PNGの目視で確かめる。

## 外部引用

- 探す先：Wikimedia Commons、公的機関（NASA / NIH / USGS）、PDB、研究機関・メーカーの公開資料、論文の補足資料。
- **再利用条件が不明な画像を使わない。** ライセンス行はファイルページで最終確認する。
- 帰属は「作者名／ライセンス名／ファイルページへのリンク」を図の下に付ける。
- 出典が使えないときは、外部資料を事実確認に使い、自分で模式図を描く。

### 実物と模式図の使い分け

実物の形・材料・寸法感・複雑さを知ること自体に教育価値があるなら写真。内部機構・見えない粒子・電場・反応経路を説明するなら模式図。両方要るなら「A. 実物／B. 同じ対象の模式図」の2パネルにする。**「本当にそう見える」図と「そう考えると理解できる」図を混同しない。**
