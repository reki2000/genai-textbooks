# 手段の選び方と実装

## ルーティング（Phase 1 で決める）

図は**すべて自分で描く**か、**実在する資料を引用する**かのどちらかにする。外部の画像生成サービス（ChatGPT など）へ依頼しない。依頼すると、細部の創作を検査しきれず、修正のたびに往復が要り、同じ教材の図が同じ規約でそろわない。

| 対象 | 手段 | 理由 |
|---|---|---|
| 実物・装置・顕微鏡像・実測データ・歴史的な製品・史料 | **外部引用（参考写真）** | 描いたものは資料の代わりにならない |
| 標準記法があるもの（回路・化学構造・状態遷移） | SVG直書きで標準の記号と向きを守る | 標準記法そのものに教育価値がある |
| 座標・個数・寸法・接続が答えになるもの（格子、ビット列、厳密な回路、寸法比較） | SVG直書き＋グリッド座標 | 位置と個数を保証できる |
| 生物学的形態・断面・装置・自然現象の模式図 | **SVG で自力描画（挿絵風模式図）** | 形態は曲線で描ける。参考写真で形を確かめてから描く |
| 量的関係 | 実データがあれば引用、モデル式なら SVG でグラフを描く | 「式を見れば形が分かる曲線」は描かない |
| 概念の対比・系譜 | SVG直書き | パネル間で座標を固定できる |

形態が主役の図（細胞、臓器、地形、装置の断面）は、実物の写真を引用して「実物＋模式図」の2枚組にするのが最も強い（`layout.md` の構図の型）。写真だけで足りるなら模式図は描かない。

## SVG直書き

道具は `scripts/figs/svgkit.py` の1つだけにする。グラフも模式図も同じ道具で描くと、文字・色・線が教材を通してそろい、検査器が全部の文字を検査できる。

1. **形と大きさを決める**（`layout.md`）。
2. **座標を宣言する。** 図の関数の docstring に、キャンバス寸法と要素の座標を先に書く。
3. **その座標だけを使って描く。**
4. 検査 → PNG目視 → 直す。

**Mermaid・matplotlib・Graphviz は使わない。** 自動レイアウトは折れ曲がりと交差を制御できず、matplotlib は文字をパスにするので検査が効かない。

svgkit の部品：

| 部品 | 用途 |
|---|---|
| `rect` `circle` `line` `arrow` `text` | 基本形。`text` はリストで複数行、`halo=True` で線の上でも読める |
| `poly(pts, smooth=, closed=, arrow=)` | 折れ線・グラフの曲線。`smooth=True` で点を通る滑らかな曲線（輪郭・膜・流路） |
| `note(x, y, rows)` | 結論の注記。答えの隣に1個 |
| `badge(cx, cy, n)` | 読み順の番号 |
| `zoom(src, dst)` | 全体＋拡大の枠と案内線 |
| `hatch(color)` | 斜線の塗り（色に頼らない区別） |

色は `MAIN / FOCUS / WARN / MUTED`、淡い地色は `TINT[MAIN]` のように引く。

## 自力描画（挿絵風模式図）

箱と直線だけでは形態が失われる対象を、SVG で描く。外注の画像生成の代わりになるのがこの節である。

1. **参考資料を集める。** 対象の実物写真・電子顕微鏡像・教科書の図を探し（探し先は下の「引用と帰属」）、形・比率・部位の位置関係を確かめる。見た資料の URL は `scripts/figs/<id>.md` の「作画資料」へ残す。引用もする写真は、同じ URL を本文の帰属にも使う。
2. **写さずに描く。** 他人の図の構図・輪郭をなぞらない。資料から取るのは事実（何がどこにあるか、どちらが大きいか、何本あるか）だけで、形は自分で単純化する。
3. **形を点列で宣言する。** 輪郭は `poly(closed=True, smooth=True)`、膜・管・流路は `poly(smooth=True)`、曲がった経路は `poly(smooth=True, arrow=True)`。点列は docstring の座標宣言に含める。
4. **繰り返し現れる部品は関数にする。** 受容体・小胞・分子などは `scripts/figs/<id>.py` に `def receptor(s, x, y, open=True)` のような部品関数を置き、全図で同じ形を使う。同じ物がいつも同じ形なら、2枚目以降は説明なしで読める。
5. **模式図であることを隠さない。** 立体感・陰影・質感を付けない。輪郭線＋淡い地色の平面で描き、実物の見た目は引用写真に任せる。
6. **本文との照合。** 描いた部位・数・向き・順序が本文と一致するか、`assert` で突き合わせられる値（個数、段数、比）は突き合わせる。

膜の二重線、細胞内の小器官、液面や地層の境界など、曲線の形そのものに意味がある箇所は「接続線は直線」の規約の対象外。規約が縛るのは、要素と要素を結ぶ接続線・引き出し線だけである。

## グラフ

- 値そのものではなく、**曲線の形・傾き・閾値・飽和・領域の違い**が理解対象のときだけ描く。
- 曲線は式から点列を計算して `poly` で引く。点は1本あたり60〜120個で足りる。
- 軸は必要な目盛だけ。目盛りの数値に意味が無いなら消す。凡例を作らず、曲線の端に直接名前を置く。
- 多段の波形は縦に積んで x 座標を共有する。前段と同じ形のパネルを2枚並べない。

## 引用と帰属

図の出典に関する規則はここが正本。本文に表示する参考写真と、作画資料として参照しただけの資料の両方に適用する。

- 探す先：Wikimedia Commons、公的機関（NASA / NIH / USGS）、PDB、研究機関・メーカーの公開資料、論文の補足資料。
- **再利用条件が不明な画像を使わない。** ライセンス行はファイルページで最終確認する。ルールが確認できない、権利者が特定できない、期限付きURLしかない画像は使わない。
- 帰属は「作者名／ライセンス名／ファイルページへのリンク」を図の下に付ける。
- **写真は加工せずに引用する。** トリミング・注記の書き込み・合成は改変にあたる。注記したいときは、写真の後に同じ構図の自作模式図を置いて、そちらに書く。
- 表示は原則としてファイルページの表示用 URL を直接参照し、`docs/books/<id>/figs/` へ複製しない（`repo.md`）。
- 出典が使えないとき（ライセンス不明・改変禁止で注記できない等）は、本文には表示せず作画資料として使い、自分で模式図を描く。

```markdown
*出典：作者・提供者「資料名」[サイト名](https://example.org/original-page)。CC BY 4.0。*
```

### 実物と模式図の使い分け

実物の形・材料・寸法感・複雑さを知ること自体に教育価値があるなら写真。内部機構・見えない粒子・電場・反応経路を説明するなら模式図。両方要るなら「A. 実物／B. 同じ対象の模式図」の2パネルにする。**「本当にそう見える」図と「そう考えると理解できる」図を混同しない。**

## 歴史図版

記号・量・実体の代わりに、史料・空間・同時代性を補う。

- 史料は外部引用に限る。制作年代と対象の年代、作者・発注者・所蔵者、何の証拠になるかを必要に応じてキャプションに記す。後世の肖像や歴史画を本人の容貌・同時代の目撃記録として見せず、自作の絵で代替しない。
- 地図は基準年と色の意味を示し、支配領域・朝貢圏・影響圏・現代国境を区別する。最大版図を全期間へ適用せず、不確かな境界へ現代の実線国境や民族色を投影しない。境界・地名が論点なら検証可能な既存地図を引用し、自作は座標と典拠を検証できる場合だけ。
- 比較年表は横軸を共通年代、縦軸を地域とし、期間データから位置・幅を計算する。文明の発展段階で揃えず、長期は時代の帯と少数の同期点に絞る。その節で論じる帯だけに色を付け、同期点の線には必ず名前を付ける（`layout.md`）。
- 史料の制作年代と利用条件は所蔵館やCommonsのファイルページで確認し、恒久的な資料ページへ帰属リンクを付ける。
