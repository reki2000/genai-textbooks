# 手段の選び方と実装

## ルーティング（Phase 1 で決める）

実行するエージェントやモデルの種類ではなく、図の教育価値と正確性で手段を選ぶ。座標・数値・接続の厳密さが教育価値なら決定的な作図を使い、生物学的形態や自然な空間構造を幾何図形へ落とすと本質を損なうなら画像生成を使う。

| 対象 | 手段 | 理由 |
|---|---|---|
| 実物・装置・顕微鏡像・実測データ・歴史的な製品 | **外部引用一択** | 生成すると資料の代わりにならない |
| 標準記法があるもの（回路・化学構造・状態遷移） | 専用ツール（SchemDraw / circuitikz / SMILES+RDKit / Graphviz） | 標準記法そのものに教育価値がある |
| 座標・個数・寸法・接続が答えになるもの（格子、ビット列、厳密な回路、寸法比較） | SVG直書き＋グリッド座標 | 生成画像では位置と個数を保証できない |
| 生物学的形態を含む断面・臓器・細胞・自然現象 | **画像生成を優先** | 箱と線へ落とすと対象の形態と空間関係を失う |
| 装置・空間の模式図 | 画像生成またはSVG直書き | 自然な形態が主なら画像生成、座標の再現性が主ならSVG |
| 量的関係 | 実データがあれば引用、モデル式なら matplotlib | 「式を見れば形が分かる曲線」は描かない |
| 概念の対比・系譜 | 画像生成またはSVG直書き | 自然な対象が主なら画像生成、パネル間の座標固定が主ならSVG |

描画コードは、座標・数値・曲線・接続の再現性が教育価値を持つときだけ使う。ただの説明図をコードで無理に描かない。

## SVG直書き

`scripts/figs/svgkit.py` を使う。手順は必ずこの順。

1. **グリッドを宣言する。** キャンバス寸法と、各要素の座標を関数の docstring へ先に書き出す。
2. **その座標だけを使って描く。** docstring に座標を書いていない要素を描かない。
3. 検査 → PNG目視 → 直す。

宣言と実装を分けると、レイアウトの破綻が目に見えて減る。**Mermaid は使わない。** 自動レイアウトなので折れ曲がりと交差を制御できない。

svgkit が持つもの：`rect / line / path / circle / text / arrow / dim / cross`。役割名の色定数（`MAIN / FOCUS / WARN / MUTED` と `TINT_*`）と、太さに依存しない矢印の頭。接続線には `role="connector"` を付ける（検査器が接続線どうしの交差だけを咎められるようになる）。

```python
from svgkit import SVG, MAIN, FOCUS, INK, SUB, TINT_MAIN
s = SVG(760, 340, "大区画・小区画・残りの実測を足して rank を求める")
s.rect(40, 60, 250, 90, fill=TINT_MAIN)          # 大区画
s.arrow(60, 100, 300, 100, stroke=MAIN, sw=6)    # 太さで量を表す
s.dim(150, 190, 170, "小区画の幅")
s.save(OUT_DIR / "fig2-1-rank.svg")
```

置き場所・骨格・ビルド検査は `references/repo.md`。

## 画像生成

- 複数の図をChatGPTへ依頼するときは `chatgpt-image-prompt.md` を使い、**1図1ファイル**とZIPの内部パスを固定する。2枚の総覧図やコンタクトシートへ統合させない。
- **配色は `conventions.md` の役割表と同じにする。** プロンプトへ値を明示する。SVGの図と並べて同じ教材に見えなければ作り直す。
- 用途は科学教育。対象・視点・ラベル・正確性の制約・避ける表現をプロンプトへ固定する。**装飾目的の3D・遠近法・影・光沢・レンズ効果を明示的に禁止する**（`conventions.md` の規律は生成画像にも効く）。
- 長い説明文や数式を画像へ焼き込まない。ラベルは名詞か短い句だけにし、詳しい説明は本文とキャプションへ置く。
- 生成後は見た目の自然さではなく、**本文と形態・因果・スケール・ラベルが矛盾しないか**を検査する。科学的に重要な細部をモデルが創作した疑いがあれば採用しない。粒子の個数や比率が量を表しているように見えるなら、本文の量と合わせるか、合わせられないなら数を出さない構図にする。
- 再現できない画像を本文へ置かない。最終プロンプトの残し方は `references/repo.md`。
- 検査で不正確な図が見つかったら、ChatGPT向けに「検出した誤り」「正しい状態」「図の完全仕様」「禁止事項」を含む、新規セッションだけで完結する再生成指示を出す。不合格ファイルだけを生成・ZIP納品させ、正しいファイルは作り直しも再納品もさせない。

## グラフ（matplotlib）

```python
matplotlib.rcParams["font.family"] = "Noto Sans CJK JP"
matplotlib.rcParams["axes.unicode_minus"] = False
```

- 値そのものではなく、**曲線の形・傾き・閾値・飽和・領域の違い**が理解対象のときだけ描く。
- 多段の波形はサブプロットを縦に積み、x軸を共有する。周期は疎に（1画面に20〜30周期以内）。密すぎると塗り潰しに見える。
- 最終段には元の信号を破線で重ねるなど、そのパネルでしか分からないことを載せる。前段と同じ形のパネルを2枚並べない。
- 目盛りの数値に意味が無いなら軸の目盛りを消す。

## 引用と帰属

図の出典に関する規則はここが正本。外部引用図も、外部素材を貼り込んだ生成画像も同じ扱いにする。

- 探す先：Wikimedia Commons、公的機関（NASA / NIH / USGS）、PDB、研究機関・メーカーの公開資料、論文の補足資料。
- **再利用条件が不明な画像を使わない。** ライセンス行はファイルページで最終確認する。ルールが確認できない、権利者が特定できない、期限付きURLしかない画像は使わない。
- 帰属は「作者名／ライセンス名／ファイルページへのリンク」を図の下に付ける。
- **生成画像へ外部素材を貼り込んだ場合も同じ。** 生成画像だからという理由で出典を省かない。合成した素材が複数あるならサイト名とURLを全部書き、そのサイトの指定どおりの表記・リンク先にする。**改変を禁じているサイトの画像は、生成画像へ貼り込むこと自体が改変にあたるので使わない。**
- 出典が使えないときは、外部資料を事実確認に使い、自分で模式図を描く。

```markdown
*出典：作者・提供者「資料名」[サイト名](https://example.org/original-page)。CC BY 4.0／本文の装置構造を示すため引用し、本図へ合成した。*
```

### 候補を探すときのレート制限

Wikimedia は連続アクセスに **HTTP 429 (Too many requests)** を返す。**429 は画像の不備ではないので、
それを理由に候補を落とさない。** 返ってきた本文はHTMLのエラーページなので、保存したファイルが
画像かどうかを必ず先頭バイトで確かめる（JPEG `FF D8 FF` / PNG `89 50 4E 47`）。拡張子とサイズだけ
見ていると、1KBのHTMLを画像として扱ってしまう。

- **メタデータは1回のAPI呼び出しでまとめて取る。** `titles=File:A|File:B|…` は複数指定できる。
  ファイルごとに叩かない。`prop=imageinfo&iiprop=url|extmetadata|size&iiurlwidth=960` で、
  ライセンス・作者・寸法・サムネイルURLが1往復で揃う。
- **ダウンロードは直列にして、1件ごとに数秒空ける。** 並列化しない。429 を受けたら待ち時間を
  伸ばしながら数回だけ再試行する。
- **User-Agent に用途と連絡先を入れる。** 既定のUAは弾かれやすい。
- **原寸を取りに行かない。** 6000px級の原本ではなく `iiurlwidth` のサムネイルを使う。目視判定には
  960px あれば足りる。転送量が減るぶん制限にも当たりにくい。
- **同じファイルを二度落とさない。** 取得済みなら再取得を飛ばす。検査のやり直しで何度も走らせる
  ことになるので、これが一番効く。
- 到達確認をまとめて回すと制限に当たる。**本文へ入れる直前の疎通確認は、自分で組み立てたURL
  （エンコードした括弧やカンマを含むものなど）だけに絞る。** APIが返した `descriptionurl` は
  そのまま使うかぎり正しい。

### 実物と模式図の使い分け

実物の形・材料・寸法感・複雑さを知ること自体に教育価値があるなら写真。内部機構・見えない粒子・電場・反応経路を説明するなら模式図。両方要るなら「A. 実物／B. 同じ対象の模式図」の2パネルにする。**「本当にそう見える」図と「そう考えると理解できる」図を混同しない。**
