# 形・大きさ・構図

Phase 2 で1枚ごとに、描き始める前に読む。`conventions.md` が「どの図でも同じにするもの」なら、ここは「図ごとに変えるもの」である。

旧来の図は、ほぼ全部が幅760・高さ270〜520の横長で、文字11〜13px、全要素が同じ太さと濃さだった。この形はスマホ幅（約340px）へ縮むと文字が5px台になり、どの図も同じ顔に見え、どこを見ればよいかを図が教えない。**既定の形を持たないこと**がこの節の目的である。

## 1. 形は内容の軸から決める

描く前に「この図の主軸は何か」を1語で言い、そこから形を選ぶ。

| 主軸 | 形 | viewBox の目安 | 例 |
|---|---|---|---|
| 時間・列・流れ（1次元が長い） | 横長の帯 | 760×220〜320 | 年表、ビット列、処理の流れ |
| 深さ・階層・層・手順の段 | **縦長** | 440〜520×560〜760 | 断面の層、木構造、細胞から分子への拡大 |
| 平面・2変数・地図 | 正方に近い | 520〜600×480〜600 | 散布図、尤度の山、地図、配置図 |
| 1つの物の形 | **小さな挿図** | 320〜420×240〜360 | 1個の受容体、1本の曲線の形、1つの区間 |
| 対照（前後・成功と失敗） | 横に2枚（または縦に2枚） | パネル1枚分×2 | 閉じ忘れた行と閉じた行 |
| 状態の連続（3〜6段） | 小さな多数を格子に | 1コマ160〜240角 | 更新の各段、細胞周期 |

- 同じ教材の中で形が全部そろったら、選定を疑う。4枚以上あれば、少なくとも2種類の形が出るのが普通である。
- 縦長の図はスクロールの流れと合う。階層・拡大・因果を上→下で描くなら、横へ押し込まずに縦に使う。
- 小さな挿図は、本文の1文を補うだけの図に使う。大きく描くと、重要な図と同じ重みに見えてしまう。

## 2. 大きさは重要度で決める

図の表示幅は、図の重さ（本文の中での重要度）を読者に伝える。埋め込み時に docsify の表示指定で幅を決める（書き方は `repo.md`）。

| 区分 | 表示幅 | 使いどころ |
|---|---|---|
| S | 320〜420px | 1文を補う挿図。物の形、1本の曲線 |
| M | 480〜600px | 1節の核になる図。多くの図はここ |
| L | 本文幅いっぱい | 章の要になる図、全体地図、比較年表 |

- **L を既定にしない。** L は章に1〜2枚まで。
- **viewBox の幅は表示幅に近づける。** 表示幅 420 の図を幅760で設計すると、文字が0.55倍に縮む。設計単位と表示単位をそろえれば、指定した文字サイズがほぼそのまま画面に出る。
- 文字サイズは、スマホ本文幅（340px）へ縮めた実効値で考える。`check_figure.py` は実効6px未満を NG にする。幅760なら主ラベル16px以上・補助14px以上、幅420なら主ラベル14px・補助12pxで足りる。**小さくして詰め込むより、キャンバスを狭くして要素を減らす。**

## 3. 構図の型

図の問いに合う型を1つ選ぶ。型を混ぜない。

### 注釈付き単一図

1つの対象に、結論の注記（`svgkit.note`）を1個だけ、答えが見える場所のすぐ横に置く。多くの図の基本形。注記は「山の頂上と帰無仮説の距離を測るのが Wald」のような、図を見て確かめられる一文にする。

### 全体＋拡大

全体の中のどこの話か、を先に示してから細部を見せる。`svgkit.zoom` で元の位置に破線枠、拡大側に実線枠と案内線を引く。拡大率が大きい（細胞→シナプス→受容体）ときは縦長にして上から下へ降りる。

### 読み順つきの図

要素間の順序が要点で、しかも空間配置も要点のとき（経路が細胞内を移動する、要求が層を通る）。箱と矢印の流れ図にせず、実際の空間配置の上に番号（`svgkit.badge`）を打つ。番号は5個まで。それ以上なら図を分ける。

### 小さな多数（small multiples）

状態が変わっていく様子。全コマで座標・縮尺・配色を固定し、変わる要素だけを FOCUS で示す。コマの見出しは「1月」「更新後」など短い名詞にする。

### 対照の2枚

成功と失敗、前と後。同じ座標系で描き、違う箇所にだけ WARN（失敗側）か FOCUS（変化点）を使う。違わない部分は MUTED で弱く描き、目が差分へ行くようにする。

### 実物＋模式図

実物の写真（外部引用）を先に置き、その直後に同じ対象の自作模式図を置く。模式図は写真と同じ向き・同じ部位名にする。写真と模式図の対応を1文で本文かキャプションに書く。

### 帯の年表・比較年表

横軸は共通の年代、縦軸は地域。帯を全部同じ色にしない。**その節で論じる帯だけを MAIN／FOCUS で塗り、残りは MUTED の輪郭だけにする。** 同期点の縦線には必ず名前（「755 安史の乱」）を付ける。名前の無い縦線は読めない。

## 4. 説明力の確認（描いた後に毎回）

PNG を見て、次の順に確かめる。1つでも落ちたら直す。

1. **3秒テスト。** 画像を3秒見て目を離し、最初に目に入ったものを言う。それが図の問いの答えでなければ、強調の配分が間違っている。
2. **焦点は1か所。** FOCUS 色と最も太い線と最も大きい文字が、同じ場所に集まっているか。焦点が2か所以上あるなら、どちらかを MUTED へ落とすか図を分ける。
3. **濃淡の階層。** 主役（太さ3〜5、濃い色）／関係する要素（太さ1.5〜2）／背景・目盛（太さ1、MUTED）の3段がある。全要素が同じ太さ・同じ濃さなら、それは表であって図ではない。
4. **注記が答えを言っている。** 結論の注記が図の中にあり、答えが見える場所の隣にある。キャプションにしか結論が無い図は、図だけでは読めない。図の上端に大見出しは付けない（キャプションと重複する）。
5. **360px幅でも読める。** 縮小PNGで、主ラベルと注記が読め、焦点が判別できる。
6. **余白が偏っていない。** 外周の余白は20〜32で、空いた帯（何も無い上下の余白、使われない右半分）が無い。空いた帯があるなら、キャンバスを縮めるか形を変える。

## 5. 旧図に多かった失敗

- 全帯が同じ淡色で、どの帯を読めばよいか分からない年表。→ 論じる帯だけ色を付ける。
- 名前の無い破線の縦線。→ 同期点・照会点には必ずラベル。
- 上部の大見出し＋下部の数値の羅列で、図の中に答えが無い。→ 答えは注記として該当箇所へ。
- 目盛と主役が同じ太さ・同じ色。→ 3段の濃淡階層。
- 幅760の枠に小さな要素が中央に寄り、上下に大きな余白。→ 形を変えるか S／M にする。
