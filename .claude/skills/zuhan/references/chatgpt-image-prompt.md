## 書きすぎない

**この雛形でいちばん大事な規則。図の細部を指定しない。**

渡すのは次の4つだけにする。

1. 図を置く箇所の**本文の原文**（要約しない）
2. その図で**説明したいこと**（1〜2文）
3. **大まかな構図**（何と何を並べるか、断面か配列か、パネルは何枚か）
4. **図中に入れたいラベルの文言**

配置、寸法、個数、線の引き回し、矢印の始点と終点、塗り分けの位置は**指定しない**。
どう描けば伝わるかはChatGPTに任せる。

### 細かく指定すると、なぜ壊れるか

座標や個数や接続を文章で細かく積み上げるほど、出てくる図は悪くなる。

- 指示が増えるほど取りこぼしが増える。20個の必須要素を並べれば、そのうち数個は無視される。
  どれが無視されるかは選べない。**この図の主張そのものを担う要素が落ちることがある。**
- 「AをBへ接続する」と書いても、絵として接続が成立するとは限らない。装飾的な線が
  素子の手前を素通りするような、指示は満たしているが意味をなさない絵が返る。
- 個数や座標の一致を文章で要求しても保証されない。**保証が要るなら、それは画像生成で
  作る図ではない。** `recipes.md` の選定表に戻って、SVG直書きへ回す。
- 禁止事項を並べるほど、モデルはその語に引きずられる。「装飾的な✕印を描かない」と
  書けば、かえって✕が出てくることがある。

**細部を詰めたくなったら、それは手段の選択が間違っている合図。** 座標・個数・接続が
教育価値そのものである図（格子、ビット列、厳密な回路、寸法比較、分布の重なり）は
画像生成では作れない。プロンプトを厚くして解決しようとしない。

### 何を渡さないか

- 「幅は◯px」「高さの3分の1の位置」のような寸法・座標
- 「ちょうど8個」「4行4列」のような、絵として数える必要がある個数
- 「AからBへ矢印を1本、CからDへ矢印を3本」のような接続の全列挙
- 長い禁止事項リスト
- 「上端は太く下端は細く、その差は約半分」のような比率の指定

これらが図の主張に必要なら、画像生成をやめる。

## 初回生成プロンプト

`{...}` を実案件の値へ置き換える。図の数とファイル名を先に確定する。

完成したプロンプトは `scripts/figs/{教材ID}-prompt.txt` へ**そのまま全文を書き出す**。`scripts/figs/{教材ID}.md` へ埋め込まない。ユーザーがChatGPTへコピペする際、`.md` の見出しや周囲の解説文が誤ってコピー範囲に入らないようにするため。ユーザーには `.txt` のパスを伝え、内容を開いて全文をコピーするよう依頼する。

````text
日本語教材「{教材タイトル}」に掲載する科学教育図版を作成してください。

最重要の納品条件：
- 作る図は次の{N}枚です。必ず各項目を別々のPNGファイルとして生成してください。
{番号付きのファイル名一覧}
- 複数の図を1枚へ統合しないでください。
- 総覧図、コラージュ、コンタクトシート、複数図を並べたページを作らないでください。
- 1ファイルには、対応する1つの図の内容だけを描いてください。
- 生成後、上記{N}個のPNGがすべて個別ファイルとして存在することを確認してください。

共通仕様：
- 用途：scientific-educational
- 出力：各画像 {WIDTH}×{HEIGHT} px のPNG
- 背景：白
- 画風：精密で清潔な2D模式図。空間配置が理解対象なら、箱と矢印だけのフローチャートにしない。
- 青 #1f6fd0：{この教材での意味}
- 橙 #e07b1f：{この教材での意味}
- 赤 #cf3b2d：{この教材での意味}
- 灰 #8d8d8d：構造と補助情報
- 淡い地色：青 #e6eefb、橙 #f6e6b8、赤 #fbeae8、灰 #f2f2f2
- 主方向は左から右。階層または拡大は上から下。
- 色だけで区別せず、実線・破線、形、塗り／白抜きなどでも区別する。
- 指定したラベルの文言は一字も変えずに使ってください。指定していない説明文は足さないでください。
- 上付き・下付き文字を使わず、「n2」「m/s2」「SiO2」のように普通の文字で書いてください。
- 本文に出てこない対象、数値、製品名を足さないでください。
- 装飾的な3D、遠近法、影、光沢、発光、グラデーション、レンズ効果、写真風表現は使わないでください。
- 人物、ロゴ、ウォーターマーク、図番号、キャプションは入れないでください。
- 360px幅へ縮小しても主対象と結論が判別できる太さと文字サイズにしてください。

図ごとの内容：
{下の雛形で、ファイルごとに区切って列挙する}

納品前チェック：
1. ファイル名一覧と実際のPNGを照合し、{N}個すべてがあることを確認する。
2. 各PNGが別々の図であり、複数の要求を統合していないことを確認する。
3. 指定したラベルの文言が入っていることを確認する。

ZIP納品：
- 最後に、全{N}個のPNGを1個のZIP「{教材ID}-figures.zip」へまとめてください。
- ZIP内部のパスは、例外なく「{教材ID}/{ファイル名}.png」にしてください。
- ZIP内部には次の{N}ファイルだけを入れてください。
{`{教材ID}/{ファイル名}.png` の完全な一覧}
- PNGをZIPのルート直下へ置かないでください。
- `{教材ID}` の下に追加のサブディレクトリを作らないでください。
- README、PDF、JSON、サムネイル、総覧画像、元画像、途中生成物、隠しファイルを入れないでください。
- 個別画像だけを返して終了せず、必ずダウンロード可能なZIPファイルを最終成果物として提示してください。
````

ChatGPTが一度に全図を生成できない場合も、同じ会話で1枚ずつ生成を続け、最後に全PNGを集めて完全なZIPを作らせる。「2枚にまとめてよい」などの代替を許可しない。

## 図ごとの仕様

1ファイルにつきこのブロックを1個作る。**4項目より増やさない。**

````text
### {連番}. `{ファイル名}.png`

該当本文：
"""
{図を置く箇所の本文原文。要約しない}
"""

この図で説明したいこと：
{1〜2文。読者に何が分かればよいか}

大まかな構図：
{2〜4行。何と何を並べるか、断面か配列かグラフか、パネルは何枚か。それ以上は書かない}

図中に入れるラベル：
- 「{ラベル}」
````

`該当本文` を必ず入れる。ChatGPTが描くべき対象を知る唯一の情報源であり、
仕様が本文にない語彙を持ち込んでいないか照合する手がかりでもある。

`大まかな構図` の粒度は「左右2パネルで、左が失敗する構成、右が成立する構成」くらい。
「左パネルの中央p層は左右のn層より明らかに薄く、電子の経路は青の矢印で……」まで書いたら
書きすぎ。

## ZIP受領後の判定

ユーザーへ次のように依頼する。

```text
ChatGPTからダウンロードしたZIPを、展開せずにリポジトリルートの `tmp/` 配下へ置いてください。初回なら例：`tmp/{教材ID}-figures.zip`、修正版なら例：`tmp/{教材ID}-figures-fix-{連番}.zip`。置いたらファイル名を知らせてください。
```

受領後は次の順で判定する。

1. ZIP原本を変更せず、`check_image_zip.py` で内部パス、全件性、余分なファイル、PNG形式、寸法を確認する。
2. 安全な一時ディレクトリへ展開し、全ファイルを原寸で見る。
3. 約360px幅でも主対象と結論が分かるかを見る。
4. 該当本文と照らして、**説明したいことが伝わる絵になっているか**を見る。細部の一致ではなく、
   本文と矛盾していないか、主張が読めるかで判断する。
5. 合格画像だけを `docs/books/{教材ID}/figs/` へコピーする。不合格画像を取り込まない。
6. 判定と修正指示を `scripts/figs/{教材ID}.md` に記録する。

ZIPが壊れている、内部パスが違う、ファイルが統合されている、欠落がある場合も「画像品質」とは分けて不合格理由を書く。

**2回直しても同じ箇所が直らない図は、依頼を重ねない。** 3回目を投げる前に、その図が
画像生成に向いているかを `recipes.md` の選定表で問い直す。座標・個数・接続が主張なら
SVG直書きへ移す。プロンプトの書き足しでは解決しない。

## 修正プロンプト

不合格時は、新規ChatGPTセッションへそのまま投入できる自己完結したプロンプトを作る。過去の会話、元画像、初回プロンプトを参照させない。「前回と同じ」「他は維持」のような、新規セッションでは解決できない指示を書かない。

**修正版でも細部を指定しない。** 直したい点を1〜2個だけ言葉で述べ、あとは初回と同じ4項目を渡す。
「検出した誤り」を長い箇条書きにして、その裏返しを全部要求すると、初回より悪い図が返る。

このプロンプトも `scripts/figs/{教材ID}-prompt-fix-{連番}.txt` へ全文を書き出す。初回プロンプトと同じ理由で `.md` へは埋め込まない。

````text
日本語教材「{教材タイトル}」に掲載する科学教育図版のうち、次の{M}枚だけを生成してください。この依頼は新規セッション用です。過去の会話や画像は前提にしないでください。

生成・納品するファイル：
{不合格ファイルだけの番号付き一覧}

重要：
- 上記{M}枚以外は生成しないでください。
- 他の合格済み画像は、このセッションには存在しません。要求も納品もしません。
- 複数の図を統合しないでください。1図1PNGにしてください。
- 総覧図、コラージュ、コンタクトシートを作らないでください。

共通仕様：
{初回プロンプトの共通仕様を省略せず再掲する}

図ごとの内容：

### `{不合格ファイル名}.png`
- 該当本文：
  """
  {図を置く箇所の本文原文。要約しない}
  """
- この図で説明したいこと：{1〜2文}
- 大まかな構図：{2〜4行}
- 図中に入れるラベル：{文言の一覧}
- 特に気をつけてほしい点：{1〜2個だけ。前回うまくいかなかったことを短く述べる}

納品前チェック：
1. 指定した{M}枚だけが、別々のPNGとして存在することを確認する。
2. 指定したラベルの文言が入っていることを確認する。

ZIP納品：
- ZIP名：`{教材ID}-figures-fix-{連番}.zip`
- ZIP内部は「{教材ID}/{ファイル名}.png」の形を維持してください。
- ZIPには今回生成した不合格修正版{M}枚だけを入れてください。
- 合格済み画像や、今回指定していない画像を入れないでください。
- ZIP内部には指定したPNG以外を入れないでください。
- 最後にダウンロード可能なZIPファイルを提示してください。

期待するZIP内部の一覧：
{不合格ファイルだけの `{教材ID}/{ファイル名}.png` 一覧}
````

パッケージだけが不正で画像内容は検査できている場合は、同じChatGPTセッションに限り、画像を再生成させず次を使う。新規セッションには画像がないため、この短縮指示は使わない。

```text
画像内容は変更も再生成もしないでください。このセッションで生成済みの修正対象PNGだけをそのまま使い、指定一覧どおりの内部パスで `{教材ID}-figures-fix-{連番}.zip` を再作成してください。合格済み画像、総覧画像、追加資料、隠しファイルは入れないでください。
```

## 作業記録

ChatGPTへ渡すプロンプトの全文は `scripts/figs/{教材ID}.md` へ埋め込まず、`scripts/figs/{教材ID}-prompt.txt`（初回）と `scripts/figs/{教材ID}-prompt-fix-{連番}.txt`（修正、あれば連番ごとに複数）へ独立したファイルとして書き出す。ユーザーがChatGPTへコピペしやすくするための分離であり、`.md` にはこれらの `.txt` へのパスだけを記録する。`.md` 自体は次の最小構成にする。

```markdown
# {教材タイトル} 図版生成記録

- 生成手段：ChatGPT {分かる範囲のモデル／機能名}
- 生成日：YYYY-MM-DD
- 初回プロンプト：`scripts/figs/{教材ID}-prompt.txt`
- 納品ZIP：`tmp/{教材ID}-figures.zip`
- 修正プロンプト：`scripts/figs/{教材ID}-prompt-fix-{連番}.txt`（なければ「なし」）
- 修正ZIP：`tmp/{教材ID}-figures-fix-{連番}.zip`（なければ「なし」）
- 期待寸法：{WIDTH}×{HEIGHT}
```
