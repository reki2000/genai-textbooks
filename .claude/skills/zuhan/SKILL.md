# 図版設計

## 前提

図の目的は本文を短くすることではない。**本文だけでは頭の中に正しく組み立てにくいモデルを渡すこと**である。

したがって判定基準はひとつ。

- 本文からその図が一意に復元できる → 不要
- 図から本文を書き下すと数段落かかる → 有用

生成AIが作る図が安っぽくなる最大の原因は、5秒で読める文章を四角と矢印で再掲することである。これを最初に潰す。

図が勝つ情報：空間配置、接続の位相、2次元以上の同時比較、連続量の「形」、スケール差、実物の見た目。
図が負ける情報：定義、線形な因果連鎖、列挙、手順、3個の数値。これは文章か箇条書きで足りる。

## 進め方：2フェーズ＋検査ループ

```
Phase 1  選定 （章/幕ごとに1回。何を描き、何を描かないか）
   ↓ 図版スロットを本文へ埋め込む。ここで人間のレビューを受ける
Phase 2  制作 （1枚ごと。作る → check_figure.py → PNGを目視 → 直す）
```

**レビューを受けられないときは止まらない。** 「図を追加して」の一言で始まった作業のように、応答を待てる相手がいないことがある。そのときは Phase 1 の出力（採用した図の一覧と、却下した候補とその理由）を成果物として残したうえで Phase 2 へ進む。残す先はコミットメッセージか PR 本文。**選定の判断を人が後から覆せる形にすることがレビューの目的**なので、対話の往復そのものは必須ではない。判断が割れそうな点（枚数、ある章を0枚にしたこと）は成果物の中で明示する。

**「仕様書」フェーズを別に置かない。** 仕様の中身は2つに分解できる。毎回同じ定数（色・向き・要素数の上限・線の規則）は `references/conventions.md` に固定してあり、生成し直す意味がない。図ごとに決めるべき可変部（答える問い／含める・含めない／手段／挿入位置）は Phase 1 の出力欄に収まる。

中間フェーズを挟むと本文が落ちる。これが実害になる。本文の語彙に無い形式（例：バンド図）を足してしまう、本文が「一部／大部分」と言っているから矢印の太さで電流比を表す、といった判断は、本文を読んでいないと出てこない。**Phase 2 には必ず該当箇所の本文をそのまま渡す。** 要約を渡さない。

## Phase 1：選定

入力は章の本文全体。要約せずに読む。

### 手順

1. **層の欠落を探す。** 節ごとに、記号層（式・記号・回路記号）／量的層（グラフ・波形）／実体層（写真・顕微鏡像）のどれが本文に無いかを見る。文章は記号層と言葉に偏るので、欠けている層を1つ補うと図に必然性が出る。全層を埋める必要はない。
2. **必要性テスト。** 候補ごとに「この図が無いと理解できない本文の一文」を原文から引用する。引用できない候補は落とす。
3. **却下候補も理由つきで残す。** 何を描かなかったかを人間が確認できるようにする。
4. **総数を先に縛る。** 目安は本文1万字あたり3枚。ただし章によって適正量は大きく違う。空間的・機構的な章は倍要ることがあり、政策や歴史の章は0枚が正解のこともある。均等配分しない。

### 挿入位置：図を「正解の先出し」にしない

再発見型・対話型の教材では、図の位置が内容と同じくらい効く。

- 誤ったモデル → 反例 → 再発見、という流れなら、図は**再発見の後**に置く。先に置くと答えを見せてしまい、学習体験を壊す。
- 失敗案と成功案を並べる図は、読者（または登場人物）が失敗した直後に置く。
- 図を足したら、**本文にその図を指す一文を足す**。「この図の左半分だけ見て」のような参照が無いと、後付けの図は本文から浮く。本文の差分もセットで提示する。

### 出力：図版スロットを本文へ埋め込む

画像はまだ作らない。本文の該当位置に、次のコメントを挿入した差分を出す。

```
<!-- FIGURE A1
anchor:    「でも、それがどう一方通行になるんだお？」の直後
question:  障壁が下がる・広がるとは、何の幅と高さが変わることか（問いは1つだけ）
layer:     記号 | 量 | 実体
must:      空乏層の幅、固定イオン、障壁の高さ、3状態
must-not:  エネルギーバンド図（本文にバンドの語彙が無い）、I-V曲線
means:     引用 | プロット | SVG | 生成
why:       「外から順方向電圧をかけると障壁が下がって…」（本文からの引用）
-->
```

最後に「図にしなかった重要箇所」と却下理由を列挙する。

## Phase 2：制作

1枚ずつ作る。始める前に `references/conventions.md` を読む（作図規約。毎回読むこと）。手段の選び方と実装手順は `references/recipes.md`、このリポジトリでの置き場所・埋め込み方・ビルド検査は `references/repo.md`。

SVGを直書きするなら `scripts/figs/svgkit.py` を使う。グリッド座標を先に決めてから描く設計になっており、自動レイアウトを使わないので線が勝手に折れ曲がらない。

**Codex から使うときは、SVG直書きより画像生成を優先する。** 座標・数値・接続の正確さがそのまま教育価値になる図（格子、回路、状態遷移、寸法の比較）だけは Codex でも SVG へ落とす。どの手段で描いても**配色は `references/conventions.md` と同じ**にする。生成画像なら色をプロンプトへ明示する。外部サイトの画像を生成画像へ貼り込むなら、**引用元のサイト名とURLを必ず併記し、そのサイトの引用ルールに従う**（`references/recipes.md`）。

### 検査は必ず走らせる

```bash
python3 .claude/skills/zuhan/scripts/check_figure.py "docs/books/<id>/figs/*.svg" --png-dir /tmp/figpng
```

見るのは、内省では絶対に捕まらない事故だけ：フォントに無い文字（豆腐）、接続線どうしの交差、はみ出し、ラベルの詰め込みすぎ。

**そのうえで PNG を必ず開いて目視する。** ソースを読み返す自己レビューは、ラベルの重なり・矢印の頭の肥大・図形の食い違いを1つも捕まえない。ここを省くと必ず事故が残る。matplotlib が吐く SVG は文字がパスになるので文字検査が効かない。目視が唯一の砦になる。

直したら、また検査して見る。2〜3周は普通にかかる。

## 却下すべき図の型

- 本文が否定している枠組みを図が肯定してしまうもの（例：本文が「半導体＝導電率が中間」を否定しているのに、絶縁体—半導体—導体の導電率スケール帯を描く）。**最も危険**。
- 本文から形が一意に復元できる曲線（「順方向は流れる、逆方向は流れない」だけのI-V曲線）。
- 本文に語彙が無い形式を持ち込む図（本文にバンドの話が無いのにバンド図）。
- 本文の比喩で足りているものの図解。
- 「入力→処理→出力」「原因→結果」型の箱と矢印。
- 数値を3個並べただけの棒グラフ。
- 装飾目的の科学イラスト。
- 対比のためだけの3枚目。2枚を**同じ作図規約**（同じ向き・同じ座標系）で描けば、並べるだけで対比になる。

## 完了条件

- すべての図が check_figure.py を通り、PNG を目視で確認してある（デスクトップ幅と約360px幅）
- `scripts/figs/<id>.py --check`・lint・サイトビルドが通っている（`references/repo.md`）
- 各図に自己完結したキャプションがある（本文の繰り返しではなく、「何を見るか」を書く）
- 引用図には出典URL・作者・ライセンス名が付いている。外部サイトの画像を貼り込んだ生成画像も同じで、サイト名とURLを併記し、そのサイトの引用ルールに従っている
- 生成画像は最終プロンプトと生成手段が残っており、配色が他の図と揃っている
- 本文側に、各図を指す参照文が入っている
- 却下した候補とその理由が残っている
