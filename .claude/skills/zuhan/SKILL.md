# 図版設計

## 判定基準

図の目的は本文を短くすることではない。**本文だけでは頭の中に正しく組み立てにくいモデルを渡すこと**である。

- 本文からその図が一意に復元できる → 不要
- 図から本文を書き下すと数段落かかる → 有用

図が勝つ情報：空間配置、接続の位相、2次元以上の同時比較、連続量の「形」、スケール差、実物の見た目。
図が負ける情報：定義、線形な因果連鎖、列挙、手順、3個の数値。これは文章か箇条書きで足りる。

図は**自分で描くか、実在する資料を引用するか**のどちらかにする。外部の画像生成サービスへは依頼しない。形態が主役の図も SVG で自力描画し、実物の見た目は Web から探した参考写真の引用で補う（[recipes.md](references/recipes.md)）。

図はそろえるものと、そろえないものがある。配色・線・記法は教材を通して固定する（[conventions.md](references/conventions.md)）。**キャンバスの形・大きさ・構図は図ごとに内容から選ぶ**（[layout.md](references/layout.md)）。全部が同じ横長・同じ幅の図は、どれも同じ重みに見え、どこを見ればよいかを教えない。

歴史教材では [recipes.md](references/recipes.md) の「歴史図版」を読む。

## 進め方：2フェーズ＋検査ループ

```
Phase 1  選定 （章/幕ごとに1回。何を描き、何を描かないか）
   ↓ 図版スロットを本文へ埋め込む。ここで人間のレビューを受ける
Phase 2  制作 （1枚ごと。形を選ぶ → 描く／引用する → 機械検査 → PNGを目視 → 直す）
```

**レビューを受けられないときは止まらない。** 応答を待てる相手がいなければ、Phase 1 の出力（採用した図と、却下した候補とその理由）をコミットメッセージか PR 本文へ残して Phase 2 へ進む。**選定を人が後から覆せる形にすることがレビューの目的**なので、対話の往復そのものは必須ではない。判断が割れそうな点（枚数、ある章を0枚にしたこと）は成果物の中で明示する。

**Phase 2 には必ず該当箇所の本文をそのまま渡す。要約を渡さない。** 本文に無い語彙の図を足してしまう、本文が「一部／大部分」と言っているから太さで比を表す、といった判断は、本文を読んでいないと出てこない。

## Phase 1：選定

入力は章の本文全体。要約せずに読む。手段の選定表は `references/recipes.md`。

1. **層の欠落を探す。** 節ごとに、記号層（式・記号・回路記号）／量的層（グラフ・波形）／実体層（写真・顕微鏡像）のどれが本文に無いかを見る。文章は記号層と言葉に偏るので、欠けている層を1つ補うと図に必然性が出る。全層を埋める必要はない。
2. **必要性テスト。** 候補ごとに「この図が無いと理解できない本文の一文」を原文から引用する。引用できない候補は落とす。
3. **却下候補も理由つきで残す。** 何を描かなかったかを人間が確認できるようにする。
4. **総数を先に縛る。** 目安は本文1万字あたり3枚。ただし章によって適正量は大きく違う。空間的・機構的な章は倍要ることがあり、政策や歴史の章は0枚が正解のこともある。均等配分しない。

### 挿入位置：図を「正解の先出し」にしない

再発見型・対話型の教材では、図の位置が内容と同じくらい効く。

- 誤ったモデル → 反例 → 再発見、という流れなら、図は**再発見の後**に置く。先に置くと答えを見せてしまい、学習体験を壊す。
- 失敗案と成功案を並べる図は、読者（または登場人物）が失敗した直後に置く。
- 図を足したら、**本文にその図を指す一文を足す**。「この図の左半分だけ見て」のような参照が無いと、後付けの図は本文から浮く。本文の差分もセットで提示する。

### 出力：図版スロットを本文へ埋め込む

画像はまだ作らない。本文の該当位置に、次のコメントを挿入した差分を出す。

```
<!-- FIGURE 2-1
anchor:    「数え表を全部持てばいいんじゃないかお？」の直後
question:  rank はどこまでが表引きで、どこからが実測か（問いは1つだけ）
layer:     記号 | 量 | 実体
must:      大区画の累積、小区画の累積、残りのビット列、問い合わせ位置
must-not:  select の手順（別の図にする）、実装上のメモリ配置
means:     引用 | グラフ | SVG | 描画（自力の挿絵風模式図）
shape:     横長 | 縦長 | 正方 | 小挿図 ／ 表示幅 S | M | L
kind:      注釈付き単一図 | 全体＋拡大 | 読み順つき | 小さな多数 | 対照の2枚 | 実物＋模式図 | 帯の年表
answer:    図の中に注記として置く結論の一文（「表を2回引き、残りだけ数える」）
why:       「大区画、小区画、残りの実測を足す」（本文からの引用）
-->
```

最後に「図にしなかった重要箇所」と却下理由を列挙する。スロットを並べたら `shape` の列を見る。全部が同じ形・同じ表示幅なら、形を内容から選び直す（L は章に1〜2枚まで）。

## Phase 2：制作

1枚ずつ仕様を確定する。始める前に `references/conventions.md`（作図規約）・`references/layout.md`（形・大きさ・構図）・`references/repo.md`（置き場所・骨格・検査）を読む。手段ごとの実装は `references/recipes.md` の該当節だけでよい。

1. **形と大きさを決める。** スロットの `shape` と `kind` を `layout.md` で確かめ、viewBox を表示幅に近い寸法で決める。
2. **参考資料を集める。** 実物のある対象は Web（Wikimedia Commons、公的機関、研究機関の公開資料）で写真・顕微鏡像・実測図を探す。再利用条件が確認できる写真は本文へ引用し、そうでない資料は作画資料として形や配置を確かめるだけに使う。URL と取り出した事実は `scripts/figs/<id>.md` に残す。
3. **描く。** `scripts/figs/svgkit.py` を使い、グリッド座標を docstring に先に書いてから描く。形態は `poly(smooth=True)` で点列から描き、答えは `note` で答えの隣に1個、読み順が要るなら `badge` を打つ。
4. **検査して見る。** 機械検査の後、原寸と約360px幅の PNG を `layout.md` の「説明力の確認」6項目で見る。落ちた項目を直して繰り返す。

### 検査

[repo.md](references/repo.md) の手順で `check_figure.py` を実行する（豆腐・はみ出し・文字の実効サイズ・ラベル数・形の一様さ）。全図を原寸・デスクトップ幅と約360px幅で目視し、本文との整合、文字・線・配置、焦点と注記の位置を確認する。修正後は検査と目視を繰り返す。

## 却下すべき図の型

- 本文が否定している枠組みを図が肯定してしまうもの（例：本文が「正規形の段階を上げれば解決する」を否定しているのに、1NF→2NF→3NF の階段図を描く）。**最も危険**。
- 本文から形が一意に復元できる曲線（「増やせば増える、ある点で頭打ちになる」とだけ書いてある飽和曲線）。
- 本文に語彙が無い形式を持ち込む図（本文が扱っていない理論の標準図を、説明のために持ってくる）。
- 本文の比喩で足りているものの図解。
- 「入力→処理→出力」「原因→結果」型の箱と矢印。
- 数値を3個並べただけの棒グラフ。
- 装飾目的の科学イラスト。自力描画は形態の理解に要るときだけ。
- 図の中に答えが無く、キャプションを読まないと何の図か分からないもの。
- 全要素が同じ太さ・同じ濃さで、どこを見ればよいかを示さないもの。
- 対比のためだけの3枚目。2枚を**同じ作図規約**（同じ向き・同じ座標系）で描けば、並べるだけで対比になる。

## 完了条件

- 上記の機械検査・目視（説明力の確認を含む）と、[repo.md](references/repo.md) のlint・サイトビルドが通っている。
- 教材内の図が内容に応じた形・表示幅になっている。
- 本文に各図への参照文、図に自己完結したキャプション、引用写真に帰属表記がある。
- 生成コード、作画資料と引用写真の出典、検査結果、採用・却下の理由が残っている。
