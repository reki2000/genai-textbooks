# やる夫式教材をつくる

読者が結論の根拠をたどれ、条件を変えた場面でも使えるようにする。登場人物が学ぶにつれて、判断・行動・関係が変わる読み物にする。

## 学びと物語

- 核心には、考える材料と確かめる機会を置く。「課題→素朴案→反例→原因→修正→検算」は有力な方法だが、全概念・全節に同じ順序を要求しない。観察、比較、成功の応用、教師の説明から理解を進めてもよい。
- 既習事項は即答してよい。未知の正答には、提示された情報や途中の推論が必要。「いや待て」「自信がない」だけを足して苦労の代わりにしない。用語や公式を先に教え、その意味を一緒に確かめてもよい。
- やる夫は読者の不満や願望を極端な案として口にし、自分で試して反例にぶつかる。改訂で他人の意見を整理するだけの役や、先回りして正解を言う優等生へ変えない。学んでも欲や焦りで短絡する面と、最後に判断が変わる面を両立させる。
- 各場面は、その人物の目的・疑問・作業から動かす。失敗や選択の結果を後へ残し、締切や解決策を都合よく追加しない。本文は会話だけで進め、状況・動作・時間経過も台詞で伝える。ト書きや地の文を足さない。
- 笑い、誤答、感情変化、発言長、最後の話者に回数や型を課さない。人物の暮らしや関係から自然に生じる笑いを使い、被害者の苦痛を笑いの材料にしない。同じ問答が続くときは、語尾より会話の目的と主導権を見直す。
- 比喩やトイ例は役立つものを育てる。復習は要約の再掲より、別条件への適用を優先する。演習は読者が答えを見る前に試せる形でもよい。終幕は到達点が行動や選択に現れたところで閉じ、総括を重ねない。

## 人物と書式

やる夫は楽観的で欲望に忠実な生徒役。一人称は「やる夫」、語尾は「だお」。やらない夫はぶっきらぼうだが面倒見のよい教師役。一人称は「俺」。既存教材の改訂では、その作品の人物像を優先する。脇役の人数・登場量は役割に合わせ、説明や否定だけを担当する人にしない。

冒頭の登場人物欄には立場を簡潔に書き、正体や結末を明かさない。本文は具体的な場面から始める。全体の紹介は `catalog.yml` の `question` と `plot` に置く。

## 面白味をつくる

- やる夫の案への反例は、その案を実行すると誰に何が起きるかで示す。短絡した案の奥にある切実な不満まで否定しない。
- 笑いは欲、面子、勘違い、人物間の情報差から生む。やらない夫も毎回同じ否定で返さず、あえて乗る、数字で帰結を示す、やる夫の着眼を認めるなど、応答を変える。笑いをすべて概念説明に従属させず、人物への親しみや息抜きも保つ。
- 舞台・小道具・脇役の事情を、問いや判断に効かせる。先の冗談や物が後で違う意味を持つ回収は、学びと余韻の両方を強くする。
- 大きな発見の前には、それまでの案では越えられない問題を育てる。発見後には行動・関係・見え方の変化を描く。静かな場面や詳しい説明も使い、全節を同じ強さの山にしない。
- 歴史の当事者が見ていた選択肢、具体的な数字の規模、原料や装置の意外なつながりは読みごたえの核になる。項目名の要約に置き換えず、現在の問いにつなぐ。

構成をつくるとき、大幅に改訂するとき、単調さを直すときは [面白味と起伏の手札](references/anti-patterns.md) を読む。各手札は選択肢であり、毎節の義務や採点項目ではない。

- 本文の書式・英語併記は [format.md](references/format.md)。
- 脚注を扱うときは [citation.md](references/citation.md)。
- 数式の導出は出発式・操作・結果を残し、記号・単位・条件を定義する。要所で数値・次元・極限を検算し、厳密式と近似式を分ける。
- 実例が必要なら元教材の該当箇所だけ読む：感情から問いを起こす [buddhism](../../../docs/books/buddhism/README.md) 第1幕、成功から長い問いへつなぐ [chemical-plant](../../../docs/books/chemical-plant/README.md) 第0幕、反例から数式を組み立てる [general-relativity](../../../docs/books/general-relativity/README.md) 4-2。設定・数値・書式をそのまま移植しない。

## 進め方

1. 対象読者、前提知識、読了後にできること、範囲、保存先を確認する。分量は必要な学びから決め、指定がなければ字数帯を目標にしない。
2. 新規・全体改訂では、各幕の出来事、得る理解、次へ残る課題を短いプロットにする。既に了承された方針は引き継いで進める。ユーザーが途中確認を指定した場合は、その区切りを守る。
3. 執筆する。長編では、定義・数値・人物が知る情報・現実と模型の時間・未解決事項・出典を短い台帳に残す。接続が怪しいときは台帳だけで判断せず、本文の対応箇所を読む。
4. 改訂では、学びと読みごたえを支える事例・数字・原料や仕組みの詳細・面白いやり取りを保つ。短縮を求められていなければ、整理を理由に削らない。縮約を求められた場合も、残す具体と魅力を先に選び、重複から整理する。情報を一発言へ押し込まない。
5. 全体を読み直し、学習の足場、人物の成長、場面のつながり、盛り上がりと中だるみを確認する。改訂前の良い場面がどう残ったかも照合する。意味と読み味は `yaruo-review`、事実・数式は `yaruo-proofread`、書式は `yaruo-format` を必要に応じて使う。

## 機械検査と読解を分ける

```bash
python3 scripts/yaruo_lint.py docs/books/<id>/README.md --check --verbose
python3 scripts/generate_site.py
```

error は解消する。warning / info は内容を読む手掛かりであり、数を減らすために会話を追加しない。書式が通っても、面白さ・意味の通り・事実の正しさを確認したことにはならない。教材の登録・下書き・公開はリポジトリの `AGENTS.md` と `BUILD.md` に従う。
