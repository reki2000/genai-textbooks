# やる夫式・再発見型教材を作る

解説の対話化ではない。核心概念ごとに **課題 → 素朴な案 → 具体的反例 → 原因の言語化 → 修正 → 検算** を描く。生徒が失敗を足場に理論を再発明し、教師は答えではなく次の一手と命名を担当する。

## 参照資料

**節を新規に書く、または会話を大幅に書き直すターンでは、最初の節を書く直前に [section-card.md](references/section-card.md) を1回読む。** 同じターン内の後続節では再読しない。プロットだけのターン、誤字・書式・脚注番号の修正では読まない。即答・教師総括・発言偏重の warning を内容修正で直すときは、修正前に読み直す。

| いつ | 読むもの |
|---|---|
| 本文を初めて書く／書式を大きく直す | [format.md](references/format.md) |
| 長編・サーベイのプロットを組む | [long-form.md](references/long-form.md) |
| 数式が核心の教材を書く | [math-dialogue.md](references/math-dialogue.md) |
| 脚注を付ける | [citation.md](references/citation.md)（書式の正本） |
| 分量削減を頼まれた | [condense.md](references/condense.md) |
| 構成が単調・講義的になった | [anti-patterns.md](references/anti-patterns.md) の該当項目だけ |
| 完成後・改訂後 | `python3 scripts/yaruo_lint.py <教材.md> --check --verbose` |

完成例は既定では読まない。導入がテーマ説明に流れる、教師の講義が続く、数式の展開が不自然になる、といった症状が出たときだけ `references/sample-intro-buddhism.md`、`references/sample-intro-chemical-plant.md`、`references/sample.md` から該当する1本を読む。特殊な作風が要るときは `rg '^#{2,3} ' docs/books/<id>/README.md` で見出しを確認し、該当する1〜3節だけ読む。既存教材の続編・改訂では、その教材自身を第一の参照元とする。内容・数式・固有名詞は流用しない。

## 3つの禁則

1. **冒頭に全体説明を置かない。** 登場人物紹介の直後は、いきなり第1幕の具体的な場面から始める。「はじめに」「本書の狙い」「対象読者」「学習の流れ」にあたる節も、同じ内容を地の文で述べる導入も書かない。これらは同じディレクトリの `catalog.yml` の `question` と `plot` が担う。
2. **第1幕の最初の節も、テーマ紹介から始めない。** やる夫が困っている、思いつく、失敗する、要求されるといった出来事から入る。教師が「今日は〜について学ぶ」と主題を宣言する形も避ける。
3. **末尾に演習を置く場合も、箇条書きの設問だけにしない。** 各演習でやる夫が誤答か不完全な案を出し、やらない夫が手掛かりを渡し、やる夫が推論と自己修正を経て正答へ到達する対話にする。

## 人物

**やる夫（生徒）**：楽観的・直情型で欲望に忠実。怠け者で**非常に調子に乗りやすく**、小さな成功をすぐ大成功へ飛躍させて夢を見る（「大儲けだお」）。打たれ弱いが立ち直りは早い。語尾は「〜だお」「〜だお！！」「〜なのかお？」、一人称は「やる夫」。感嘆符と三点リーダーを多用する。素朴案を自信満々に出し、失敗して悔しがり（「ぐぬぬ」）、過去の教訓を自力で流用する（「これさっきと同じ病気だお！」）。**計算の手を動かすのは基本的にやる夫。** 気づきは「……あっ」で立ち上げ、直後に自分の言葉で言語化する。

**やらない夫（教師）**：ぶっきらぼう・皮肉屋だが本質は面倒見が極めて良い。答えを先に言わず「計算してみろ」「では判定してもらおう」で駆動する。**命令でなく問いかけ**を基本とし、ドラマ上必要なときだけ命令する。承認は重要な転換点へ絞る。命名・整理・歴史的補足を担当し、節末で結論を奪わない。口調は「〜だろ」「〜じゃねぇよ」、一人称は「俺」、決め台詞は「そんなわけねぇだろ、常考。」

**できる子**は静かで簡潔な補助役（長門有希・綾波レイ系の口調。有名な台詞をそのまま使わない）。**できる夫**は高テンションの出木杉君。どちらもほとんど登場しない。

### 冒頭の「## 登場人物」欄

**立場だけを書き、振る舞いと作中でやることは書かない。** 所属・役職・年齢・前提知識・性格傾向といった**その教材でどういう立場の人物か**を書く。「答えを教えず、反例と問いで導く」「〜して転ぶ」「〜を突きつける」「〜を計算させる」のような作中の行動描写は、上の人物設定で担保されているので欄には書かない。結果として `**やらない夫** ── 物理学の教師。` の一行で終わってよい。

- **ネタバレを書かない。** 正体が後で明かされる人物の正体、人物の変化の到達点、教材の結末や「やる夫は〜していく」という筋の予告は入れない。冒頭の引用ブロックに書く全体説明も同じ扱いで、`貫く問い`、`!>` の注意書き、トイ例・マップ・基礎データの設定は残してよいが、結末に触れる文は落とす（禁則1も参照）。
- **1人100字以内**（`**名前** ── ` の見出しを含む。概算はバイト数÷3）。
- **載せるのは、複数の幕にまたがって登場する人物だけ。** 一つの幕や一つの節の中でだけ発言する人物は、発言数が多くても、また `できる子` `できる夫` のような常連の名前であっても載せない。「漁師」「移住者」のような役割名の話者も同じ。
- 人物以外でも、全編を通じて使い回す反復要素（トイ例、地図、基礎データ、計測器）は同じ欄に置いてよい。これらは100字の対象外。

導入・終幕を除く各主要幕で最低一度、やる夫の慢心と転落の弧を置く。ただし各節へ同じ慢心を割り当てない。感情の手札は慢心と転落だけでなく、好奇心、警戒、苛立ち、恥、恐怖、安堵、共感、達成感、笑いを使い分ける。笑いに重傷・重病・死・生活破綻・深刻な侮辱を使わない。

**終幕は箇条書きの要点整理や教師の講義的総括で締めない。** 最後の場面も対話にし、やる夫がその旅を情緒的に振り返り（冒頭の自分自身への呼応や、まだ解けない問いの余韻を伴う）、やらない夫がぶっきらぼうな優しさで短く受けて、開かれた地平を残して閉じる。

**地の文は書かず、状況・作業・感情はすべて台詞で表現する。** ただし、台詞だけでは時系列を誤読する場面転換では、`〜〜 翌朝 〜〜` のような短い時間・場面カードを話者外へ独立して置いてよい。カードに出来事や感情を書き込んで地の文の代用にしない。

## 制作フロー

### Step 0: 制約を固定する

作業種別（新規／続編／全体改訂／局所改訂／縮約改訂）、対象読者と前提知識、読了後にできること、扱う範囲と扱わない範囲、分量帯、保存先 `docs/books/<英字ハイフン区切り>/README.md` を決める。不明でも結果を大きく左右しないものは妥当な値を仮定して明示する。

分量帯は**作業スコープとコストの見積もり**であって品質基準ではない。標準3.4万〜5.1万字（単一テーマを6幕前後）／長編8.5万〜11.9万字（前提となる道具が多い単一テーマ）／サーベイ13.6万字以上（ユーザーと明示的に合意した場合だけ）。概算はファイルサイズ÷3。**分量を満たすために概念・会話・節を増やさない。**

### Step 1: プロットの合意を取る

新規・続編・全体改訂では、本文より先に幕構成を提示する。**プロットを提示したら執筆へ進まず、そこで作業を止めてユーザーの明示的な合意を待つ。** 局所改訂では、変更範囲と前後への影響を特定すれば全体プロットは不要。

各幕について、始動させる具体的な事件・矛盾・要求・前幕の副作用／やる夫の一見もっともらしい素朴案／それを壊す具体的反例／やる夫が言語化する失敗原因／再発見する概念と検算方法／感情と関係性の変化／次幕へ残す未解決課題／育てるトイ例／分量配分を高密度に書く。

基本形は「既存の考え方の破綻／核となる直観／核心アイデアへの跳躍／道具の構築（全体の40〜50%）／条件から答えを絞るクライマックス／既知の結果・実験・極限による検証」の6ブロック。テーマに応じて統合・分割してよい。各幕を因果で接続し、説明都合で新概念を突然出さない。**歴史・分派・応用だけを巡るツアー部分は全体の20%以内。**

### Step 2: 概念を分類し、躓きを設計する

**核心概念**は完全な再発見サイクルを回す。**前提知識**は想起させるか短く補い、独立したサイクルを強制しない。**補助用語**は必要な時点で定義し、節を増やさない。

核心概念ごとに「始動課題／素朴な案／数行で試せる反例／過去の足場／検算例／次へ残す課題」を内部で表にする。概念数が分量帯に収まらなければ、範囲を削るか上位概念へ統合してから執筆する。

**核心概念・補助用語には、命名した時点の1回だけ英語を併記する**（`長期増強（long-term potentiation）`）。見出しには付けない。書式の詳細は [format.md](references/format.md) の「専門用語の英語併記」。

素朴な案は初学者にも一見もっともらしいものにする。**藁人形を作らない。** 生徒が知識予算（執筆前の前提知識＋作中で既に到達した内容）を超えた知識を突然披露しないよう、各概念の登場順を先に確かめる。後半では、前に使った失敗・式・比喩・反復トイ例を再利用する。素朴な案が歴史上で実際に試され棄却された事実を確認できる場合は積極的に使う。史実を捏造せず、確認したURLを作業メモへ残す。名前や年号の羅列で再発見サイクルを置き換えない。

### Step 3: 再発見サイクルを回す（最重要）

核心概念を一つ導入するたびに、次を一巡させる。

1. **具体的・現実的な課題**：その概念が必要になる課題を置く。前節の未解決事項や解決策の副作用を引き継いでよい。読者が事前知識なしでも「それは困る」と納得できる状況にする。説明したい概念名から会話を始めない。
2. **素朴な案**：やる夫が「〜でいいお」と、初学者が本当に思いつきそうな、条件の一部は満たす案を出す。
3. **具体的反例**：教師が数行で計算・判定できるトイ例やデータを渡す。教師が破綻を宣告するのではなく、**やる夫自身に手を動かさせ**、予想と結果の食い違いを確認させる。
4. **原因の言語化**：やる夫が「失敗した」ではなく失敗の構造を自分の言葉で説明する（例：「座標の取り方で結果が変わるのは物理としてありえないお」）。**ここを教師に代弁させない。** 言語化を次の修正案の設計条件にする。
5. **修正**：教師は答え全体でなく方向や次の一手だけを示し、やる夫が反例を避ける式・定義・設計を組み立てる。**命名は、やる夫が中身へ到達した後**に行う。
6. **検算**：新しい道具を具体例へ適用し、期待どおり動くことをやる夫自身に確認させる。可能なら**合格例と不合格例の両方**で判定する。最初の反例を新しい概念で再判定できるなら、それを優先して失敗を回収する。

**1節につき1つの中心問題。それを掘り下げるのに必要な長さだけ書く。** 短い中心問題は隣接節へ統合し、2つの核心概念が競合する節は分割する。ユーザーが字数を指定した場合はそれに従う。教材全体で再利用できる、単純だが非自明なトイ例を一つ育てる。

### Step 4: 分割執筆でも状態を小さく保つ

**2幕分の執筆が完了した時点で執筆を止め、ユーザーにレビューを依頼する。承認を得るまで3幕以降を書き始めない。**

本文全体を毎回読み直さず、次を含む短い状態台帳を作業メモとして維持する：対象読者と知識予算、幕ごとの到達点と現在位置、定義済みの用語・記号・数値、反復トイ例の使用履歴、植えた伏線と回収先、未解決課題、幕ごとの感情曲線、確認済み事実の出典URL。

節を書き終えるたびに台帳を更新する。次の節では、プロット、台帳、直前の接続部分だけを優先して読む。**台帳が古いと気づいたら、既存本文を検索して欠落分を補ってから続きを書く。**

### Step 5: 納品する

リポジトリ直下から実行する。

```
python3 scripts/yaruo_lint.py <教材.md> --check --verbose
```

- **error は必ず解消する**（exit 1）。脚注の未使用・未定義、節番号の破れ、終端マーカーと見出しの揺れ、冒頭の全体説明節、金額・割合の表記、制御文字・私用領域文字の混入。`--fix` で機械修正できるルールは `--list-rules` の `fix` 印で分かる（`invisible-chars` は文意の判断を伴うので手で消す）。
- **warning は人が内容を見て可否を判断する。機械的に0を目指さない。** 節ごとの内訳（実効往復・発言長分布・高速区間）は `--verbose` の info に出る。**info は診断であって合否ではない。**

- `term-english` の warning は英語併記の**置き方**（初出でない位置・重複・半角括弧）だけを見る。どの語に併記すべきかは機械には決められないので、そこは人が確認する。

スクリプトが見ないのは、専門用語に英語併記が付いているか、素朴な案が藁人形でないか、ツアー部分が20%以内か、数式の途中式と検算が足りているか、伏線が回収されているか、感情曲線が隣接節で反復していないか。ここだけを人手で確認する。

書式lintは `yaruo-format`、ファクトチェックは `yaruo-proofread` が担当する。教材カタログや公開目次は、教材完成をユーザーが確認した後に別工程で更新する。
