# やる夫式・再発見型教材を作る

単なる解説の対話化ではなく、核心概念ごとに **課題 → 素朴な案 → 具体的反例 → 原因の言語化 → 修正 → 検算** を描く。生徒が失敗を足場に理論を再発明し、教師は答えではなく次の一手と命名を担当する。

## 教材全体に効く3つの禁則

節単位の作法は [references/section-card.md](references/section-card.md) にまとめてある。ここでは本の骨格を決める、後から直すと手戻りになるものだけを挙げる。

1. **冒頭に全体説明を置かない。** タイトルと登場人物紹介の直後は、いきなり第1幕の具体的な場面から始める。「はじめに」「この教材について」「本書の狙い」「対象読者」「扱う範囲」「学習の流れ」にあたる節も、同じ内容を地の文で述べる導入も書かない。これらは本文と同じディレクトリの `catalog.yml` の `question` と `plot` が担う。
2. **第1幕の最初の節も、テーマ紹介から始めない。** やる夫が困っている、思いつく、失敗する、要求されるといった具体的な出来事から入り、読者にはその場面から状況を掴ませる。教師が「今日は〜について学ぶ」と主題を宣言する形も避ける。
3. **末尾に演習を置く場合も、箇条書きの設問だけにしない。** 各演習でやる夫がもっともらしい誤答または不完全な案を出し、やらない夫が内容を受け止めて手掛かりを渡し、やる夫が推論・計算・自己修正を経て正答へ到達する対話にする。

やる夫は**非常に調子に乗りやすい**人物として描き、導入・終幕を除く各主要幕で最低一度は、簡単なアイデアや小さな成功から大成功を早合点して夢見る言動を入れる。ただし各節へ同じ慢心と転落を割り当てない。この幕をまたぐ大きな弧とは別に、節ごとの小さなボケとツッコミの掛け合いがあり、そちらは [references/section-card.md](references/section-card.md) が持つ。

## 制作フロー

### Step 0: 制約を固定する

次を作業冒頭に決める。不明でも結果を大きく左右しないものは、既存教材と依頼内容から妥当な値を仮定して明示する。

- 作業種別：新規、続編、全体改訂、局所改訂、縮約改訂
- 対象読者と前提知識、読了後にできるようになること
- 扱う範囲と扱わない範囲
- 分量帯と保存先 `docs/books/<英字ハイフン区切り>/README.md`

分量は次から選ぶ。概算文字数はファイルサイズ÷3を目安とする（正確な集計が要るときだけ yaruo-count を使う）。

| 分量帯 | 目安 | 用途 |
|---|---:|---|
| 標準 | 3.4万～5.1万字 | 単一テーマを6幕前後で再発見する |
| 長編 | 8.5万～11.9万字 | 前提となる道具が多い単一テーマ |
| サーベイ | 13.6万字以上 | 分野を体系的に巡る。ユーザーと明示的に合意した場合だけ選ぶ |

分量を満たすために概念や会話を増やさない。範囲が狭ければ短くする。

### Step 1: プロットの合意を取る

新規・続編・全体改訂では、本文より先に幕構成を提示してユーザーの合意を取る。**プロットを提示したら執筆へ進まず、そこで作業を止めてユーザーのレビューと明示的な合意を待つ。** 各幕を1～2文でまとめ、幕を始動させる具体的な要望・矛盾・クレーム・前幕の副作用、生徒の到達点、次幕へ残す未解決課題、感情トーン、分量配分を含める。局所改訂では、変更範囲と前後への影響を特定すれば新しい全体プロットは不要。

基本形は次の6ブロックとする。テーマに応じて統合・分割してよい。

1. 既存の考え方の破綻
2. 核となる直観
3. 核心アイデアへの跳躍
4. 道具の構築（全体の40～50%）
5. 条件から答えを絞るクライマックス
6. 既知の結果、実験、極限による検証

歴史・分派・応用だけを巡るツアー部分は全体の20%以内にする。各幕を因果で接続し、説明都合で新概念を突然出さない。

長編・サーベイでは、プロットに次の反復構造も組み込む。

- 導入・終幕を除く各主要幕の終盤に、同じ名前と形式を持つ短いコラム的コーナーを置く。その幕で得た道具を現実の事例、観察、別のトイ例、小さな判定問題へ適用し、幕が進むほど過去の道具も重ねて使う。単なる要点の再掲にしない。
- 2〜4幕ごとの大きな区切りに `## 幕間` を置き、これまでの発見をやる夫がまとめる、別事例へ転移して発展させる、やらない夫のクイズをやる夫が迷い・誤りを経て解く、という機能を組み合わせる。本全体でこの三つをすべて少なくとも一度は行う。
- コラムと幕間を分量調整の付録にしない。前の幕を回収して次の幕の未解決課題を立ち上げる接続部として働かせる。これらも節として扱い、[references/section-card.md](references/section-card.md) の作法を適用する。

構造の参照例は `docs/books/chemical-plant/README.md` の「工場を読む①〜⑥」（幕末の累積適用）、「幕間　量産化の博物館」（歴史事例への転移）、「8-4　最後のテスト」（全幕の統合クイズ）。`rg -n '^### .*工場を読む|^## 幕間|^### 8-4' docs/books/chemical-plant/README.md` で位置を特定し、該当箇所だけを読む。

### Step 2: 概念を分類し、躓きを設計する

- **核心概念**：読者自身が到達すべき学習目標。完全な再発見サイクルを回す。
- **前提知識**：既習として想起させるか、短く補う。独立したサイクルを強制しない。
- **補助用語**：理解に必要な時点で定義する。節を増やさない。

核心概念ごとに次の表を内部で作る。概念数が分量帯に収まらなければ、範囲を削るか上位概念へ統合してから執筆する。

| 核心概念 | 始動課題 | 生徒の素朴な案 | 数行で試せる反例 | 過去の足場 | 検算例 | 次へ残す課題 |
|---|---|---|---|---|---|---|

素朴な案は初学者にも一見もっともらしいものにする。藁人形を作らない。生徒が知識予算（執筆前の前提知識＋作中で既に到達した内容）を超えた知識を突然披露しないよう、各概念の登場順を先に確かめる。後半では、前に使った失敗、式、比喩、反復トイ例を再利用する。

### Step 3: 再発見サイクルを回す（最重要）

**節を書き始める前に毎回 [references/section-card.md](references/section-card.md) を読む。** 核心概念を一つ導入するたびに、次の型を一巡させる。

1. **具体的・現実的な課題の提示**：その概念が必要になる課題を置く。前節の未解決事項や解決策の副作用を引き継いでよい。新出課題なら、読者が事前知識なしでも「それは困る」と納得できる状況にする。説明したい概念名から会話を始めない。
2. **素朴な案**：生徒が「～でいいお」のように、初学者が本当に思いつきそうな単純案を出す。一見もっともらしく条件の一部は満たす案にする。
3. **具体的反例**：教師が「では判定してもらおう」と、数行で計算・判定できるトイ例やデータを渡す。教師が破綻を宣告するのではなく、生徒自身に手を動かさせ、予想と結果の食い違いを確認させる。
4. **原因の言語化**：生徒が、単に「失敗した」と言うのでなく、失敗の構造を自分の言葉で説明する（例：「座標の取り方で結果が変わるのは物理としてありえないお」）。ここを教師に代弁させない。原因の言語化を次の修正案の設計条件にする。
5. **修正・正しい概念への到達**：教師は答え全体でなく方向や次の一手だけを示し、生徒が反例を避ける式・定義・設計を組み立てる。教師による概念の**命名は、生徒が中身へ到達した後**に行う。
6. **検算**：新しい道具を具体例へ適用し、期待どおり動くことを生徒自身に確認させる。可能なら**合格例と不合格例の両方**で判定する。最初の反例を新しい概念で再判定できるなら、それを優先して失敗を回収する。

数式が核心となるサイクルでは、最終式だけを提示しない。定義の代入、式の展開、項の消去、近似や対称性の適用など、結論に必要な中間段階と各変形の理由を会話でたどる。機械的に長い計算だけを圧縮し、概念的な跳躍を「計算すると」で隠さない。詳細は [references/style-guide.md](references/style-guide.md) の「数式・導出の説明」に従う。

一つの中心問題を掘り下げるのに必要な長さだけ書く。短い中心問題は隣接節へ統合し、二つの核心概念が競合する節は分割する。

教材全体で再利用できる、単純だが非自明なトイ例を一つ育てる。可能なら生徒自身に数値を出させる。素朴な案が実際に歴史上で試され、棄却・修正された事実を確認できる場合は積極的に使う。件数に上限は設けないが、名前や年号の羅列で再発見サイクルを置き換えない。史実を捏造せず、確認したURLを作業メモへ残す。

### Step 4: 分割執筆でも状態を小さく保つ

2幕分の執筆が完了した時点で執筆を一旦止め、ユーザーにレビューを依頼する。**承認を得るまで3幕以降の執筆を開始しない。**

長文では、本文全体を毎回読み直さず、次を含む短い状態台帳を作業メモとして維持する。

- 対象読者と知識予算、幕ごとの到達点と現在位置
- 定義済みの用語・記号・数値、反復トイ例の使用履歴
- 幕末の反復コーナーで使った題材と累積適用の履歴、幕間の配置と実施済み機能
- 植えた伏線、回収先、未解決課題、確認済み事実の出典URL

節を書き終えるたびに台帳を更新する。次の節では、プロット、台帳、直前の接続部分だけを優先して読み、整合性確認が必要な箇所だけ検索する。

### Step 5: 納品する

リポジトリ直下から次を実行する。このスクリプトは同スキル配下にあるため、`scripts/check_dialogue_constraints.py` として探さない。

```
python3 .claude/skills/yaruo-rediscovery/scripts/check_dialogue_constraints.py <教材.md>
```

- **error は必ず解消する**（exit 1）。脚注の未使用・未定義、節番号の破れ、終端マーカーと見出しの揺れ、冒頭の全体説明節、金額・割合の表記。表記違反は `normalize_financial_numbers.py <教材.md> --apply` で機械修正できる。
- **warning は人が内容を見て可否を判断する。** 節の字数と往復数、発言長の偏り、節末を教師が締めていないか、承認語のインフレ、解説の無い脚注。抑止が正しい場合もあるので、機械的に0を目指さない。節ごとの内訳は `--verbose` で出る。

スクリプトが見ないのは、素朴な案が藁人形でないか、ツアー部分が20%以内か、数式の途中式と検算が足りているか、伏線が回収されているか、感情曲線が隣接節で反復していないか。ここだけを人手で確認する。

教材カタログや公開目次は、教材完成をユーザーが確認した後に別工程で更新する。

## 縮約改訂 ── 既存教材の分量を削減する

分量削減を頼まれたら、書き直す前に節数と1節あたりの情報量から逆算し、達成可能な削減率を数字で提示して合意を取る。往復数だけを減らしても字数は減らない。節を統合すると統合先の発言へ内容が集まるため、**字数は往復数ほどには減らない**。

1. 節ごとにUnicode字数、実効往復数、発言長の分布を `--verbose` で実測して一覧にする。
2. 原寸で残す固定部（冒頭の節、終幕、参考文献、登場人物）を確定して目標から引く。削減率の分母に参考文献を含めるかもここで決めて共有する。数ポイント動く。
3. 残す節を1節の標準字数へ割り付ける。**残す節数 × 下限字数** が、情報量を維持した圧縮の概算下限になる。目標がこれを下回るなら概念または節の削除が必要で、削除候補の節名と字数を並べて指示を仰ぐ。
4. 案を複数出すときは「全概念を残す案」と「概念を削る案」を分け、それぞれの到達率を数字で示す。到達できない率を約束しない。

削りやすい順は次のとおり。

1. 幕間の総復習。直前の幕末コーナーと内容が重複していることが多い。
2. 節末の「分かったのは三つだお」形式の総括。発見と残った疑問の1〜2行へ縮める。
3. 同型計算の2回目。手順は既出なので、条件と結果と一行の含意だけにする。
4. 近接して反復する同型の慢心、転落、承認、要約。同じ感情曲線を一つにまとめる。
5. 帳簿・台帳・一覧の全行列挙。上位3行と「その他」へ丸めるか、表へ落とす。
6. 末尾の演習。本編で同じ判定を一度通していれば重複度が高い。

縮約後は `check_dialogue_constraints.py` と `python3 scripts/generate_site.py` を実行する。脚注の孤立と節番号の破れは前者が検出するので、残る確認は節や幕間を落とした箇所の前後接続（直前の節末が残した問いを、直後の節冒頭が受けているか）だけでよい。
