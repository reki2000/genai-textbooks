# 教材を読者の立場で評価する

執筆ルールへの適合や回数の多寡を品質の代わりにしない。教材全体を読み通した読者に何が積み上がり、何が記憶に残るかで評価する。レビューだけの依頼では本文を編集しない。修正も依頼されていれば、合意された範囲で改訂まで進める。

## 観点

題名・`catalog.yml` の問いと対象本文を確認し、全体評価では通読する。各観点を、良い場面と改善したい場面の両方から本文の証拠で判断する。

| 観点 | 良い状態 | 典型的な欠陥 |
|---|---|---|
| 学習の蓄積 | 後の節が前の理解を道具にして、一段深い問いや別条件の問題を解く。終盤ほど少ない説明で多くを判断できる | 項目を並べるだけで、前の節を読まなくても後の節が読める。同じ説明のやり直し。学んだことが後で一度も使われない |
| 議論の継続性 | 各節が、前段の未解決の問い・失敗・約束・やる夫の不満から始まる。話題の転換に人物側の理由がある | 唐突な話題転換。解決のための設定・締切・資料が都合よく追加される。前段の結論と矛盾したまま進む |
| 発見と物語の一体化 | 発見がその場面の出来事・人物の欲や失敗から生じ、場面を差し替えると学びも変わる。歴史の当事者、数字の規模、仕組みや原料の意外なつながりなど、記憶の手掛かりになる周辺情報が豊富 | 場面が飾りで、別の話題へ移植しても内容が変わらない。発見が教師の説明として届くだけで、印象に残る具体がない。周辺情報が項目名の要約に痩せている |
| 伏線回収 | 仕込みだけで後から合理的に説明がつき、しかも回収の直前には予測しにくい。回収で物や冗談の意味が変わり、学びが深まる | 回収のための情報を回収の場で追加する。予告どおりに回収されて意外性がない。仕込みが放置される |
| 会話のテンポ | 発言の長短と主導権が内容に応じて変わり、各発言が直前の相手に応答している。説明の山の後に息抜きがある | 教師の長い講義の連続。一発言への情報の詰め込み。総括の重ね。相槌だけの受け |
| やる夫の知識量 | やる夫はその時点で本文に出た情報と日常感覚から考え、欲や短絡で素朴な案を出す。既習事項は即答してよい | 未習の専門用語・正式名・結論をやる夫が先に言う。教師の総括に「だお」を付けただけの台詞。命名や太字の結論をやる夫が先取りする |
| やらない夫の教え方 | ぶっきらぼうでも面倒見がよい。問い、具体例、あえて乗る、帰結を数字で見せる、着眼を認めるなど応答が変わる | 「計算しろ」「言え」「やり直せ」のような命令で会話を駆動し続ける。毎回同じ否定で返す。答えを出す以外の仕事をしない |
| 配役と記号 | やる夫とやらない夫が軸で、できる子・できる夫・できる代が出るなら固有の立場・信念・欲を持って話を動かす。物や場所は具体的な名前で呼ばれる | レギュラー以外の人物（きめぇ丸・きらきーなど別系統のキャラクター、職業名・固有名で作品ごとに作った脇役）が出る。レギュラーでも論点を読み上げるためだけに出て消える。`Y-17` のような識別子や在庫コード風の呼び名。先に宣言した枠を幕ごとに読み上げる監査文書的な装置 |

次は欠陥ではない。

- しつこいくらいのギャグの繰り返し。回数を減らす改善案を出さない。
- 既習事項の即答、教師の説明、静かな場面、詳しい説明、意図的な復習。
- 意図された誤答や暴論。教材の結論との区別が伝わるかだけを見る。
- 再発見の手順（課題→素朴案→反例→原因→修正→検算）の空欄。読者が理解できない具体的な飛躍だけを指摘する。

## 見本

品質がよいと著者が判断した教材：`japan-food-policy`、`birthrate-and-aging`、`education`、`chemical-plant`、`philosophy`、`buddhism`、`memory-chip`、`memory-engram`。観点の判断に迷ったら、同じ観点でこれらの該当場面と比べる。題材・設定・数値・書式を基準として移植せず、点数や回数の目標にもしない。

## 進め方

1. **台帳をつくる。** 長い教材や全体評価では、判定の前に [台帳](references/ledger.md) を節ごとに作る。概念の初出と再利用、未解決の問い、やる夫が使った語の初出、発見を支える具体、伏線の仕込みと回収を引用付きで拾う。台帳づくりの段階では評価しない。
2. **観点ごとに判定する。** 蓄積・継続性・やる夫の知識量・伏線は台帳の前後関係から候補を出し、原文の前後を読んで確定する。一体化・テンポ・教え方・配役は該当場面を読んで判断する。台帳だけで欠陥を断定しない。
3. **伏線は二段で確かめる。** 回収ごとに、仕込みの位置だけで後から説明がつくか（合理性）と、回収直前までの本文から予測できたか（意外性）を分けて書く。確かめる価値のある回収では、回収直前までの本文だけを別の読み手（サブエージェント等）に渡して展開を予測させ、当たったかを記録してよい。
4. **全体を見る。** 冒頭の問いが終盤で答えられ、到達点が行動や選択に現れているか。盛り上がりと中だるみの区間を、前後の文脈と合わせて示す。

## 機械で確かめること

```bash
python3 scripts/yaruo_lint.py docs/books/<id>/README.md --check --verbose
```

error は書式上の欠陥として扱う。warning / info は品質の合否に使わない。

回数や比率（特定の反応語の回数、話者比率、ビートの指示率・苦労率など）は、読む区間を絞る手掛かりにだけ使い、良否の根拠にしない。数を増減させる改善案も出さない。話者の一覧は lint の `--stats`、同型反復の候補は `scripts/yaruo_beat_repetition.py --show`（ラベルを付ける場合だけ [beat-labels.md](references/beat-labels.md)）で出せる。候補が0件でも通読を省略しない。

事実・数式の疑いは `yaruo-proofread` で確認するか、未確認と明記する。

## 報告する

最初に全体の評価と **改訂要否** を示す。

| 判定 | 目安 |
|---|---|
| そのまま | 観点ごとの指摘が局所的な言い回しに留まる |
| 部分改訂 | 特定の幕・節で蓄積・継続性・一体化・人物の知識や態度が崩れているが、全体の骨格は機能している |
| 全体改訂 | 学習が積み上がらない、配役や記号装置が全体に浸透している、やる夫とやらない夫の役割が全体で崩れているなど、骨格から直す必要がある |

判定には、根拠とした観点と代表的な証拠を添える。点数や観点の平均で決めない。

続けて、残すべき魅力（改訂しても失ってはいけない場面・具体・人物の持ち味）と、優先する改善を観点ごとに示す。指摘には **本文の位置と引用断片／読者への影響／具体的な改訂案** を付ける。反復・矛盾なら比較する箇所を、不在なら調べた範囲を示す。好みと明確な不整合を分け、必要なものから順に報告する。

改善の手法が必要なら [面白味と起伏の手札](../yaruo-rediscovery/references/anti-patterns.md) を使う。手札の未使用を欠陥にせず、その教材で生じている読者体験を根拠にする。過去の診断例として [`v2-to-v3.md`](../../../v2-to-v3.md) があるが、症状の見立ての参考に留め、そこでの処方（命令で駆動する教師、反応語の回数など）を基準にしない。

修正した場合は、前後の接続に加え、具体例・数字・詳細・人物の持ち味を削って読みごたえを失っていないか旧版と比べ、検証結果も伝える。行番号は変わるので、改稿後は引用から位置を取り直す。

## 他の読み手を使う場合

長い教材や大幅改訂でLunaを一次読者に使う場合は [Lunaを使う一次レビュー](references/low-cost-review.md) に従う。方法の提案だけを依頼された場合は起動しない。

Codex ⇄ Claude の書面協議は `discuss` を使う。招待には対象・問い・修正範囲だけを書き、双方が独立した評価を固定してから開示する。観点を分担せず、同じ本文を読む。各指摘を本文の証拠で照合し、一致を多数決の正しさとみなさない。不一致と理由を残す。修正する場合は適用項目を双方で確定し、開始側だけが編集、相手が差分を確認してから終了する。通信・終了手順は `discuss` を正本とする。

定量評価の pilot を明示的に依頼された場合だけ [試行ルーブリック](references/entertainment-learning-rubric.md) と対応 schema を使う。通常のレビューへ採点表やゲートを持ち込まない。
