# 教材を読者の立場で評価する

教材全体を読み通した読者に何が積み上がり、何が記憶に残るかで評価する。執筆ルールへの適合、回数・比率・点数を品質の代わりにしない。レビューだけの依頼では本文を編集しない。修正も依頼されていれば、合意された範囲で改訂まで進める。

## 観点

題名・`catalog.yml` の問いと本文を確認し、全体評価では通読する。各観点を、良い場面と改善したい場面の両方から本文の証拠で判断する。

| 観点 | 良い状態 | 典型的な欠陥 |
|---|---|---|
| 学習の蓄積 | 後の節が前の理解を道具にして、一段深い問いや別条件の問題を解く。終盤ほど少ない説明で多くを判断できる | 項目の並列で、前の節を読まなくても後の節が読める。同じ説明のやり直し。学んだことが後で使われない |
| 議論の継続性 | 各節が前段の未解決の問い・失敗・約束・やる夫の不満から始まり、転換に人物側の理由がある | 唐突な話題転換。解決のための設定・締切・資料の後付け。前段の結論と矛盾したまま進む |
| 発見と物語の一体化 | 発見が場面の出来事や人物の欲・失敗から生じ、場面を差し替えると学びも変わる。歴史の当事者、数字の規模、仕組みや原料の意外なつながりなど、記憶の手掛かりになる周辺情報が豊富 | 別の話題へ移植しても内容が変わらない飾りの場面。教師の説明として届くだけの発見。項目名の要約に痩せた周辺情報 |
| 伏線回収 | 仕込みだけで後から合理的に説明がつき、回収の直前には予測しにくい。回収で物や冗談の意味が変わり、学びが深まる | 回収の場での情報の後付け。予告どおりの回収。放置された仕込み |
| 会話のテンポ | 発言の長短と主導権が内容に応じて変わり、各発言が直前の相手に応答する。説明の山の後に息抜きがある | 教師の講義の連続。一発言への詰め込み。総括の重ね。相槌だけの受け |
| やる夫の知識量 | その時点で本文に出た情報、日常感覚、登場人物欄の立場から自然に持つ知識で考え、欲や短絡で素朴な案を出す。既習事項は即答してよい。本文の推論から分類を言い当てるのは発見 | 未習の用語・正式名・結論を先に言う。命名や太字の結論の先取り。教師の総括に「だお」を付けただけの台詞 |
| やらない夫の教え方 | ぶっきらぼうでも面倒見がよい。問い、具体例、あえて乗る、帰結を数字で見せる、着眼を認めるなど応答が変わる | 「計算しろ」「言え」のような命令で会話を駆動し続ける。毎回同じ否定。答えを出す以外の仕事がない |
| 配役と記号 | やる夫とやらない夫がメイン。できる子は準レギュラー、できる夫は必要な場面だけに出て、固有の立場・信念・欲で話を動かす。物や場所は具体的な名前で呼ぶ | できる子・できる夫がメインから主導権を奪う、できる夫が不要な場面に居続ける。レギュラー外の人物（できる代、きめぇ丸などの別系統、作品ごとに作った脇役。一行だけの群衆や、登場人物欄にない話者も含む。当事者の声はレギュラーの台詞の中で伝える）。論点を読み上げて消えるだけの登場。`Y-17` のような識別子が具体物の名前を置き換える。先に宣言した枠や版番号を、幕ごとに同じ型で読み上げて話を進める装置（失敗から一つずつ育ち、形を変えていく枠は装置ではない） |

次は欠陥ではない。

- しつこいくらいのギャグの繰り返し。回数を減らす改善案を出さない。
- 既習事項の即答、教師の説明、静かな場面、詳しい説明、意図的な復習。
- 意図された誤答や暴論。教材の結論との区別が伝わるかだけを見る。
- 再発見の手順（課題→素朴案→反例→原因→修正→検算）の空欄。読者が理解できない具体的な飛躍だけを指摘する。

**見本**：著者が品質良と判断した `japan-food-policy`、`birthrate-and-aging`、`education`、`chemical-plant`、`philosophy`、`buddhism`、`memory-chip`、`memory-engram`。判断に迷ったら同じ観点で該当場面と比べる。題材・設定・数値・書式は移植しない。`birthrate-and-aging` のできる代は配役の見本にしない。

## 進め方

1. **台帳をつくる。** 長い教材や全体評価では、判定の前に [台帳](references/ledger.md) で前後関係を引用付きで拾う。この段階では評価しない。台帳は作業用で、報告には求められた場合だけ含める。
2. **観点ごとに判定する。** 台帳から出た候補は原文の前後を読んで確定・棄却する。一体化・テンポ・教え方・配役は該当場面を読んで判断する。
3. **伏線は合理性と意外性を分けて書く。** 筋は予告どおりでも仕掛けが意外なら、両方を書く。確かめる価値のある回収は、回収直前までの本文だけを別の読み手（サブエージェント等）に渡して展開を予測させ、当たったかを記録してよい。
4. **全体を見る。** 冒頭の問いが終盤で答えられ、到達点が行動や選択に現れているか。盛り上がりと中だるみの区間を前後の文脈と合わせて示す。

## 機械で確かめること

```bash
python3 scripts/yaruo_lint.py docs/books/<id>/README.md --check --verbose
```

error は書式上の欠陥として扱う。warning / info、特定の反応語の回数、話者比率、ビートの指示率・苦労率などは、読む区間を絞る手掛かりにだけ使う。良否の根拠にせず、数を増減させる改善案も出さない。話者の一覧は lint の `--stats`、同型反復の候補は `scripts/yaruo_beat_repetition.py --show`（出力の読み方とラベルは [beat-labels.md](references/beat-labels.md)）。候補が0件でも通読を省略しない。

字数・日付・簡単な計算のように本文だけで確かめられる食い違いはレビュー内で確かめてよい。出典の要る事実や数式の導出は `yaruo-proofread` で確認するか、未確認と明記する。

## 報告する

最初に全体の評価と **改訂要否** を、根拠とした観点と代表的な証拠を添えて示す。点数や観点の平均では決めない。

| 判定 | 目安 |
|---|---|
| そのまま | 指摘が局所的な言い回しに留まる |
| 部分改訂 | 欠陥が特定の幕・節に留まり、その範囲の書き直しで直る |
| 全体改訂 | 欠陥が全幕に及び、局所の修正では直らない。学習が積み上がらない場合に加え、学習と物語の筋が健全でも、配役・記号装置・会話の型・メイン二人の役割の崩れが全幕に浸透していれば全体改訂とし、残す筋を明記する |

続けて、残すべき魅力（改訂で失ってはいけない場面・具体・人物の持ち味）と、優先する改善を観点ごとに示す。指摘には **本文の位置と引用断片／読者への影響／具体的な改訂案** を付ける。反復・矛盾なら比較箇所を、不在なら調べた範囲を示す。好みと明確な不整合を分ける。

改善の手法は [面白味と起伏の手札](../yaruo-rediscovery/references/anti-patterns.md) を使ってよいが、手札の未使用を欠陥にしない。

修正した場合は、具体例・数字・詳細・人物の持ち味を削っていないか旧版と比べ、前後の接続とあわせて検証結果を伝える。改稿後は引用から位置を取り直す。

## 他の読み手を使う場合

- 長い教材や大幅改訂でLunaを一次読者に使う場合は [Lunaを使う一次レビュー](references/low-cost-review.md) に従う。方法の提案だけを依頼された場合は起動しない。
- 定量評価の pilot を明示的に依頼された場合だけ [試行ルーブリック](references/entertainment-learning-rubric.md) と対応 schema を使う。
