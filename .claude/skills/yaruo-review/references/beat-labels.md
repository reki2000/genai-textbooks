# ビートラベルと同型反復の検出

会話の「型」が反復しているかを、語の一致ではなく**発言が直前の発言に対して何をしたか**で測る。
固定語での検出は使わない。同型反復は語の一致ではなく関係の型の一致であり、実測でも
語彙が毎節入れ替わりながら型だけが残る例が出ている（`bureaucracy` 4-1〜6-2）。

検出は2層。層2は機械、層3は読み手の意味判断。**層2は候補の絞り込みであって合否ではない。**

## 層2 表層（機械・語彙非依存）

```bash
python3 scripts/yaruo_beat_repetition.py docs/books/<id>/README.md
python3 scripts/yaruo_beat_repetition.py docs/books/<id>/README.md --show   # 会話の具体つき
```

発話ターンを「役割ID（書内の総発話量順位）× 長さ級 × 終端型 × 非散文の有無」の1記号に落とし、

- **単位内単調度 M**：周期反復が列を占める割合。`ABABAB` を直接捉える。
  周期の上限は固定3ではなくターン数に応じて可変（最大6）。3ターンより長い
  型の反復（摩擦→導出→提示、など）も拾うため
- **単位間新規性 N**：隣接単位の正規化編集距離。**その教材自身の中央値で正規化する**

を出す。教材ごとに地の文体が違うため、書間で共通の閾値は意味を持たない。
`N` が書内下位に3単位以上連続で留まる区間を `same-beat-run` の候補として出す。

**層2の取りこぼしは既知。** 表層の統計が動いていて型だけが同じ区間は落ちる
（`weather-forecasting` 第4幕は厳密記号では層2は0件、層3で検出される）。層2で0件でも、
観点1の通読を省略しない。

取りこぼしの主因は、長さ級・終端型が境界1文字で記号ごと変わり、型が同じでも
新規性を高く誤判定させること。これを補うため、役割と非散文の有無だけの粗い記号
（`loose_symbols`）でも同じ検定をかけ直し、厳密ランに載らない区間を
`loose-novelty-candidate` として別枠で出す（`?` 行）。3単位未満の短い区間も
除外しない。**あくまで層3へ回す候補であり、合否には使わない。**
`weather-forecasting` 第4幕は、厳密記号では `runs=0` でも
`act-04.section-02…act-04.section-04` が candidate として出る。

## 層3 ビートラベル（読み手が付ける）

候補区間と、比較のための対照区間（同じ教材の非候補区間）にだけ付ける。全文には付けない。
判定基準は**どんな語が出たかではなく、直前のターンに対して何をしたか**。

| 側 | ラベル | 意味 |
|---|---|---|
| 教師 | **指示** | 命令形で次の作業を与える |
| 教師 | **問い** | 答えを生徒に探させる問いかけ |
| 教師 | 摩擦 | 反例・反証・失敗の提示 |
| 教師 | 提示 | 正式名・整理・答え合わせ |
| 生徒 | 提案 | 自発的な素朴案 |
| 生徒 | **質問** | 生徒から教師への問い返し。主導権が生徒に渡る |
| 生徒 | **誤答** | 素朴な誤答・的外れな断定 |
| 生徒 | **逡巡** | 迷い、言い淀み、保留、答えられない |
| 生徒 | **単純正答** | 摩擦を経ずに正解を返す |
| 生徒 | 検算 | 手計算・具体例での検査 |
| 生徒 | 診断 | なぜ失敗したかの言語化 |
| 生徒 | 修正 | 案の作り直し |
| 共通 | 情動 / 脱線 | |

`{unit_id: [ラベル, ...]}` の JSON にして渡す。ターン数と要素数は一致させる。

```bash
python3 scripts/yaruo_beat_repetition.py docs/books/<id>/README.md --beats beats.json --units
```

## 指標と、最も避けたい型

| 指標 | 定義 |
|---|---|
| 指示率 | 指示 ÷（指示＋問い） |
| 単純正答率 | 単純正答 ÷ 全ビート |
| 苦労率 | （誤答＋逡巡＋摩擦）÷ 全ビート |
| 生徒主導率 | （提案＋質問）÷ 全ビート |
| 指示→単純正答 | 「指示 or 問い」の直後に「単純正答」が来る隣接ペア数 |

**生徒の問い返しを逡巡へ寄せない。** 「どうすればいいんだお」と会話を動かすのは良い兆候で、
答えられずに詰まる逡巡とは別物。混ぜると苦労率が水増しされる。

**「教師が指示し、やる夫が一発で正解する」が最も避けたい型。** 再発見が成立しておらず、
知識の羅列に落ちている。同型反復とは独立の欠陥なので、`instruction-and-plain-answer` として
別立てで出す（1単位でも成立しうる）。

- **苦労率が 0 の区間が3単位以上続く**：観点3（L2 苦労の実在）の指摘にする。E3 ではない
- **ランに載らない単位も見る。** 3単位に満たなくても `no-struggle` などのマークが付いた単位は
  `*` 付きで一覧に出る。指示→単純正答は1単位でも成立するので、ランだけを見て済ませない
- **指示率が高い（問いより命令が多い）**：やる夫が探す側でなく作業する側になっている
- 誤答も逡巡も無い区間は、やる夫が**既に知っている**ことを述べているだけの疑いが強い

実例：`education` 第5幕は6節で苦労率 0.0、指示率 0.636、指示→単純正答 11組。
節末で教師自身が「全問正解にしといてやるよ」と言う。
逆に `rental-car-operations` 第10幕は、10-1・10-4 が誤答から始まり摩擦と診断を持つため落ちず、
`QAQAQAQAQA` の 10-3 だけが立つ。

## 校正されていない点（指摘票へ書くときの注意）

- **severity は未校正。** ラベル付きの事例が少なく、`bureaucracy` を手動 minor と判定した区間を
  検出器は critical と出す。**深さ・単位数・苦労率の生値を票に書き、severity 文字列を根拠にしない。**
- 意図的な溜め・静けさの可能性を全体文脈で判断する。**同型ビートN連続を自動不合格にしない。**
- 層2の記号列（`ASASAS…`）は証拠の要約であって証拠ではない。**票には必ず行番号と引用を書く。**
