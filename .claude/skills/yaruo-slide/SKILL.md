# やる夫教材スライド化

対話教材を、**物語を捨てて学習内容だけを残した marp スライド**へ変換する。出力は教材ディレクトリ直下の `slide.md` 一つだけ。

`scripts/generate_site.py` が `docs/books/{ID}/slide.md` を marp-cli で `build/books/{ID}/slide.html` にレンダリングし、教材ページ右上に「要約」リンクを出す。ファイル名と置き場所は変えない。

## 1. 対象と部を確定する

教材本体は分割されることがある。`docs/books/{ID}/README.md`（第1部）、`README.2.md`（第2部）、`README.3.md`（第3部）……の順で1つの教材を成す。

```bash
rg --files docs/books/{ID} | rg 'README'
```

- 本体が `README.md` だけなら、それを対象にする。
- 分割されているなら、**どの部をスライド化するかを必ずユーザーに確認してから着手する。** 各部の先頭 `# ` 見出し（例: `やる夫で学ぶ統計学 I ──…`）を選択肢として提示する。
- 選ばれた**一つの部だけ**を処理する。他の部の内容を混ぜない。
- 出力先は選んだ部によらず `docs/books/{ID}/slide.md`。既存の `slide.md` があるときは、中身を読んで何の部のスライドかを確認し、上書きしてよいかユーザーに確認する。

## 2. 落とすものと残すもの

**落とす**

- `## 登場人物` セクション全体。
- 話者表示行（`**やる夫**：`、`**やらない夫**（老いて）：` など。判定は `scripts/yaruo_markdown.py` の `SPEAKER_LINE` が正本）と、人物名・呼びかけ・相づち・感情表現。
- 情景描写、幕・場のドラマ、物語上の事件そのもの。
- 「なるほど」「つまりこういうことかお」のような、内容を進めない会話。

**残す**

- 概念の定義、成立条件、前提、例外。
- 数式とその導出。**数学・物理系の導出は途中式を省略しない。** 1枚に収まらなければ導出だけで複数枚に割ってよい。
- 数値例・具体例のうち、概念の理解に必要なもの（登場人物の名前は外し、匿名の事例として書く）。
- 表、比較、手順、判断基準。
- 誤解しやすい点（教材が「間違いから正す」形で扱った箇所は、正しい結論と、なぜ誤りやすいかを一行で）。

会話文はそのまま引用せず、**説明文・箇条書きに書き換える**。教材の学習順序は保つ。

## 3. 分量と粒度

- 原則 **1節（`###` 見出し）につきスライド1枚**に圧縮する。
- 短い節、同じ論点を分担している連続した節は、まとめて1枚にする。
- 例外は数式の導出で、ここだけは枚数を使ってよい。
- 1枚は、見出し1行 + 本文6〜10行程度を上限の目安とする。ただし箇条書きの1項目が長く折り返す場合や数式を含む行は、生のMarkdown行数以上に縦を食う。行数を数えるだけで安全とみなさず、5節の画像確認で必ず実測する。
- 溢れるなら削るか、導出でない限りは節の統合をやめて内容を絞る。「理由が2つ」「手順が3段階」のような列挙は、それだけで1枚に独立させることをためらわない。
- 幕（`##`）の切り替わりには、幕題だけの区切りスライドを置く。

## 4. 書式

先頭の front-matter は次を既定とする。

```markdown
---
marp: true
theme: default
paginate: true
size: 4:3
math: katex
style: |
  svg[data-marpit-svg] {
    height: auto;
    width: 100%;
    aspect-ratio: 960 / 720;
    display: block;
    margin-bottom: 12px;
  }
  section {
    font-size: 22px;
  }
---
```

`style` は必須。サイト側の要約表示エリアは16:9ではない（`scripts/site_template.html` の `#slide-frame`）ため、これを付けないと各スライドが表示領域いっぱいに引き伸ばされ、本来の16:9枠の上下に大きな黒帯が生まれる。スライド間の間隔（`margin-bottom`）もここで決める。表示側（`scripts/generate_site.py`・`site_template.html`）はスライドの中身やレイアウトを一切調整しない。

- スライドは `---` で区切る。
- 各スライドの先頭は `## 見出し`（表紙のみ `# `）。表紙には教材タイトル（と部の名前）を置く。
- 数式は教材と同じ `$...$` / `$$...$$` をそのまま使う。KaTeX が解釈できない独自マクロは書かない。
- 画像・外部フォントなど、リポジトリ外のリソースを参照しない。
- 箇条書きは1階層まで。長文の段落は置かない。

## 5. ビルドで確認する

書いたら必ずレンダリングを通す。

```bash
npx --yes @marp-team/marp-cli@4 docs/books/{ID}/slide.md -o /tmp/slide-check.html --html --allow-local-files --template bare
```

サイト全体まで確認するなら次を実行する（marp-cli が失敗するとビルドが落ちる）。

```bash
python3 scripts/generate_site.py
```

確認する点:

- marp-cli がエラーなく終了する。
- 数式が KaTeX でレンダリングされ、生の TeX が残っていない。
- **はみ出しを画像で実測する。** 行数の目算はあてにならない（列挙項目の折り返しや数式で簡単に超える）。次のように全スライドを画像化し、Read ツールで1枚ずつ目視する。本文がスライド下端の枠を割っていたら、その節を分割する。

```bash
npx --yes @marp-team/marp-cli@4 docs/books/{ID}/slide.md -o /tmp/slide-check.png --images png --allow-local-files
```

## 6. 完了時に報告する

- スライド化した部（ファイル名と部のタイトル）
- 総スライド枚数
- 意図的に落とした内容のうち、学習上の判断を含むもの
