# rental-car-operations：統合改訂プラン

行番号は 2026-09-23 時点の本文。v1＝`docs/books/rental-car-operations/README.md`、v2＝`docs/books/rental-car-operations-v2/README.md`。

## 1. 方針

- **前提読者と前提知識**：事務・店舗・情報システムのどれかで業務を回した経験がある社会人と、その予備軍。Excel の表と四則演算、確率の掛け算（$0.9^4$ 程度）までを前提にする。データベース・統計・機械学習の知識は求めない。
- **中心の問い（catalog の question 案）**：「一番速い人が何でも片づけている会社で、業務改善と自動化を担う組織（CoE）を立ち上げても、なぜ現場は良くならないのか。仕事を代わりに引き受けずに、会社の業務を変え続けるにはどうするのか。」
- **plot 案**：ホライゾンレンタカーで一番速い事務担当のやる夫が、新設の改善組織の室長に抜擢される。与えられた猶予は半年。一月の取締役会で成果がなければ、室は解散され、外部コンサルが提案する基幹一括更改と事務委託へ切り替わる。最大の法人顧客の離反、整備保留車の貸出未遂、室に殺到する240件の依頼、忙しすぎるエンジニア、AI全社導入の号令を越えて、年末年始の大雪と連携障害の日に、室が現場から手を引けるかが試される。
- **扱う範囲**：v1 の学習内容（業務の端・タッチタイムとリードタイム・引継ぎと正本・粒度とID・履歴・レギュラーとイレギュラー・WIP・失敗学・FMEA・対策の強さ・BPR/ECRS・承認のリスク分類・プロセスオーナー・自動化の梯子と TCO・市民開発・AI の評価と統制・変更管理・運用負債・指標・運営リズム・CoE の設計と測定）に、v2 の道具（状態の直交分解・二つの時刻と出所・冪等性・ピットレーンのボトルネック・禁止遷移・損傷の証拠と分類・料金イベント・時間窓と利用可能在庫・過剰予約の裾と相関・回復手段の束・時間展開ネットワーク・縮退レベル・AI の情報境界と評価集合）を、CoE が受ける案件として載せる。
- **土台**：構成は新しく組む（著者の決定）。学習の骨格と実話は v1、案件の具体・数値例・時間の圧力の作り方は v2 から取る。v1 の「一件の請求事故を追う」筋も v2 の「一台を24時間で貸す」筋も主題にせず、**「室を半年で立ち上げ、取締役会で存続を勝ち取る」ことを主筋**にする。v2 の24時間は終幕の一日に縮めて使う。
- **目標分量**：本文 約70,000字（v1 は付録込み約90,000字、v2 は約52,000字）、付録（業務設計のパターン）約6,000字。第0幕〜第10幕と終幕・エピローグの12単位、各幕4〜7節。v1 の「対話演習」5本と「幕間　業務事故の博物館」は独立させず、実話は該当する幕の案件へ分散する。

**v2 の装置が果たしていた役割の置き換え**

- 「一台を読む(n)」「業務を読む(n)」の累積適用 → 次の案件が前の幕の失敗の余波として室に持ち込まれる形にする。室の **依頼の受け方** 自体が、Slack の DM → `#なんでも相談` → 80項目のフォーム → 段階的トリアージと、失敗から形を変えて育つ（装置ではなく育つ枠）。

## 3. 設定と人物

- **舞台**：ホライゾンレンタカー。県内外に数十店舗を持つ中堅。試行地区は **空港店・駅前店・郊外店** の三店舗（車は各数台〜十数台）。本社の法人車両運用チーム、会計、エンジニア部門。最大の法人顧客は **北斗フーズ**（営業車12台、食品卸で年末が繁忙）。
- **時間の枠**：7月末の発足から翌年1月の取締役会まで約半年。
  - 第0〜2幕：7月末〜8月（発足、北斗フーズの請求事故）
  - 第3〜4幕：8月下旬〜9月上旬（社長への中間報告、整備保留車の貸出未遂）
  - 第5幕：9月（北斗フーズ更新まで30日）→ 結果は「年末の運用を見て決める3か月の暫定更新」
  - 第6〜7幕：10〜11月（室の渋滞と再建、自動化）
  - 第8〜10幕：12月（AI 号令、年末の配車準備）
  - 終幕：12月30日夕〜31日（大雪と連携障害）、1月の取締役会前夜と翌朝
- **対抗案**：外部コンサルの「基幹一括更改と事務委託」案（5年総額約14億円、事務チームの大半を委託先へ）。社長と一部役員が支持。人物としては出さず、やる夫・できる夫の台詞で伝える。
- **やる夫**：法人車両運用チームで一番速い事務担当。Excel とマクロに強い。**一番速いという理由で室長に抜擢される**。欲：肩書・社長賞・銅像（繰り返しのギャグとして保つ）、室を「全社の難問を解く帝国」にしたい。弱点：自分で片づけたがる、良い数字だけ報告したがる、社長の期待に弱い。成長：第6幕で室が自分への依存で詰まる姿を見て帝国を捨て、終幕では **大雪の日に店舗の電話と鍵を取り上げない** ことを選ぶ。最後も欲は残る（エピローグで銅像を申請しかける）。
- **やらない夫**：元店舗責任者で、現在は事故調査の担当。室へ **兼務** で出される。肩書を嫌い、室長の椅子を断っている。教え方の持ち味：失敗を安全な範囲でやらせる（80項目フォームにあえて乗る）、帰結を数字で見せる、現場へ連れ出す、やる夫の着眼を認める。**正体**：8年前に社内で作られ2年で消えた「業務改革推進室」の室長だった。室は依頼を中央で抱え込み、自分が英雄として燃え尽き、任命した12人の改善チャンピオンは繁忙期に2人しか動かず、最後は全部緑の報告書で延命して解散した。第6幕2節で明かす。

### 第0幕　一番速い男が室長になる（7月31日〜8月1日）

**0-1　返した車が、まだ走っている**
- 出来事：北斗フーズから怒りの電話。CAR-0427 が返却済み・貸出中・課金中の四つの現実に割れる。やる夫は10分で直して社長賞を狙う。押し忘れた担当者を犯人にしかけ、延長を受けたのが自分で、Slack のスタンプの意味が決まっていないことに気づく。
- 学ぶこと：食い違いは一人の注意不足ではなく、仕事のつながり（電話・Slack・夜間取込・締め）の時刻の噛み合わせから生まれる。
- 流用元：v1:31-106 を改稿。日付を直す（§6）。v1:98-106 の総括を削る。
- 伏線：Slack スタンプ（第1幕で回収）。夜間取込の時刻（第2幕）。
- 終わり方：調べている最中に社長室から呼び出しが来る。

**0-2　室長やる夫と、兼務の男**
- 出来事（新規）：経営会議で改善組織（CoE）の新設が決まり、「一番速いから」やる夫が室長に。半年後の取締役会で成果がなければ一括更改と事務委託へ切り替える、と条件付き。やる夫は帝国を夢見て、四システムの CSV を集める万能マクロを宣言する。やらない夫は事故調査から兼務で出され、室長の椅子を断る。倉庫を片付けると「業務改革推進室」の古い表札が出てきて、やらない夫は即座に「捨てとけ」と言う。

- 流用元：v1:109-194 改稿（モナーを「隣の席の同僚」に、L185 のボトルネックの先取りを削る）。社長・対抗案・表札は新規。

- 終わり方：翌朝、宮本（北斗フーズ）からのメールをやる夫が読み上げる。「九月の更新で他社と比較します」。室の最初の案件が決まる。
