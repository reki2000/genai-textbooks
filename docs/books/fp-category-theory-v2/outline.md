# やる夫が消えた三分間を射で追うようです ── 五つの時刻表から圏論を再発見する の新アウトライン

## 再設計の方針

旧版のモナド解読と、物の所在を追う配送劇を捨てる。五つのAPIをつないだ共同配送で、20時17分から三分間だけ確保した路上予約R-17が、全サービスの成功ログにもかかわらず現地表示から消え、別車両と二重予約になる同期障害へ置き換える。地図アプリ開発者やる夫は本番切替を守りたい。市の形式監査人やらない夫は道路を危険な状態で開けない。上下関係のない対立当事者が、同じ光る時刻線と短い型付きコードを調べ、対象より関係、値より変換、個別テストより合成則を見る必要から圏論を導く。

## 第1幕　全部成功したのに三分間がない

- 地図、配車、道路予約、通知、課金は全て成功だが、20:17になるはずの路側灯だけ点かず、別車両も同じ区画へ向かう。
- 各サービスの内部DBを全部読む案を、権限、異なる表現、更新時刻、切替期限で棄却する。
- 入力と出力がつながる変換だけを白板へ書き、予約処理を矢印の列として扱う。
- 同じ時刻がUTC、地方時、営業日内分、三分スロットIDへ変わることを確認する。
- 光る時刻線R-17、三拍メトロノーム、二本の変換経路を全編の手掛かりとして置く。

## 第2幕　矢印をつなぐ最低条件

- 対象、射、始域、終域、合成、恒等射を時刻変換と区域変換から再発見する。
- 型が合わない射はつながらず、何もしない処理と「元へ戻す処理」を同一視する案を合否例で壊す。
- 三処理の括り方を変えてログが違う不具合から、結合律を実行順の交換ではないと明確にする。
- 小さなTypeScriptコードで、純粋変換と時刻取得・書込みの外部効果を分けてテストする。
- R-17の型はつながるのに、区域先行と時刻先行の結果が一致しない非可換な四角形を発見する。

## 第3幕　同じ青信号へ行く二本の道

- 住所から道路区画を出す直行経路と、座標・行政区を経由する経路の出力が一日だけ違う例を作る。
- 可換図式を飾りでなく「別手順でも同じ予約判断になる」という統合契約として読む。
- 同じ対象を別の射で結ぶことと、同じ射を別名で呼ぶことを区別する。
- 同型を完全な同一視とせず、往復が恒等になる構造保存変換として検査する。
- R-17は旧区域IDから新区域IDへ変わった深夜境界で、二本の経路が可換でなくなったと絞る。

## 第4幕　時刻表全体を写す

- 旧予約スキーマと新予約スキーマの二圏を作り、対象だけ写す移行表が合成を壊す反例を置く。
- 恒等射と合成を保つ関手を、型と関数、DB表とクエリ、道路網と所要時間の例で導く。
- `map`を値へ小細工する俗な比喩から外し、図式の射を整合的に写す操作として読む。
- 二つの移行関手の間を一様に変換する自然変換と自然性の四角形を、地方時補正で作る。
- R-17だけ例外分岐で直したパッチが一様でなく、自然性を壊して翌日の枠を二重化したと分かる。

## 第5幕　条件が交わる一点を作る

- 車両情報と走行計画の積を、単なるペアでなく二つの射を同時に受ける普遍性から特徴づける。
- 昼便／夜便の余積、終対象、始対象、等化子、引戻しを小さな予約要求で作る。
- 「全条件を書き込んだ巨大レコード」を、他の候補から一意に因子化できないことで棄却する。
- pullbackを走行計画IDと道路許可時間の整合照合へ使い、通常のDB結合との関係と違いを示す。
- R-17が点灯できる条件を、区域適格性と空き時間の引戻しとして再構成する。

## 第6幕　自由な経路と実行可能な経路

- 生の道路断片から合成可能な経路式を自由に作る操作と、意味を忘れて基礎グラフへ戻す操作を比べる。
- 随伴を、個別の便利関数でなく二つのHom集合の自然な対応として、カリー化と自由モノイドで確かめる。
- unitとcounitを経路式の生成・評価へ対応させ、三角恒等式を小例で検算する。
- 随伴からモナドが生じる経路を示し、`flatMap`を失敗・ログを伴う予約処理の合成へ置く。
- R-17の再試行をResult/Writer風の文脈でつなぎ、失敗した時刻情報を上書きせず残す。

## 第7幕　外から来る矢印が三分間を語る

- R-17の内部レコードを全開示する案を、五サービスが別管理主体であることと、同じ値でも振舞いが違う反例で壊す。
- ある対象への／からの全ての射の振舞いで対象を調べる発想から米田の補題へ進む。
- 代表可能関手と自然変換の対応を、小さな有限圏で表にして手計算する。
- 極限・余極限を、図式全体を最も普遍的にまとめる円錐として第5幕の積・引戻しへ接続する。
- 「内部を見ずに分かる」を、観測可能な全インターフェースとの関係で同一視できる、という範囲へ限定する。

## 第8幕　図式を本番の信号規則にする

- 修正案を個別のif文、中央変換層、版付き自然変換の三案で比較する。
- 可換性、合成則、単位律をプロパティテストにし、反例を自動縮小する。
- 副作用、部分関数、時間、並行処理は素朴なSet圏の外へ出るため、Kleisli圏や豊穣化への境界を示す。
- 圏論が性能や安全を自動で保証しないこと、良い抽象にも移行・監視コストがあることを明記する。
- R-17の例外パッチを一様な変換へ置換し、旧日付と新日付の二経路が可換になり、二重予約が消えるまで検収する。

## 終幕　二十時十七分の青信号

- 20:17、R-17の三分間だけ路側灯が青く点き、予定した車両が停止して時間どおり消灯する。
- やる夫はモナドを比喩一語で片づける癖を卒業し、どの対象、射、合成、保存則、普遍性を使ったかで説明する。
- 三拍メトロノームは成功音でなく、どの括り方でも同じ合成になることを確かめる試験音になる。
- 次の課題は復路R-18。やる夫が矢印を逆向きにする前に「逆射があるとは限らない」と手を止めて閉じる。

## 依存と検算

- R-17の旧／新区域ID、地方時、営業日境界、道路区画、点灯時刻を固定する。
- 非可換四角形は第2幕で発見、第3幕で診断、第4幕で自然性、第8幕で自動検査へ育てる。
- 三分間の光は第1幕で消失、第5幕で条件の交点、第8幕と終幕で正確な点灯へ回収する。
- 三拍は第2幕の合成、第6幕の文脈付き合成、終幕の法則検査へ意味を変える。
- 各抽象は少なくとも一つの有限圏、型付きコード、予約時刻例の三者で照合する。
