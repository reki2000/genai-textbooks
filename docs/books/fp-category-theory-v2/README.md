# やる夫が消えた三分間を射で追うようです ── 五つの時刻表から圏論を再発見する

---
## 登場人物

**やる夫** ── 共同配送用の地図アプリを作った独立開発者。

**やらない夫** ── 市の路上利用を監査する形式手法研究者。

**できる子** ── 共同配送の運行指令員。

**できる夫** ── 統合事業の広報担当。

**R-17** ── 新区域B-07の路上を20:17〜20:20だけ利用する予約関係。

!> コードとサービス構成は学習用の仮想例です。圏論的な法則が成立しても、性能、可用性、情報セキュリティ、現場安全が自動的に保証されるわけではありません。

**やらない夫**：
20:17へ3を足すと20:20になるが、枠406へ3を足すと枠409だ。

## 第2幕　矢印をつなぐ最低条件

---
### 2-1　型が合う矢印だけ

**やる夫**：
対象を`Address, Coord, Zone, Slot, Signal`と置くお。
射（morphism）$f:A\to B$は型Aから型Bへの変換だお。

**やらない夫**：
$f:A\to B$と$g:B\to C$をつなげ。

**やる夫**：
合成$g\circ f:A\to C$で、先に$f$、次に$g$だお。
終域Bと次の始域Bが一致しない射はつながらないお。

```ts
type Address = { text: string }
type Coord = { lat: number; lon: number }
type Zone = { id: string; version: number }

const geocode = (a: Address): Coord => ({ lat: 35.0, lon: 139.0 })
const zoneAt = (c: Coord): Zone => ({ id: "B-07", version: 2 })
const addressToZone = (a: Address): Zone => zoneAt(geocode(a))
```

**やる夫**：
`zoneAt(address)`は型不一致で拒まれる。
型検査は全ての意味的誤りを捕まえないけれど、つながらない矢印は実行前に落とせるお。

**やらない夫**：
何もしない恒等射（identity morphism）$1_A:A\to A$も要る。

**やる夫**：
$f\circ1_A=f$、$1_B\circ f=f$だお。
「元へ戻す処理」は情報を失えば恒等射じゃないお。

---
### 2-2　三拍をどこで括る

**やる夫**：
三処理$f:A\to B,g:B\to C,h:C\to D$は、左から実行すればいいお。

**やらない夫**：
括り方を比べろ。

**やる夫**：

$$h\circ(g\circ f)=(h\circ g)\circ f$$

**やる夫**：
これが結合律（associativity）だお。
実行順$f,g,h$を交換する法則ではなく、同じ順序の括り方を変えても同じ射になる法則だお。

**やらない夫**：
三拍目が現在時刻を読み直す処理なら。

**やる夫**：
純粋な射でなく外部効果が混じり、括り方や再試行時刻でログが変わるお。
時刻を入力として明示するお。

```ts
type Context = { nowMinute: number; zoneVersion: number }
const slotOf = (ctx: Context, startMinute: number): number =>
  Math.floor(startMinute / 3) + 1
```

**やる夫**：
第四拍を足して安全確認した気になるお！

**やらない夫**：
余計な処理は恒等射じゃねぇよ。

---
### 2-3　五対象の合成表

**やる夫**：
有限圏（finite category）カードにA=`Address`、C=`Coord`、Z=`Zone`、T=`Slot`、S=`Signal`を置くお。
射は$g:A\to C,z:C\to Z,q:Z\to T,ℓ:T\to S$と恒等射だお。

**やらない夫**：
合成で新しい射も閉じている必要がある。

**やる夫**：
$z\circ g:A\to Z$、$q\circ z:C\to T$、$\ell\circ q:Z\to S$、さらに全合成$\ell\circ q\circ z\circ g:A\to S$が要るお。

**やる夫**：
カード15本には、生成射4本だけでなく必要な合成射6本と5恒等射を含めるお。
合成した結果が圏の射集合から外れたら閉じていないお。

**やらない夫**：
三拍$z,g,q$の括りを実値で試せ。

**やる夫**：
住所`中央1`を$g$で座標`(35,139)`、$z$でB-07、$q$で406へ写すお。
$q\circ(z\circ g)$でも$(q\circ z)\circ g$でも406だお。

**やらない夫**：
$q$と$z$を交換したら。

**やる夫**：
$q$はZone始域だからCoordへ作用できず型不一致だお。
結合律は順序交換可能性じゃないことを、合成表自体が示すお。

**やる夫**：
三拍目に外部時計読取を混ぜた旧処理は、同じ入力カードでも違う射になっていた。
`Context`を対象へ含めて初めて表へ固定できるお。

## 第3幕　同じ青信号へ行く二本の道

---
### 3-1　可換でない四角形

**やる夫**：
始点を予約要求$R$、終点を点灯命令$S$にするお。
上経路は区域更新$u$の後に枠化$s$、下経路は枠化$t$の後に区域更新$v$だお。

**やらない夫**：
可換条件を式にしろ。

**やる夫**：

$$s\circ u=v\circ t$$

**やる夫**：
これは「通勤できる図」じゃないお。
二つの手順が全ての対象予約で同じ点灯判断へ着く統合契約だお。

**やる夫**：
R-17では上が`(B-07,406)`、下が`(A-12,406)`だから非可換だお。
成功HTTP応答は射が返っただけで、二合成の等しさを検査していなかったお。

**できる子**：
区域表の版切替は20:00。
直行キャッシュだけ版1のままです。

**やる夫**：
非可換な最小反例がR-17だお。
右下の光跡のずれが障害位置を表していたお。

---
### 3-2　同型は同一ではない

**やる夫**：
A-12をB-07と同じ名前だと宣言すれば直るお。

**やらない夫**：
名前替えで道路規則が保存されるか。

**やる夫**：
対象AとBが同型（isomorphic）とは、$f:A\to B$と$g:B\to A$があり、$g\circ f=1_A$、$f\circ g=1_B$になることだお。

**やる夫**：
旧A-12は夜間積卸可、新B-07は20:00以降予約必須。
旧へ戻すと予約必須情報を失うから、往復は恒等にならないお。

**やらない夫**：
つまり版1と版2は同じ道路付近を指しても、予約構造として同型ではない。

**やる夫**：
同じ対象を別の射で結ぶことと、同じ射へ別名を付けることも違うお。
R-17だけ旧IDを残す名前パッチでは構造保存を証明できないお。

---
### 3-3　往復できる有限例

**やる夫**：
同型の合格例も手で作るお。
24時間表Hと1,440分表Mを考えるお。

**やる夫**：
$f:H\to M$を$f(h,m)=60h+m$、$g:M\to H$を商と余りで$g(n)=(\lfloor n/60\rfloor,n\bmod60)$とするお。

**やらない夫**：
範囲を忘れるな。

**やる夫**：
$0\le h<24,0\le m<60,0\le n<1{,}440$だお。
$g(f(20,17))=(20,17)$、$f(g(1{,}217))=1{,}217$で往復が恒等だお。

**やらない夫**：
文字列`20:17`との往復は。

**やる夫**：
`8:05`と`08:05`のような複数表記を許すと、整形後に元文字列へ戻らないお。
意味上の時刻とは同型でも、未正規化文字列全体とは同型でないお。

**やらない夫**：
A-12とB-07も同じ道路座標へ写るだけでは不十分だな。

**やる夫**：
許可規則を含む射が往復で恒等か検査する。
位置の同一と予約構造の同型を区別するお。

**やる夫**：
同型なら実装表現を交換できる場面があるが、性能や権限まで同じとは限らないお。

## 第4幕　時刻表全体を写す

---
### 4-1　対象表だけでは移行できない

**やる夫**：
旧圏$\mathcal C$の対象A-12を、新圏$\mathcal D$のB-07へ写す表を作ったお。

**やらない夫**：
対象だけでなく射をどう写す。

**やる夫**：
関手（functor）$F:\mathcal C\to\mathcal D$は対象と射を写し、二法則を守るお。

$$F(1_A)=1_{F(A)}$$

$$F(g\circ f)=F(g)\circ F(f)$$

**やる夫**：
旧系で`zone -> permit -> signal`が合成できるなら、新系でも対応する射が同じ順序で合成できる必要があるお。

**やらない夫**：
`map`だから道路地図を拡大するのか。

**やる夫**：
そのギャグはやる夫の担当だお！
関手は値一個への小細工でなく、圏全体の合成構造を整合的に写すお。

---
### 4-2　二つの移行を一様に比べる

**やる夫**：
区域先行関手$F$と時刻先行関手$G$を、R-17だけif文で合わせるお。

**やらない夫**：
翌日のR-18ではどうなる。

**やる夫**：
例外条件がR-17のIDに固定され、別予約で四角形がまた壊れるお。

**やる夫**：
各対象Aに射$\eta_A:F(A)\to G(A)$を置き、全ての$f:A\to B$で自然性を要求するお。

$$G(f)\circ\eta_A=\eta_B\circ F(f)$$

**やる夫**：
これが自然変換（natural transformation）だお。
区域、時刻、許可、信号の各成分が同じ移行方針でつながるお。

**できる子**：
R-17個別パッチは当日を直しましたが、翌日の同時刻枠を二重化しました。

**やる夫**：
一点の成功で一様性を代用したのが失敗だお。
版付き$\eta$を全対象へ適用し、自然性の四角形をテストするお。

---
### 4-3　自然性をR-17へ代入する

**やる夫**：
自然性の式を文字だけで終わらせず、$f$を`zoneToSlot`へするお。
$F(Zone)=A-12@v1$、$G(Zone)=B-07@v2$だお。

**やる夫**：
$\eta_{Zone}$は旧区域を版付き新区域へ移し、$\eta_{Slot}$は旧枠キーを新枠キーへ移すお。

**やらない夫**：
二経路を順に言え。

**やる夫**：
左辺$G(f)\circ\eta_{Zone}$は、A-12をB-07へ移してから新規則で枠406を得る。
右辺$\eta_{Slot}\circ F(f)$は、旧規則で得た旧枠406を版付き新枠406へ移すお。

**できる子**：
R-17では両方`B-07@v2#406`。
境界前19:59では両方`A-12@v1#400`です。

**やる夫**：
R-17だけ返り値をB-07へ変えたパッチは$\eta_{Zone}$しかなく、$\eta_{Slot}$や許可成分がない。
だから別射の四角形で壊れるお。

**やらない夫**：
自然変換は全対象へ同じ関数を使うという意味か。

**やる夫**：
成分$\eta_A$は対象ごとに型が違ってよい。
重要なのは全射$f$に対し自然性が成立し、移行が構造と一様に両立することだお。

**やる夫**：
有限圏カードの全15射を列挙できるから、今回は自然性を全件検査できるお。

---
### 4-4　温度表示で壊れる「同じ換算」

**やる夫**：
道路以外なら、自然変換は摂氏から華氏への換算みたいなものだお。
どの温度にも$F(c)=1.8c+32$を掛ければ一様だお。

**やらない夫**：
それだけでは自然変換の例にならない。
関手と、自然性を試す射を先に出せ。

**やる夫**：
有限圏を二対象`Morning`, `Noon`と射`warm: Morning -> Noon`にするお。
摂氏観測関手Cと華氏観測関手Hがあり、成分$\eta_{Morning},\eta_{Noon}$を$c\mapsto1.8c+32$にするお。

**やらない夫**：
朝10 ℃、正午20 ℃として、二経路を数値で比べろ。

**やる夫**：
先に摂氏で10 ℃上げてから換算すると$1.8\times20+32=68$ °Fだお。
先に50 °Fへ換算して華氏で18 °F上げても$50+18=68$ °Fだお。
だから$H(warm)\circ\eta_{Morning}=\eta_{Noon}\circ C(warm)$だお。

**やらない夫**：
華氏側も10だけ上げたら。

**やる夫**：
右経路は60 °F、左経路は68 °Fで壊れるお。
各成分が正しく見えても、射の意味を保存しなければ自然でないお。

**やらない夫**：
ではR-17の版移行も、区域IDの変換表だけでは足りないな。

**やる夫**：
区域の更新に対応する枠・許可・点灯側の射まで同じ四角形で検査するお。
自然性は「同じコードを使った」ではなく、「どちらの順に変換しても観測結果が一致した」だお。

---
### 4-5　R-17を読む(4)

**やる夫**：
旧新スキーマは関手で写し、二移行の差は自然変換で結ぶお。
R-17例外でなく全射の合成保存を検査するお。

**やらない夫**：
だが点灯には区域と時刻の両条件が同時に要る。

## 第5幕　条件が交わる一点を作る

---
### 5-1　巨大レコードより普遍性

**やる夫**：
車両、運転者、区域、枠、許可、課金を全部持つ巨大レコードを正解にするお。

**やらない夫**：
後から監査要求Xが来たとき、その全項目を埋めないと使えないのか。

**やる夫**：
欲しい関係より内部表現を固定しすぎるお。
車両Vと計画Pの積（product）$V\times P$は、射影$\pi_V,\pi_P$を持ち、任意のXから$f:X\to V,g:X\to P$があれば一意な$\langle f,g\rangle:X\to V\times P$がある対象だお。

$$\pi_V\circ\langle f,g\rangle=f,\qquad\pi_P\circ\langle f,g\rangle=g$$

**やる夫**：
「ペアっぽい」ではなく、二情報を同時に受ける全候補から一意に因子化できる普遍性（universal property）で特徴づけるお。

**やらない夫**：
昼便か夜便かなら。

**やる夫**：
余積（coproduct）$D+N$で、どちら由来かを入射とともに保存するお。
単なる文字列結合で出自を消さないお。

---
### 5-2　許可時刻の引戻し

**やる夫**：
点灯条件は区域適格ならtrue、空き枠ならtrueを別々に返せば十分だお。

**やらない夫**：
同じ許可キーについてのtrueか。

**やる夫**：
区域適格$Z\to K$と空き時間$T\to K$が同じキーKへ写る組だけを取る引戻し（pullback）が要るお。

$$Z\times_KT=\{(z,t)\mid p(z)=q(t)\}$$

**やる夫**：
R-17では区域側キー`B-07@v2`、時間側が旧`A-12@v1`だから一致せず、点灯対象が存在しないお。
課金は注文成功だけ見ていたから始まったお。

**やらない夫**：
DBの内部結合と同じか。

**やる夫**：
Setの有限例では等値結合として実装できる。
でも圏論の定義は特定DBでなく、任意候補Xからの整合する二射が一意に引戻しへ因子化することだお。

**できる子**：
版付き変換後は両キー`B-07@v2`、枠406。
点灯候補が一つです。

---
### 5-3　四候補から一組だけ残す

**やる夫**：
積を作ってから条件で絞れば、引戻しもただのフィルタだお。

**やらない夫**：

**やる夫**：

**やる夫**：

### 6-2　失敗時刻を潰さない合成

```ts
type Trace<A> = { result: { ok: true; value: A } | { ok: false; error: string }; log: string[] }

const flatMap = <A, B>(x: Trace<A>, f: (a: A) => Trace<B>): Trace<B> =>
  x.result.ok ? (() => { const y = f(x.result.value); return { result: y.result, log: [...x.log, ...y.log] } })()
              : { result: x.result, log: x.log }
```

**やる夫**：

**やらない夫**：

**やる夫**：
モナドは単なる副作用ラベルじゃないお。
型構成子とunitと合成法則を持つ構造で、この例では失敗とログを保つお。
