# 寸評：やる夫が圏論チョットワカルかもしれません

約151KB／全8幕。「モナドは自己関手の圏のモノイド対象」というジョークを出発点に、Goの集計バッチ障害からモノイド・関手・自然変換・クライスリ圏を再発明し、呪文を自力で復元する教材。

## 良い点

**「結合法則＋単位元」をカウンタとして全体に埋め込んだ構造が強い。** 489–491行目でやらない夫が「この2点セットは姿を変えてあと3回現れる。現れるたびに数えろ」と予告し、実際に 924行目（Writerのログ）、1103–1107行目（圏の公理）、1598–1600行目（モナド則）で、やる夫自身が「2回目」「3回目」「4回目」と数え上げる。読者に能動的な照合作業をさせる仕掛けで、幕をまたぐ長距離の緊張を作れている。同種の教材が「あとで効いてくる」と言うだけで終わりがちなのに対し、ここは回収が機械的に検証可能な形になっている。

**理論の必要性が、常に「壊れたコード」から立ち上がる。** 引き算 `[10,3,2]` の並列化で逐次 −15 と並列 −11 が食い違い（147–159行目）、平均で分割位置により 2.25 と 1.75 に割れる（169–173行目）。ここからやる夫が自力で「並列化がやっているのは括弧の付け替え」（183行目）→ 結合法則、空チャンク → 単位元（197–203行目）に到達する。抽象概念の導入としてこれ以上具体的な入口はない。

**「型は同じだが法則を破る実装」を2つ用意し、やる夫に自分で殺させた。** EvilMap（1293–1301行目）は正規の Map と型シグネチャが区別できないが `EvilMap(xs, id)` が恒等にならない。CheatHead（1416–1428行目）は型パラメータで総称に見えて中で `probe.(int)` と型を覗き、経路A/Bが Some("0") と Some("10") に割れる（1434–1438行目）。関手則と自然性が「機械的に検査できる等式」（1454行目）であることを、合格例と不合格例の両方で体感させている。

**「箱」アナロジーの検死が徹底している。** まず箱説がうまくいく範囲を公平に確認させ（772–777行目）、次に Reader で「この箱のどこに int が入っている?」と問い、やる夫に「中身が未来にしかない」（798行目）と言わせる。決定打は `rr(env)(env)` の env 二重配布（815–819行目）で、「箱の中の箱を潰す絵からは絶対に出てこない」と自分で判定させる。モナドチュートリアルの誤謬[^6]を、説教ではなく反例で示した点が良い。

**「対象か射かは役割であって属性ではない」に長い尺を割いた。** 1166–1235行目の約70行が、やる夫の「整数 0,1,2,3 はどこ行ったんだお?」という混乱の解消に費やされ、`(Int, String)` は対象2個かという追加の誤解（1191–1200行目）まで潰し、最後に表（1225–1228行目）でまとめる。学習者が実際に転ぶ場所を知っていて、そこに意図的に時間を使っている。

**モナド則が「バラバラの3つのルール」から「圏の公理」に化ける瞬間の作り方。** Fish を書かせ（1516–1523行目）、圏の合成の資格条件を番号付きで列挙させ（1544–1548行目）、恒等射の候補が Some だと発見させ（1559行目）、モナド3法則と並べて書かせる（1569–1571行目）。そこで「バラバラの3つじゃなかった」（1577行目）→「失敗するかもしれない関数たちの世界は、圏になる」（1582行目）。第3幕で貼った付箋（745–749行目）の回収としても正確。

**参考文献23点が本文の該当箇所に脚注で付いている。** 一次文献（Wadler 1989、Moggi 1991、Meijer 1991、Swierstra 2008、McBride & Paterson 2008、Plotkin & Pretnar 2009、Huet 1997）を挙げ、解説としてWikipediaを添える形式（3061–3083行目）。Go側も Type Parameters Proposal の「No higher-level abstraction」節を根拠に挙げており（3067行目）、4-3の高階型の壁の主張が裏取りされている。

## 欠点

**第7幕・第8幕で再発見が完全に止まり、全体の4割が講義になる。** 2277行目で「再発明のサイクルはもう回さない」と作者自身が宣言しているが、結果として 1765–2905行目の約1140行が、ほぼ全節「痛みの提示 → やらない夫が道具を出す → やる夫が『〜だったんだお』と感心する」の同型反復になる。8-1から8-9まで9節連続で同じリズムで、第1〜6幕で作った「素朴案が死ぬ」緊張が消える。教材の主張（呪文は自分で作れる）を最も体現している前半に対し、後半は普通の解説記事と区別がつかない。

**クライマックスでやる夫が最も強い。** 1152–1155行目で「対象1個の圏＝(Z,+,0) のモノイド」を独力で発見、1628–1651行目で自己関手の圏を構成した上に関手合成が結合法則＋単位元を持つことまで自力で到達、1664–1675行目ではモノイド対象の部品（join と pure）を「第2幕のモノイドの部品を思い出せ」という一言だけの誘導で全部翻訳しきる。第2幕の並列化バグでは3往復かけて詰まらせたのに、教材で最も非自明な翻訳作業が一発正解になっている。ここは跳躍の妥当性が読者に判定できない。

**Writer の3法則がモノイド則から導かれることを「宿題でいい」で捨てている。** 971行目。だがこれは「モノイドとモナド、何か血縁関係がある」（976行目）という教材の主題そのものであり、しかも 6-2 でモノイド対象へ至る道の最初の一歩でもある。角括弧ログで結合法則の破れを検算させた（933–938行目）直後なのだから、同じ手つきで正しい側も5〜10行で確認させられたはず。

**コードが1箇所壊れている。** 2014行目 `Success mkUser <*> Success 30日目...` は、無関係な文字列「30日目」が混入していて Haskell として読めない。しかもアプリカティブの最重要例（エラー蓄積）の直前で、読者が最も注意して読む箇所。あわせて 2004行目で `Validation [Error] User` を出しながら、Validation が Applicative ではあっても Monad ではない（則を満たせない）という肝は触れられておらず、「階級を1段下げる」（2921行目）話の核心が抜けている。

**幕内自己参照が複数ある。** 311行目「第2幕の FoldPar に『畳む前に各要素を変換する』を足しただけだ」、379行目「max も min もモノイド（第2幕で見た）」は、いずれも第2幕（107–498行目）の内部での発言。幕を後から分割・統合した痕跡で、読者は該当箇所を探して戻ることになる。

**第2幕の目玉道具の実装が省略されている。** 315–318行目の `FoldMapPar` は本体が `...` で、「骨格は FoldPar と同じ」とコメントされているだけ。FoldPar は wg.Add から Wait まで全部書いた（234–254行目）のに、以降の全ての集計例（平均・範囲・分散・最頻値）が依存する関数が空になっている。しかも 2093行目で「第2幕の `FoldMapPar` の正体」として Foldable と再接続されるので、中身が見えない状態が最後まで残る。

**物語的な圧力が一切ない。** 登場人物2名、舞台なし、期限なし、利害関係なし。第1幕の動機は「勉強会で笑えなかったのが悔しい」（19行目）で、以降は純粋な問答が3000行続く。同リポジトリの thermodynamics 教材が持つ「横断幕を刷ってしまった」「あと3日」のような外部圧に相当するものがなく、やる夫が途中で降りない理由が本人の意欲だけに支えられている。8-10の卒業試験（2907–2952行目）は良い装置だが、これも試験のための試験で、失敗しても何も起きない。

**やる夫の発言の正しさを検証する外部が存在しない。** 判定は常にやらない夫が「合格だ」「完璧な発見だ」と言うことで確定する。三重リストの検算（1691–1704行目）のように、やる夫が自分で計算して自分で合致を確認する箇所はあるが、都合の悪い結果を突きつけてくる第三者（thermodynamics のできる子に相当する役）がいないため、後半は「やる夫が言う→やらない夫が褒める」の往復に見える場面が増える。

## 改善案

1. **2014行目のコード破損を修正し、Validation が Monad になれない理由を1往復入れる。** 破損行を `mkUser <$> Success "yaruo" <*> Failure [...] <*> Failure [...]` の形に直した上で、その直後に「じゃあ Validation を Monad にすればいいのでは?」とやる夫に言わせ、`>>=` を定義しようとすると前の失敗を見てから次を決める以上エラーを蓄積できず、Applicative則とMonad則の整合が崩れることを気づかせる。2921行目の「弱い階級を選ぶとできることが増える」が標語から実感になる。

2. **6-2 のモノイド対象への翻訳で、やる夫を一度間違えさせる。** 1664行目の直前に、やる夫が矢印の向きを取り違える往復を1つ挟む（例：「単位元は T から Id への矢印だお」→ やらない夫「それだと Option[A] → A になるが、None のときに何を返す」→ 詰まる → 向きが逆だと自分で気づく）。この誤りは 8-7 のコモナド（2764–2772行目）の伏線としてもそのまま効き、「矢印を逆にすると鏡の国になる」の予告になる。教材で最も重要な翻訳が一発正解である現状は、いちばん惜しい省略。

3. **971行目の「宿題」を本文に戻す。** Writer の左単位元則 `PureW(a) >>= f = f a` がログの `"" + w = w` に、結合法則が `(w1+w2)+w3 = w1+(w2+w3)` に対応することを、やる夫に3法則それぞれ1行ずつ対応づけさせる。930–951行目で破れる側は既に検算済みなので、成立する側を同じ粒度で書けば対称になり、976行目の「血縁関係がある」が推測から確認に変わる。

4. **第8幕に再発見を1つだけ残す。** 現状で唯一その形になっているのは 8-7 のコモナド（「pure と join の矢印を逆向きにしたら何になる」2764–2769行目）で、これが成功している。同じ型を 8-5 のレンズに適用し、2663行目の van Laarhoven 表現を天下りで出す代わりに、「view と set の両方を1つの型で表したい。`f` を差し替えて両方に化けさせるにはどんな型か」と問うて、Const と Identity をやる夫に選ばせる。第8幕全体を再発見に戻す必要はなく、1節あれば読者のリズムが復活する。

5. **物語的圧力を第1幕と第8幕に薄く1本通す。** 6行目の人物紹介の後に「来月の社内勉強会で『モナドを一言で説明する』LTをやると宣言してしまった」を1〜2行で置き、8-10の卒業試験（2907–2952行目）を「その本番前日の最終確認」に読み替える。追加は10行未満で済み、3000行を走り切る動機が「悔しい」以外に1本増える。

6. **幕内自己参照を直す。** 311行目と 379行目の「第2幕」を「さっき」「この幕の前半」等に修正する。あわせて 315–318行目の `FoldMapPar` の本体を FoldPar と同じ粒度で埋める（10行程度）。以降の5つの集計例と 2093行目の Foldable 回収が、実物のコードに接続される。

7. **第8幕の観光を圧縮し、その分を第7幕に回す。** 8-1〜8-9 の各節は「痛み→道具→感心」で構造が同型なので、8-3（Tagless Final）と 8-4（代数的効果）は 8-1 の続きとして統合できる。削った分を 7-3 のアプリカティブと 7-4 の Traversable に回し、`sequenceA` の再帰定義（2075–2077行目）をやらない夫が示すのではなく、やる夫に `[Maybe a]` の2要素の場合から手で組み立てさせる。第7幕は「降りて歩く」（1773行目）と宣言している幕なので、そこに手を動かす時間を集中させる方が宣言と整合する。
