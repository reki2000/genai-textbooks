# やる夫が圏論チョットワカルかもしれません ── モナドの正体をたどる の骨格

社内業務システムをGoで書くやる夫が、勉強会の呪文「モナドは自己関手の圏のモノイド対象にすぎない」に笑えず、翌月の社内LT「モナドを一言で説明する」を登録。マクレーン『圏論の基礎』は1ページ目で死亡（Grp・Top の実例が読めない）。やらない夫の方針「数学書から降りるのでなくお前のコードから登る」。目標1＝識者の用語についていける地図、目標2＝FPに必要な範囲の国境線。並行して、4月1日付の組織改編（営業1課・2課→第一営業部、営業3課→第二営業部）で社員マスタの部署コード切替と、切替朝6時の「新しい上司のお知らせ」通知バッチを担当。障害対応と移行作業の中で圏論の概念を一個ずつ再発明し、切替の夜を越え、LTの後にマクレーンの1ページ目へ戻る。

人物：やる夫（Go プログラマ、Haskell はモナドの章で挫折、数学は群論の初歩）／やらない夫（同チームの先輩、FP と数学の両方）／できる子（運用担当でコードレビューも担う、Go は for とゼロ値で書く派、夜中に呼び出される側、リハーサルの差分表と切替判定を持つ）。

## 第1幕　呪文と轟沈
- 呪文のジョークの出どころ（2009年パロディ、架空のワドラー、中身はマクレーンの本物の定理）。1ページ目で死んだ理由＝実例の在庫と梯子の規格の違い。map・flatMap・reduce はお前が毎日触る実例。目標1・2と「呪文を自分の言葉で復元し1ページ目に戻る」約束。組織改編と通知バッチ、「移行が一晩で終わる前提の日程」。行程表は三つの疑問符（自己関手・モノイド対象・圏）。

## 第2幕　並列化が壊れる日 ── モノイド
- 再集計バッチを4分割 goroutine で並列化「どんな Fold も同じ手で分割できる」→在庫引き落とし（引き算）で−15が−11、平均は分割位置で2.25と1.75＝並列化は括弧の付け替え→結合法則、空チャンクで単位元、群から逆元を抜いてモノイド。混ぜたら戻せない演算は仕事で群より多い。Go の `Monoid` インターフェース、型は形を検査するが法則は検査しない。判定表（+・×・連結・append 合格、−・平均不合格、max は単位元なしで保留）。append は何も忘れないモノイド（8-2 で回収）。max の救済に「値がない」を足す＝Maybe はモノイドの単位元を製造する装置。
- 不合格の演算を「並列化不能」で済ませるか→答えでなく十分な材料をモノイドで畳む：型1 後処理送り（出庫を+で畳んで最後に引く）、型2 累算器を太らせる（平均＝(合計,個数)）、型3 ペア（範囲＝(最小,最大)、単位元は±∞）、型4 モーメント（分散＝(Σx²,Σx,n)）、型5 ヒストグラム（最頻値）。中央値は小さなモノイドに落ちない国境。`FoldMapPar`＝MapReduce の心臓部＝`foldMap`。「結合法則＋単位元の2点セットはまた出てくる、数えておけ」。

## 第3幕　nilの荒野 ── mapとflatMapの再発明
- BossEmail（社員→上司→メール、3段の nil チェック、先月の panic でできる子が夜中に呼び出された）。できる子のゼロ値案→「上司はいるがメール未登録」と「社員がいない」が同じ "" に潰れ、int の有休残0日とデータ欠落も区別できない、できる子「ないを型で持つ案ならレビューは私が見る」。`Option[T]`、ok チェックピラミッドに変わっただけ→`MapOpt`、GetBoss を Map すると `Option[Option[Employee]]`（失敗しない関数用の道具に失敗しうる関数を渡した）→Flatten→FlatMap、3段が1行。Result、部下の部下を辿るスライスの FlatMap。同じ映画を何度も見せられる。付箋：観察1（Map の2回がけと合成1回が一致）・観察2（モノイドが並列集計を支える）・観察3（FlatMap の連鎖は括り方によらないらしい、未証明）。GetBoss と GetEmail は包装1枚分型がずれるのに数珠つなぎになる＝「何を合成しているのか」（6-1 で回収）。

## 第4幕　モナドの泥沼 ── アナロジーの死とGoの限界
- 4-1　「モナドは箱」説は Option とスライスは説明できる→組織改編で GetBoss の中で `time.Now()` を見て表を切り替えたらテストが日付で落ちる、基準日を全関数に手渡しするバケツリレー→Reader（Go ではただの関数型）、`Reader[int]` の int はどこにもなく中身は未来にしかない。箱の絵で Flatten を予測できない→`rr(env)(env)`＝外側と内側に同じ基準日と組織の版を配る約束、3月31日23:59:59に走り出して上司は旧組織・メールは新組織から引く事故を起こさない（5-4・8-5 の伏線）。モナドチュートリアルの誤謬。
- 4-2　監査ログを値として返す Writer を自作、手でログをつなぐ地獄→FlatMap の仕事。PureW のログは無意識に "" を選ばされていた＝単位元、`+` の括り方も結合法則＝2点セット2回目、Writer が動く条件はログ型がモノイド。角括弧で包む非モノイド結合で「括り直しリファクタ」をするとログが [[find,boss],email] と [find,[boss,email]] に割れる＝読み飛ばしたモナド則はこのリファクタの保証。左右単位元則・結合法則を式で示し、Writer では3本ともログのモノイド則からそのまま導かれることを照合。モノイドとモナドの血縁（第6幕まで保留）。
- 4-3　FlatMap を3回書いた→共通インターフェースの `???` が書けない＝型を食べて型を返す型を渡せない、高階型。Go の限界と Haskell に乗り換える地点、`class Monad m` の m、`sequence`・`mapM`。LT の題名を「モナドは型コンストラクタと return と bind と3法則」に。

## 第5幕　道具の構築 ── 圏・関手・自然変換
- 5-1　ZF を心配→対象の中身は見ない、性質は矢印に語らせる。型と関数から部品（入出力型・合成・恒等関数）を挙げ、法則（結合・単位元）を足して圏の5行定義。判定1 型と関数の圏（Hask）。判定2 対象1個・射＝整数・合成＝足し算＝(ℤ,+,0)＝モノイドは1対象の圏、2点セット3回目。「整数はどこへ行った、対象か」の混乱→整数は射、対象も射も圏の中での役割、(Int,String) は Hask の1個の対象、多対象の Hask では端が合うときだけ合成、値は圏によって射にも対象未満にもなる（表）。群は1対象で全射可逆、亜群。判定3 引き算は二重に不合格。圏＝合成がまともにできる世界の設計基準。
- 5-2　Option は対象の対応だけでなく射も写す（MapOpt）→型が同じ `EvilMap`（逆順にしてから Map）を法則で退ける：恒等は恒等へ、合成は合成へ＝関手、自己関手（呪文の3分の1）。観察1の回収＝Map 融合の許可証（GHC の融合変換）。法則をコメントでしか書けないのは Haskell も同じ、機械検証は Agda・Coq の国境の向こう。`testing/quick` でプロパティテスト（EvilMap は一発で赤）、第2幕の判定表を通すと avgMonoid が 1.7e308 で赤→0.1・0.2・0.3 で 0.6000000000000001 と 0.6＝float64 の + はモノイドでない（丸め）、対策は銭の整数・誤差許容比較・Kahan（結合法則は戻らない）。国境線1本目「法則は数学の値について成り立ち、機械の型が守るとは限らない」。
- 5-3　HeadOption はスライス→Option の乗り換え、経路A・B（先に乗り換えて Map か、先に Map して乗り換えか）が一致。型を覗く CheatHead（int なら0）で Some("0") と Some("10") に割れる＝自然性 $G(f)\circ\alpha=\alpha\circ F(f)$、自然変換。Haskell では裏口がないので自動的に自然＝パラメトリシティ（Theorems for free!、1989）。自然性は重い処理を後ろから前に動かす許可証（述語プッシュダウン）。
- 5-4　切替リハーサル（検証環境を4月1日0時に、単体テスト全部緑）で、できる子の抜き取り100人の差分表に42番（営業2課）だけ通知バッチ（第二営業部長）とポータル（第一営業部長）が食い違う、「このままでは切替を止める」→42番の if で空にする→翌朝別の100人で57番。番号でなく理由を見る：経路A（旧所属キャッシュ→変換表→新部署）と経路B（新人事API）、4-1 の二本の道が本物に。変換表の各行は実在の新部署を返す→摂氏と華氏（各行の換算は正しくても10℃上昇を10°F上昇と写すと60と68で割れる、矢印も写す）。所属について全1,200人を突き合わせると23人、全員営業2課、変換表の1行の打ち間違い、42番と57番はたまたま抜き取りに入った2人。できる子「全件突き合わせをリハーサルの手順に、空なら切替」、42番の if も消す。可換図式。社員・部署・事業部の小さな圏、旧組織と新組織の表はそこから集合の圏への関手、変換表は成分が対象ごとに違う自然変換、自然性の四角形は射ごとに一枚（上位の四角形は打ち間違いでも通る）。HeadOption はパラメトリシティでタダの保証があったが、変換表は中身を覗くので全件を数えて守る。「営業2課は第一営業部の別名」案→逆に戻れない、同型＝行って戻れる（社員番号 int と6桁ゼロ埋め文字列は範囲内で同型、手入力の "42" "042" とは同型でない）。1945年アイレンベルクとマクレーン、圏論は「自然」を定義したくて始まった。

## 第6幕　呪文の解読 ── クライスリ、そして自己関手の圏のモノイド対象
- 6-1　つなぎ方を Fish（`>=>`）として関数化、Fish を圏の合成と呼ぶ条件（合成・結合法則・恒等射）。恒等関数は型が合わず、Some（return）が恒等射→モナド3法則を並べると「return が恒等射」「Fish が合成」＝失敗しうる関数たちの世界は圏になる＝クライスリ圏。第3幕の付箋の回収（クライスリ圏の射を合成していた、世界を掛け替えれば矢印はまっすぐ）。2点セット4回目。角括弧 Writer もどきは圏が立たず、途中を括り出す基本動作が安全でなくなる＝モナド則を守れ＝世界を圏にしろ。
- 6-2　対象＝自己関手、射＝自然変換で自己関手の圏（呪文の第3語）。関手合成という別の掛け算、恒等関手が単位元＝2点セット5回目。第2幕のモノイド部品（Combine・Empty）を翻訳：単位元を `T ⇒ Id` と取り違え、`Option[A]→A` で None から値を捏造できないと気づき向きを直して `Id ⇒ T`（Some、return）、演算は `T∘T ⇒ T`＝第3幕の Flatten（join）。join と pure の結合法則・単位元則を三重リスト `[[[1,2],[3]],[[4]]]` で内側からと外側から検算。モノイド対象の定義、呪文を自分の言葉で読み上げる（定義を圧縮した略語、部品は全部自作）。LT の題名は呪文に一周して戻る。マクレーンの原文後半（積を関手合成に、単位を恒等関手に置き換えて）まで読めば種明かし、切り抜きの罪。bind と join は相互変換可能。歴史（ゴドマンの標準構成→モッジ1989〜91→ワドラー1992ごろ）。

## 第7幕　もう一歩進んだ道具箱 ── 教養装備を手に馴染ませる
- 切替まで5日、移行の残り仕事（社員種別、人事CSV、一括照会）の中で呪文の隣の道具を拾う。
- 7-1　積（struct）を普遍性で定義、余積（Either）は Go にない（2値返しと型 switch の運用カバー）、代数的データ型、Option は余積で Writer は積。値の数で積2×3=6、和2+3=5、Option は1+T。正社員と業務委託の番号を文字列一本にしたら同じ "17" に潰れる＝タグを外すと往復できない（5-4 の合併と同じ）→Either で持つ。終対象 `()` と始対象 `Void`＝積と余積の単位元（同型を除いて）。
- 7-2　値の階段（半群⊂モノイド⊂群、max は半群、「Semigroup で十分」は要求をゆるめる倹約）と文脈の階段（関手⊂アプリカティブ⊂モナド）。カインド（`*`、`* -> *`）、「Kind が合ってない」は一段上の型検査。newtype で Sum・Product・Any・All・Min・Max・First・Last を包み分ける。
- 7-3　人事CSVの行検証を `>>=` でつなぐと最初のエラーで打ち切られ、人事部と3往復→独立な検証は `<$>`・`<*>` のアプリカティブで全部走らせ、エラーはリスト連結というモノイドで合流。Validation を Monad に昇格させると蓄積 Applicative と整合しない。リストのアプリカティブは直積（クロス結合）。独立なら中段、前を見るなら上段。
- 7-4　移行対象の社員番号を全部引いて1件でも引けなければ切替中止＝`[Maybe a]` を `Maybe [a]` にひっくり返す＝traverse・sequenceA、2要素から `(:)` と `<*>` で自作して再帰に。join は同じ層を潰し traverse は違う層を入れ替える。Foldable は第2幕の FoldMapPar の正体。
- 7-5　do 記法は `>>=` の砂糖、BossEmail の do 版、リストモナドと内包表記・guard、実体はクライスリ圏の射の合成。
- 7-6　State（Reader・Writer と中身が関数の三兄弟）、Go のスタック電卓のバケツリレーが消える。4-1 の基準日手渡しは読むだけなので Reader、書き換えもするなら State。
- 7-7　カリー化＝ $\mathrm{Hom}(A\times B,C)\cong\mathrm{Hom}(A,B\to C)$＝随伴、7-1 の積が片側に。同型は対象どうし、随伴は矢印の集合どうしが行って戻れる。State の `s -> (a, s)` に随伴の両側が並ぶ、随伴からモナドが生まれる。「〜随伴を添えて」「フレンチのメニューか」。切替は明日の夜、ドライランと戻し方が未定。

## 第8幕　切替の夜 ── 移行バッチを本番に流す
- 8-1　21時。状態・失敗・IO を同時に→手書きの case の山→モナドトランスフォーマー、MTL で lift 梯子を隠す。積む順で失敗時に状態が巻き戻るかが逆。「失敗したら変換表を逆に引いて書き戻す」→合併は往復できない（5-4）、逆引き表は作れない→戻す先を覚えておく、StateT を外に積んで写しごと消す、ただし監査ログは失敗で消えない階に＝トランザクション境界と同じ判断。モナド同士の合成がモナドにならない理由は join の真ん中の入れ替え（6-2 の join が牙を剥く）。
- 8-2　22時。ドライランで通知件数だけ数えたい（本当に送ると一足早く全社員に届く）→Free で命令を木として書き、runIO と dryRun の二つの解釈器（42番・88番は各1件、総務は0件）。Free は法則が要求する以外の等式を課さない＝第2幕の何も忘れない append と同じ、同じ通知を2回書けば2つ残る、決めるのは解釈器。「同じ人に2回 notify を書くバグなんて書かないお」「そうだといいがな」（8-6 で回収）。Go の interface 差し替え＝Tagless Final の素朴版＝DI。トレードオフ（覗けるデータか、速い関数か）、代数的効果とハンドラ（Koka、OCaml 5、polysemy、effectful、Plotkin と Pretnar）は今夜は渡らない橋。
- 8-3　23時。第一営業部長のメールを共有アドレスへ、不変データの奥だけ書き換える写経地獄→レンズを `.` で合成、Optics は圏をなす。Lens（積）・Prism（余積、社員種別の Either の片側）・Traversal。van Laarhoven 表現で `Identity` なら setter、`Const` なら getter＝関手だけで組み上がる、Traversal は Applicative に格上げ。
- 8-4　23時45分。切替前後で組織図の総人数を確かめる、部署ツリーの再帰→土台関手と `Fix` と `cata`（countAlg と chartAlg、旧新とも1,200人の検算）、ana、*Bananas, Lenses, Envelopes and Barbed Wire*。配下人数を各部署に書き込む＝周りを見て自分を決める＝コモナドの `extend`（Rule 90、ライフゲーム、画像のぼかし、スプレッドシート）。組織図エディタのカーソルは Zipper（Huet 1997）、コモナドの実例。
- 8-5　0時3分、移行完了エラーなし。できる子：通知の下ごしらえで社員表と部署表を結合すると第一営業部の人が全員消える。社員表は0時に新コード、部署キャッシュの更新は毎晩3時でまだ旧組織＝4-1 の二本の道。第二営業部は営業3課の1030を引き継いだのでたまたまつながる、第一営業部の1100には相手がいない。「結合しなければいい、巨大な一枚の表を」→42番の行に営業2課と第一営業部長が同居する矛盾行を表は黙って受け取る。2×2の組の表で一致は1組、88番の相手は古い名前の行。引戻し $E\times_K D$＝内部結合、フィルタではなく普遍性で決まる（候補M は条件違反、候補N は通知済み旗で矢印が2本）、極限（積も終対象も引戻しも同じ作り方）。キャッシュを新しい版で引き直す＝4-1 の Reader と同じ約束、4組中2組、第一営業部が戻る。米田の補題を小さな圏で（部署から出ていく矢印への自然な答え方と部署の1行が1対1、共変と反変の区別、同じ振る舞いなら同型までで同一とは言えない＝社員番号の int と文字列）。
