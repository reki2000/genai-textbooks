# やる夫の4K動画がカクつくようです ── 圧縮を再発明する の骨格

やる夫は回線25Mbpsの自称高画質マニア。**やらない夫は「動画の中に住む古参の技術者」**という設定で、自分自身も圧縮された映像なので**やる夫の回線が細るとやらない夫の画質が落ちる**（第1幕で「お前が見ているおれは480倍に圧縮されたおれだ、なのにお前は気づかない」と自分を教材にし、終幕でも回線が細って画質が落ちながら退場する）。

**動機は第1幕の数値**：生4K60は $3840\times2160\times3\times60\times8\approx$ **12Gbps**、回線25Mbpsとの差が**480倍**。480pに落としても590Mbpsで回線の24倍＝解像度を下げるだけでは解けない。

**保留が2本**、第2幕で明示的に置かれる：
- **保留(1) 人間の目に見えず耳に聞こえない情報とは具体的に何か** → 第3幕（目の穴＝高周波と色）と第5幕（耳の穴＝マスキング）で回収、さらに **7-2 のVMAFで「知覚モデルを機械学習で丸ごと作る」という一段深い回収**
- **保留(2) なぜ技術的に一番優れたものが勝つとは限らないのか** → 第6幕の特許・ライセンス戦争で回収

**倍率の掛け算**が全編の背骨：色差×2、DCT+量子化+エントロピー×10、動き補償+I/P/B×10、仕上げ×1.5〜2 ＝ 300〜400倍。**6-1 でこの積が「4K60の800倍には足りない」と判明し、fpsを混ぜていた誤りをやる夫自身が発見する**のが山場のひとつ。

## 第1幕　生（なま）の映像は運べない
- 12Gbps対25Mbps＝480倍。解像度を落とす案も、zip（無損失）案も潰れる。やらない夫の**「なぜ zip は縮むのか、どこまで縮むのか、限界はあるのか」**が第2幕への導線。**「圧縮の戦争は数式ではなく金と特許で決着した」**と第6幕を予告。

## 第2幕　ズルの余地はどこにある
- 2-1　ランレングス符号化から**冗長性＝予測がつくところには送る情報がない**。「完全にランダムな砂嵐は1ビットも縮まない」。
- 2-2　A70%/B15%/C10%/D5%で可変長符号（A=`0`,B=`10`,C=`110`,D=`111`）の平均1.45ビットを計算させ、**エントロピー $H=-\sum p_i\log_2 p_i=1.32$ ビット**が底だと示す（シャノンの情報源符号化定理）。**無損失では自然画像でせいぜい2〜3倍**。
- 2-3　**「無損失という枷を外せ」**。やる夫が「画質を落とすなんて」と抵抗するのを、**やらない夫自身が480分の1に圧縮されているのに気づかれていない**という事実で崩す。**損失符号化＝「人間の知覚の穴を正確に突く」**。ここで保留(1)(2)が置かれる。

## 第3幕　目のいい加減さを使う ── 静止画の圧縮
- 3-1　$[100,100,100,200,200,100,100,100]$ でDPCM（隣との差分）。自然画像では完全一致は稀だが「隣とだいたい同じ」は成り立つ。**差分にすると0だらけになりエントロピーが下がる**が、まだ無損失。
- 3-2　**「どの数字が目に見えない情報か、指させるか」→指させない**ので姿を変える＝DCT。平坦な行はDC成分だけになる**エネルギー集中**。**「DCT自体は1ビットも縮めない可逆な着替えだが、着替えた後は『どれが目に見えない情報か』を指させるようになった」**。
- 3-3　グラデーション（低周波）と極細市松（高周波）を同じだけ荒らす思考実験から**目の穴その1＝人間は高い空間周波数の精度に鈍い**。量子化を具体値で（DC 400/16は誤差0、中周波47.3/16で誤差0.7、高周波3.1/40は**0になって消える**）。**「捨てる工程（量子化）と縮める工程（エントロピー符号化）が分かれている」**。破綻はブロックノイズ。
- 3-4　**目の穴その2＝色の解像度には鈍い**。4:2:0で3面が1.5面＝**タダ同然で2倍**。ただし**輝度が一定で色差だけ急変する絵（黒地の赤文字、字幕やイラストの縁）では色のにじみが見える＝穴にも縁がある**。
- 3-5　JPEGの5工程が組み上がり**写真1枚が約10分の1**、色差と合わせて約20倍。「まだ480には遠いが無損失の壁は完全に破った」。
- 3-6　**DCTブロックとMCUの混同を解く節**。4:2:0の16×16領域にY 4ブロック＋Cb 1＋Cr 1＝**6個の8×8 DCTブロック＝1 MCU**。図とサンプリング別の表（4:4:4は8×8、4:2:2は16×8、4:2:0は16×16）で**「8×8は変換の単位、16×16は覆う範囲で、両方とも正しかった」**。ただし1成分だけのグレースケールや別スキャンもあるので丸暗記するなという限定つき。端の埋め草が「画素数1/4ならファイルも1/4にならない理由の一つ」。
- 3-7　**係数がビット列になるまで**。ゼロ1個に8ビット払う素朴案を潰し、**DC差分＋カテゴリー（SIZE）＋追加ビット**と**AC の RUN/SIZE**、**EOB**、**ZRL**。実際のビット列 `01111 0100 111001 1010` まで連結して**「`0x02`や`0x21`はファイルに書く1バイトではなくハフマン表を引くための記号」**と念押し。**ジグザグ順は飾りでなく「ゼロを長い尻尾に集めるための走査順」**。
- 3-8　**16進ダンプでJPEGファイルを読む**。主要マーカー表、**SOI/EOI/RSTには長さがない**こと、長さは「長さフィールド自身を含みマーカーを含まない」ビッグエンディアン。SOF0を分解して `01 22 00` の上位・下位ニブルから**4:2:0の16×16 MCUをバイト列から再発見**する。SOS以降は可変長ビット詰めなので**バイトスタッフィング（`FF`→`FF 00`）**が要る。締めは画素からファイルまでの7段の流れ。

## 第4幕　時間はほとんど止まっている ── 動画の圧縮
- 4-1　フレーム間差分を、**ボールが1画素動いただけで−100と+100のスパイクが出る**、カメラがパンすれば全画素に差分が出る、という反例で潰す。原因は**「同じ場所の画素と引き算したこと」**。
- 4-2　**動き補償**。動きベクトル(+1,0)を伝えてからずらして引くと重なる範囲の残差がゼロ。**やる夫が自分で「右へずらしたら左端に対応相手がない」と気づく**（動き補償がゼロにできるのは参照画像と重なる範囲だけ）。ブロックマッチング。**「探すのはエンコーダだけ、デコーダはずらして足すだけ＝エンコードは重く再生は軽いという非対称」**（6-8 の計算量の話へ）。
- 4-3　**I/P/Bフレーム**。最初のコマには前がないのでI、シークとエラー復帰の起点としてもI、そしてGOP。**Bフレームの必要性を「ドアの奥から人が出てきて初めて見えた壁は過去のコマに情報がない」という反例で導く**。送る順と表示順をずらす＝遅延が出る（7-1 の伏線）。生放送はBを控え、録画配信はBを増やす。時間方向で約10倍、画像20倍と掛けて**200倍**。
- 4-4　**「MPEG-2はMPEG-1の2倍縮む」を潰す節**。「その命名規則ならH.264はMPEG-2の132倍縮む」。**MPEG-2の本質は圧縮率でなくインターレース対応**（動きの速い映像をフレームのままDCTすると櫛状のずれで高周波だらけになる）＋Profile/Levelによる能力の宣言。7観点の比較表。
- 4-5　**MPEG Videoのstart codeを16進で読む**。`00 00 01 B3` などの表、Sequence Header直後の24ビットを12ビットずつ切って352×240を読み、**フィールドがバイト境界に揃っていない**ことを確認。MPEG-1とMPEG-2の見分けは`B5`拡張だが、**やる夫が「その後ろの`14 8A`をどう区切ればMPEG-2と断定できるか分からない」と正直に言い、やらない夫が「そこは推測させる場所ではない」と規格の定義を与える**のが特徴的。**「MPEG-2は別の箱を新築したのでなく、同じ入口・階層を残してB5拡張で増築した」**。
- 4-6　**コーデックとコンテナの分離**。`.ts` の先頭は `00 00 01` でなく**`47`（188バイトTS packet）**。PAT→PMT→映像PID→PES→Elementary Streamの入れ子図。**「MPEG-2 Video/H.262は画素の話、MPEG-2 Systems/H.222.0は運搬の話、`.ts`やMP4は外箱」**。

## 第5幕　耳のだましかた ── 音声の圧縮
- 5-1　CD品質PCMは約1.4Mbps、可逆では2倍が関の山。**「無音ではなく、ちゃんと鳴っているのに聞こえない音がある」**（ドリルの隣の蚊の羽音）。
- 5-2　**マスキング**（周波数方向と時間方向、前向き・後ろ向き）。**荒い模型で「何ビットまで削れるか」を数えさせる**：16ビットPCMのダイナミックレンジ96dB、閾値35dBなら守るのは61dB、1ビット≒6dBで**11ビット程度で足りる**。ただしやらない夫が**「これはフルスケールと音圧を対応させた説明用の概算で、『35dBなら常に11ビット』という規則ではない」**と限定する。
- 5-3　**やる夫が音声圧縮の5工程を自分で並べ、映像と骨格がそっくりだと気づく**（MDCT／臨界帯域／マスキング閾値／ビット割当／エントロピー符号化）＝**「映像は目の穴、音声は耳の穴を突く、同じ病気の別バージョン」**。1.4Mbpsが128kbpsへ。MP3/AAC/Opus、ステレオ2chの相関。**保留(1)の回収**（目の穴＝高周波の精度と色の解像度、耳の穴＝マスキング）。

## 第6幕　掛け算と規格戦争
- 6-1　**文化祭の配信係から「今夜までに4K動画を納品しろ、回線上限25Mbps、H.265とAV1のどちらか」という依頼が来て、やる夫が見る側から届ける側になる**。倍率を掛け算すると300〜400倍だが、**やる夫が「12Gbpsを400分の1にしても30〜40Mbpsで25Mbpsからはみ出す」「15Mbpsで配るなら800倍必要で計算が合わない」と自分で止まる**。やらない夫の指摘は**60fpsの生映像と24/30fpsの作品を混ぜてはいけない**（30fpsなら6Gbpsで400倍、24fpsなら4.8Gbpsで320倍）。残りの2〜2.7倍を道具箱で稼ぐ。**「独立な冗長性を突く工程は掛け算で効く」**。
- 6-2　**規格の家系図**（JPEG 1992／MPEG-1・2 1993-95／**H.263 1996＝低ビットレート会話という別の家系**／H.264 2003／H.265 2013／AV1 2018／H.266 2020）と、「次世代で約半分」は**特定のテスト条件での設計目標の目安**という限定。H.263のQCIF等の解像度とマクロブロック数の表、交渉可能なAnnex方式、そして**H.263のPicture Start Codeは22ビットでバイト境界に揃わない**＝「先頭が00だらけを見ただけで規格を決めつけるな」。
- 6-3　**「新しい規格ほどブロックは小さくなる」を潰す**。128×128の平坦領域を全部4×4にすると1024ブロックのヘッダが無駄、逆に一枚の大ブロックだと動きが合わない → **「平らな背景は大きく、境界付近だけ再帰的に細かく」**＝ブロック木。6規格の分割粒度の表。**「新世代は全部を小さくしたのでなく、選べる最大を大きくし、必要なら局所だけ小さくできる範囲を広げた」**。選択肢はタダでなく、**RDO $J = D + \lambda R$** で候補を試す＝**「圧縮率を上げるとは秘密のDCTを一個足す話ではなく、画質1点とビット1個の交換レートで最安を探すこと」**。
- 6-4　**H.263/H.264/H.265/AV1の道具箱の比較表**（画面内予測／画面間予測／変換／エントロピー／in-loop処理／並列化／ランダムアクセス）。動きベクトル精度（半画素→1/4→1/8）の必要性、複数参照の必要性（照明の点滅や人が横切ったフレームは参照に向かない）、**in-loopフィルタは見た目のためでなく「参照画像として保存する前に境界を整えて将来の残差も減らす」**。H.266の追加要素。最後に**「I/P/Bフレームという3文字をH.264以降へそのまま貼るのは粗い」**（sliceで記述、AV1のframe typeはKEY/INTER/INTRA_ONLY/SWITCH）＝**「名前より、どの復号済み画像を参照しどの順に復号・表示するかを見ろ」**。
- 6-5　**H.264をバイトで読む**。`00 00 00 01` と `00 00 01` の両方がstart code prefix。NAL header `67` を1/2/5ビットに割ってSPSと判定。**設計問題として「共通設定24バイト×120 slice＝2880バイトの繰り返し」を計算させてから SPS/PPS/VCL/SEI の分離に名前を与える**＝「用語を暗記する前に、繰り返しの2880バイトを見れば分離する理由が分かる」。**emulation prevention byte `00 00 03`** は JPEG の `FF 00` と**規則は違うが目的は同じ（payloadが境界記号を偽装するのを防ぐ）**。最後にMP4では**start codeでなく4バイトの長さ前置き**＝「コーデックが同じでも外側のフレーミングでバイト列が変わる」。
- 6-6　**H.265の2バイトNAL header**（6ビットtype＋6ビットlayer＋3ビットtemporal_id_plus1）。**VPSの必要性を「720p基本層と1080p追加層を合わせて一つの映像として扱う設定はどちらのSPSに置くか」という問いで導く**。VPS→SPS→PPS→sliceの階層。IRAP（IDR/BLA/CRA）とRASL。**「新しい規格ほど、絵を小さくする道具だけでなく、途中参加・時間階層・並列tile・パケット損失後の復帰というビット列を運用するための状態機械が厚くなる」**。
- 6-7　**AV1にはstart codeがない**。OBU headerの1バイトを割り、**LEB128**でサイズを計算（`BC 03` → $60+(3\ll7)=444$）。IVFコンテナ（`DKIF`/`AV01`、**little-endian**）まで読んで $2+12+447=461$ で検算。**6規格の境界発見・header・衝突回避の一覧表**と、**「バイト列を読むときは container → sample/PES → NAL/OBU → slice/tile → block のどの層にいるかを最初に確定しないといけない」**。
- 6-8　**保留(2)の回収**。コストは計算量（金で殴れる）と**特許**。H.264はMPEG-LAという一つの窓口で費用を見積もれたが、**HEVCは窓口が3つ以上に分裂し、一部は配信本数や収益にも課金すると言い出した**＝「いくら払えばいいのか誰に払えばいいのか分からない地雷原」。**やる夫が $C_{\text{total}}=C_{\text{encode}}+C_{\text{delivery}}+C_{\text{royalty}}+C_{\text{compatibility}}$ を立て、配信量20%減でも節約100万円を追加費用が超えれば圧縮率だけでは赤字**と数値化する（ただし実際の料率は時期・地域・契約で変わるので固定値を置く方が危険、という限定つき）。AOMediaとAV1、音声のOpusも同じ力学＝**「タダで誰でも使えることが、技術力と並ぶ武器になる」**。**文化祭の判断は「一番縮む方でなく、この視聴者へ今夜届けられる方」**。

## 第7幕　答え合わせ ── ネトフリはなぜ止まらない
- 7-1　15Mbpsに収めても**回線は時間で揺れる**（夜は8Mbpsに落ちる）。やる夫が**「止まるくらいなら画質を落として流し続けたい」→「1本を複数の画質で用意して、その都度選べばいい」**とABRを自力で言い当てる。**「画質が落ちるのは止まらないための映像側の踏ん張りだった」**。そして**4-3 の伏線が効く：各チャンクの頭をIフレームにしておくから別画質へ飛び移れる＝GOPの設計がチャンク切り替えの単位**。
- 7-2　**per-title／per-shot符号化**。「のっぺりしたアニメと爆発だらけのアクションに同じ15Mbpsを一律に割り当てるのは賢いか」。そして**「十分キレイを機械はどう判断するか」**に対し、単純な誤差（PSNR）を**3-3 の反例（のっぺり面のムラとザラザラの草むらでは同じ誤差でも気づき方が違う）**で否定し、**VMAF＝人間の主観を機械学習で再現するモノサシ**へ。**保留(1)の一段深い回収**＝「知覚の穴を突く技術が、ついに知覚のモデルを自動で学ぶところまで来た」。
- 7-3　**AIコーデック**（学習型、顔の動きだけ送って再合成、超解像）と、**次の規格戦争も「誰の特許か、タダで使えるか、どのチップで速く動くか」という経済の戦争になる**という見立て。
- 7-4　全行程の振り返り。**「やる夫が引っかかった場所が、全部そのまま技術の要所だった」**（同じ場所で引き算してはだめ→動き補償／どれが捨てていいか指させない→DCT／単純な誤差は人間とズレる→VMAF）。落ちは、やらない夫の画質が落ち始めて「続きはバッファが溜まってから」。

## 依存
- **やらない夫＝圧縮された映像**という設定が 第1幕（480倍に圧縮されたおれ）、2-3（枷を外す根拠）、終幕（回線が細って画質が落ちる）の3箇所で効く。単なる語り手にすると 2-3 の説得力が消える。
- **保留2本**は第2幕で明示的に置かれ、(1)は 3-3・3-4（目）→5-2（耳）→**7-2 のVMAF（知覚モデルの自動学習）**という3段回収、(2)は 6-8 で回収される。
- **倍率の掛け算**（×2／×10／×10／×1.5〜2）は 3-5（20倍）、4-3（200倍）、6-1（300〜400倍と800倍の食い違い）で3回集計される。**6-1 の「fpsを混ぜていた」という自己訂正**が本編の計算の山場なので、生データのfpsを変えると全部連動する。
- **境界記号の衝突回避**は JPEG の `FF 00`（3-8）と H.264/H.265 の `00 00 03`（6-5）で、**やる夫が「第3幕のJPEGと同じ衝突回避だ」と明示的に接続する**。AV1 は length-delimited で回避不要という対比（6-7）まで含めて三題噺。
- **「同じ骨格の別バージョン」という転移**が3回：3-1のDPCM→4-1のフレーム間差分（空間の隣→時間の隣）、第3幕の映像→5-3の音声、6-3のRDO→6-8の総コスト最小化。
- **やる夫が自分で反例を見つける／限界を言う場面**：4-2（左端に対応相手がない）、4-5（`14 8A`の区切りが分からない）、6-1（fpsの混同）、6-8（コストの式）。やらない夫が**「そこは推測させる場所ではない」**（4-5）と規格の定義を与える箇所があり、推論と規格知識の線引きが意識されている。
- **限定と留保が繰り返し付く**：3-4（4:2:0の色にじみ）、4-4（世代番号は倍率ではない）、5-2（説明用の概算）、6-1（各段は独立ではない）、6-2（「約半分」は特定条件での目標）、6-8（料率は時期・契約で変わる）。数値を書き換えるならこの留保も直す。
