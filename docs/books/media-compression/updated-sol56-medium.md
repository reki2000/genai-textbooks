# 改稿記録

`review-opus-medium.md` の指摘を軸に、本文の強みである「480倍の壁」と同じ画素列の再利用を残しつつ、数値の整合性、生徒の再発見、物語上の利害を補強した。

## 主な変更

- 12Gbps・25Mbps・15Mbpsを同じ基準で再計算した。4K60を回線へ入れる目標は480倍、15Mbpsへ入れる目標は800倍と分離し、300〜400倍は24/30fpsなら整合するが60fpsには不足すると明記した。
- 第6幕の冒頭で、やる夫に「今夜までに文化祭の4K動画の方式を選ぶ」という締切と当事者性を与え、6-8で端末対応・計算時間・ライセンスを含めて選択を回収した。
- 4-2の動き補償を「8画素すべてゼロ」から「重なる7画素がゼロ」へ修正し、参照範囲外、端の延長、有限の探索範囲に触れた。
- 第5幕に、約6dB/bitを使う説明用のマスキング計算を追加した。音圧とデジタルフルスケールを対応させた仮定であること、実コーデックの固定則ではないことも明示した。
- 6-5、6-6を用語の即答から設計問題へ変更した。設定を120 sliceへ反復する無駄を数えさせ、SPS/PPS分離と、複数層を束ねるVPSの必要性を反例から導いた。
- 条件と出典のなかったMPEG-1/2の11.1KB／11.5KB比較は削除し、比較には素材・画質・GOP・量子化条件・実装をそろえる必要がある、という再現可能性の論点へ置き換えた。
- ライセンス節には、配信費500万円・20%削減という仮定の損益計算と総費用の式を追加した。またAV1やVVCの優劣・普及について断定しすぎる表現を弱めた。

## 残した判断

- レビュー案はH.264/HEVCの実在する料率例を求めていたが、提供資料には時点・地域・契約区分を伴う根拠がない。数字を創作せず、条件つきの仮想計算で「圧縮率の差を総費用へ換算する」学習目的を満たした。
- バイト列読解の節は長いが、本文固有の強みであり、今回の根拠資料だけでは正確に縮約する境界を決めにくいため残した。その代わり、SPS/PPS/VPSの箇所では読解より設計上の必要性を先に置いた。
- lintのwarningは既存の節長・発言長・往復数に関する診断が中心で、内容上不可分な導出や既存構成に関わるため、errorのみを合否基準として判断した。
