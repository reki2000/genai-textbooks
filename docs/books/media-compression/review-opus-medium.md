# 寸評：やる夫の4K動画がカクつくようです ── 圧縮を再発明する

約100KB／全7幕。生4Kの12Gbpsと回線25Mbpsの「480倍の壁」を出発点に、エントロピー限界・JPEG・動き補償・音声マスキング・規格戦争までを一本の掛け算で通した教材。

## 良い点

**「480倍」という一つの数字が全編の背骨になっている。** 第1幕でやる夫自身が $3840\times2160\times3\times60$ から12Gbpsを出し、回線25Mbpsとの比で480倍を叩き出す（30–40行目）。以後この数字は、無損失2〜3倍では歯が立たない場面（223–225行目）、JPEGで20倍まで来た中間決算（509–512行目）、動画で200倍が見えた場面（1000–1001行目）、最終的な積の計算（1364–1375行目）と4回再登場する。抽象的な「圧縮は大事」を、毎回同じ一つの数字で殴り直す構造になっている。

**語り手の設定が主題そのものを体現している。** やらない夫は「動画の中に住む古参の技術者」で、自身が480倍に圧縮された映像である（8行目、79–82行目）。第2幕で損失符号化へ跳ぶ決定的な論拠が「480分の1に減らされたおれを見て、お前は普通に見えていると言った」（243–251行目）という自己言及であり、設定が装飾ではなく論証の材料として働いている。末尾で回線が細ってやらない夫の画質が落ちる（2152–2155行目）締めも、設定の使い切りとして良い。

**同じ8画素の1行を、幕をまたいで使い回している。** $[100,100,100,200,200,100,100,100]$ が、3-1の差分（295行目、312行目）、3-2の周波数分解（365–370行目）、4-1のフレーム間差分の破綻（839–851行目）、4-2の動き補償（878–891行目）で4回使われる。同じ数列で「差分は効く／動くと壊れる／ずらして引けば消える」を連続で体感させる設計は強い。

**バイト列まで降りる節が本物の検算になっている。** 3-7でDC差分とRUN/SIZEを実際のハフマンビット列 `01111 0100 111001 1010` まで組み立てさせ（666–673行目）、6-7でAV1のLEB128から `60 + (3<<7) = 444` を計算させ、IVFのフレーム長461バイトを $2+12+447$ で突き合わせる（1819–1855行目）。「規格は難しい」で終わらせず、実際に数が合うところまで持っていくのは他の教材にない厚みがある。

**保留を2本立てて、両方とも明示的に回収している。** 第2幕で「人間の目に見えない情報とは何か」（262–269行目）と「なぜ最良の技術が勝たないのか」（274–282行目）を保留し、前者は5-3末尾で「保留①、回収完了だ」（1346–1347行目）、後者は6-8で「保留②の回収だ」（1922–1923行目）と回収位置を明言する。さらに保留①は7-2のVMAFで「もう一段深いところで回収」（2073–2078行目）と二段構えになっており、伏線の設計が丁寧。

**参考文献が規格文書のURL付きで11点ある。** T.81、JFIF、11172-2、H.262、H.222.0、H.263、H.264、H.265、AV1仕様、H.266（2165–2175行目）。本文中の脚注参照位置も具体的で、16進ダンプの記述がどこに依拠しているかが追える。

## 欠点

**最終的な圧縮率の計算が、教材の看板である480倍と合っていない。** 6-1でやる夫は $2\times10\times10\times1.5 \approx 300\sim400$ 倍と出し「480に肉薄」と言う（1371–1374行目）。だが直後にやらない夫は「12Gbpsの生4Kが、15Mbps前後の実配信ビットレートに収まる」（1380行目）と述べる。12Gbps ÷ 15Mbps は800倍であり、300〜400倍では到底届かない。しかも「480倍」自体は回線25Mbpsに対する比で、配信ビットレートの比ではない。教材のクライマックスにあたる決算で、目標値・達成値・実配信値の3つが噛み合っていない。

**後半のやる夫が生徒ではなく解説者になっている。** 4-5で `14` の上位4ビットから「sequence_extension_id = 1」「`0x48`でMain Profile / Main Level」を即答し（1146–1153行目）、6-5でSPS/PPS/VCL/SEIの役割を一問で4項目列挙し（1664–1671行目）、6-6で「なぜHEVCはVPSを足したと思う」に対し「複数layerやsub-layer、operation pointをまとめる上位設定が要るからだお」と即答する（1746–1755行目）。これらは規格書を知らなければ出てこない答えで、ヒントもない。第2〜4幕前半の「素朴案→反例→修正」の型が、6幕ではほぼ消えている。

**分量の3割強がバイト列の読解に費やされ、再発見の教材としての比重が崩れている。** 3-6〜3-8（522–806行目）、4-5〜4-6（1087–1233行目）、6-5〜6-7（1624–1876行目）を合わせると約600行。内容自体は正確で面白いが、これらは「自分で組み立てる」ではなく「規格が決めたものを読み下す」節であり、やる夫が何かを企てて失敗する場面が一度もない。

**第5幕（音声）が映像に対して極端に薄い。** 5-1〜5-3で約110行（1238–1349行目）、映像側の1/8以下。しかもやる夫の手計算は 44100×16×2 = 1.4Mbps（1244–1246行目）の1回だけで、マスキング閾値の計算も、臨界帯域24という数字の根拠も、128kbpsという数字の内訳も一切与えられない。60dBの隣に35dB（1281–1283行目）という具体的な数字が出るのに、そこから何ビット削れるかをやる夫が数えない。映像側では量子化ステップで割って丸める計算（416–421行目）まで実演させているのと不揃い。

**MPEG-1とMPEG-2の実測値に出典がない。** 「約11.1KB、後者が約11.5KB」（1026行目）は4-4の結論を支える唯一の実測で、「世代番号は圧縮倍率ではない」という良い主張の根拠になっている。だが脚注が付いておらず、符号化条件（エンコーダ、量子化パラメータ、対象素材）も本文にない。他の11点が全て規格書で固めてあるだけに、ここだけ検証不能になっている。

**4-2の「全部ゼロ」が境界を無視している。** 前のコマを右に1画素ずらして引くと $[0,0,0,0,0,0,0,0]$ になる（887–889行目）と書いているが、右に1ずらせば左端の画素は前のコマに対応が無く、右端の画素は追い出される。8画素の閉じた行では厳密にはゼロにならない。「動き補償は劇的に効くが、参照の外へ出た画素は別途扱う必要がある」という現実の制約（画面外参照、パディング）が、ここで潰されている。

**物語的な圧力が存在しない。** 登場人物2名、期限なし、利害なし。第1幕のバッファリングという動機は良いが、第2幕から第6幕までの約1700行のあいだ、やる夫が困っている具体的状況は一度も戻ってこない（7-1でようやく回線25Mbpsが再登場する、1985–1994行目）。同リポジトリの熱力学教材における「横断幕を刷ってしまった／あと3日」に相当する駆動力がない。

## 改善案

1. **6-1の決算を、目標値・達成値・実配信値の3つで整合させる。** 1371行目の掛け算のあと、やらない夫に「実際のネトフリ4Kは15Mbps前後だ。生12Gbpsとの比は何倍だ」と問わせ、やる夫に800倍を計算させる。そのうえで「300〜400倍では足りない。残りはどこから来る」と追わせ、(a) 4K配信の多くは60fpsでなく24/30fps、(b) 実際のIフレーム比率とBフレームの寄与、(c) H.264/H.265世代の道具箱で稼ぐ分、の3つを内訳として出す。現状の「肉薄してるお!」（1374行目）を、足りない分を数える場面に変えれば、看板の数字が最後まで生きる。

2. **6-5と6-6を、読解演習から設計問題へ組み替える。** 1746行目の「なぜHEVCはVPSを足したと思う」は良い問いだが、直後に正解が出てしまう。ここを、やる夫にまず「SPSを増やせば済むのでは」と素朴案を言わせ、やらない夫が「同じ映像を720pと1080pの2層で送りたい。SPSは層ごとに違うが、両方合わせた全体のプロファイルは誰が宣言する」と反例を出し、やる夫が上位の箱の必要性を自分で言い当てる形にする。同様に6-5のSPS/PPS分離も、「設定をsliceごとに毎回送ったら何バイト無駄か」を先に数えさせてから導入する。

3. **第5幕にマスキングの定量計算を一つ入れる。** 1288行目のあと、やらない夫が「1kHzが60dB、マスキング閾値がその近傍で35dB。この帯域の成分を量子化するとき、量子化ノイズを35dB以下に抑えればよい。16ビットで持っていた成分を何ビットまで削れるか」と問い、1ビットあたり約6dBというルールからやる夫に $ (96-35)/6 \approx 10$ ビット程度で足りる、と計算させる。映像側の「係数3.1をステップ40で割ったら0になった」（420–421行目）に対応する、音声側の一撃が生まれる。

4. **4-2の境界を潰さずに、次の問いへつなげる。** 887行目の「全部ゼロだお!!」の直後に、やる夫が「……あれ、左端の画素は前のコマのどこから来たんだお?」と気づく2〜3往復を足す。参照範囲外の扱い（端の画素を伸ばして埋める、動きベクトルの探索範囲に制限がある）に触れておけば、6-3のブロック分割やRDOで「候補が有限であること」を語るときの土台にもなる。10行程度で済む。

5. **4-4の実測値に出典と条件を付ける。** 1026行目の11.1KB／11.5KBについて、使用エンコーダ（ffmpeg の mpeg1video / mpeg2video など）、量子化条件、素材を1〜2行で明記し、脚注に再現コマンドを置く。値そのものを変える必要はなく、「読者が同じ数字を出せる」状態にすればよい。

6. **やる夫を配信する側へ一度立たせて、物語的な圧力を作る。** 第6幕の頭（1355行目付近）に、やる夫が自作動画を配信することになり「H.265とAV1のどちらで出すか」を選ばされる、という設定を10〜20行で挟む。これがあれば6-8の特許・ライセンスの話が「業界の歴史」から「やる夫の意思決定」に変わり、1969–1970行目の「法務部と会議室で戦われてたんだお」という感想が、傍観者の感慨ではなく当事者の実感になる。

7. **6-8にライセンス料の具体的な数字を入れる。** 現状は「窓口が3つ以上に分裂」「配信本数や収益にも課金」（1910–1913行目）と定性的な記述に終始しており、この教材が他の全ての節で守ってきた「数字で殴る」流儀から外れている。H.264プールの年間上限額と、HEVC側で提示された料率の一例を並べ、やる夫に「年1億再生の配信で差額はいくらか」を掛け算させる。圧縮率数%の差と特許料の桁を直接比較できれば、6-8の結論（1948–1950行目）が根拠を持つ。
