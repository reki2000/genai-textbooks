# 寸評：やる夫が最強の暗号を作るようです ――秘密の事業計画を守りながら、暗号を古代から耐量子時代まで再発明する

約131KB／全9幕。シーザー暗号から耐量子KEMまでを、やる夫の「世界最強」宣言をできる子が毎回破壊する形式で通史として通し、最後に守っていた秘密そのものを落とす教材。

## 良い点

**「世界最強を宣言する → できる子が破る」の型が9幕を貫いている。** 26通りを0.002秒（83–86行目）、頻度分析（200–206行目）、Kasiski法（326–331行目）、既知平文でエニグマ（495–499行目）、two-time pad（721–748行目）、ECBの画像（1065–1067行目）、nonce再利用（1104–1112行目）、中間者（1578–1583行目）、署名nonce再利用（1971–1973行目）、seed予測（2187–2190行目）、タイミング（2203–2207行目）。11回、必ず「破った手順」まで示して殺している。読者は各節の冒頭でやる夫が自信を持った瞬間に死期を悟る状態になる。

**同じ失敗が名前を変えて戻る、というメタ構造を明示的に運用している。** 1-2で「単位を大きくしただけで安全になったと思わない」（264–266行目）と予告し、ECBで「単一換字暗号を128ビット単位に拡大しただけ」（1081行目）、CTRのnonce再利用で「第3幕のtwo-time padがまた出たお」（1112行目）、ECDSAのnonce再利用で「第3幕の鍵流再利用と似ている」（1976–1977行目）と3回回収する。教材の主題が「方式名の暗記ではない」ことを構造で証明できている。

**楕円曲線への移行が「攻撃側の足場を外す」という論理で導かれ、それが第8幕で一段抽象化される。** 1712–1719行目で指数計算法が使うのは「離散対数という抽象的難しさではなく整数の掛け算という具体的構造」だと言わせ、群を取り替えれば足場が消えると導く（1736–1740行目）。そして8-1で「群を取り替えただけでは逃げられない、周期という足場が残っている」（2571–2579行目）と、同じ論法をもう一段上へ持ち上げる。単に「ECCは鍵が短い」で済ませず、なぜ量子では効かないかまで同じ道具で説明する設計は秀逸。

**技術史の人間側・制度側を捨てていない。** レイェフスキからブレッチリー・パークへの引き継ぎとチューリングの1952年以降（579–619行目）、マークルの不遇とGCHQの1997年公開（1555–1567行目）、RSAの著者順の譲り合いと2000年9月の特許失効（1636–1658行目）、Dual_EC_DRBGとCurve25519の「説明できる定数」（1883–1899行目）。特に「数式は世界共通なのに、使える範囲は法域ごとに違った」（1661行目）は、他の理系教材がまず書かない論点。

**第9幕の落としが第1幕からの伏線を全部使い切る。** 1-1でやる夫が事業内容を絶対に言わない（29–31行目）ところから始め、9-2で中身がYARU-COIN、しかも紹介階層つきの資金循環（2908–2945行目）と判明する。「愚かな計画を最強の暗号で守ると、愚かな計画が安全に保存される」（3019行目）、「暗号は質問を難しくするが、答えを正しくはしない」（3009行目）という着地は、131KBかけて積んだ緊張の解放として機能している。

**参考文献23点が本文の節番号つきで整理されている。** 3044–3088行目。Kerckhoffs 1883からRFC 9954/9958まで、それぞれ「本文4-2に対応する」形式で紐づけられており、HQCについて「選定と最終標準化を区別した」（3074行目）と注記まである。

## 欠点

**中盤以降、やる夫が「再発見する人」ではなく「教科書を要約する人」になっている。** 第6幕・第7幕は「やらない夫が注意点を述べる → やる夫が同じ内容を短く言い直す」の2行ペアが延々と続く。2021–2051行目（証明書検証の注意点6項目）、2126–2147行目、2248–2296行目、2397–2421行目は、ほぼ全部この型である。やる夫の発言に問い・失敗・計算が一つも含まれず、格言集の生成器になっている。前半のやる夫（「なぜ折り返すんだお」1760行目）と別人。

**やる夫が自分で手を動かす計算が前半に偏っている。** $26!\approx4.03\times10^{26}$（161行目）、XORの2ビット全列挙（655–661行目）、$2^{128}$（824–828行目）、$O(2^{n/2})$（1280–1287行目）までは良いが、第6幕以降で数値を入れて結論を出す場面は 2518行目の「残り時間は5年」ほぼ一箇所しかない。第7幕・第8幕は語彙の紹介が主体で、抵抗のある計算がない。

**「玩具問題から作ろう」という宣言が実行されていない。** 2626行目でやらない夫が明言するが、直後の8-2は $\mathbf{b}=A\mathbf{s}+\mathbf{e}$（2634–2636行目）という一般形をいきなり書き、具体的な数値例は一度も出てこない。やる夫の「近い値へ丸めればいいんじゃないか」（2643行目）という良い素朴案が、実際に丸めて失敗する体験なしに、やらない夫の説明（2645–2648行目）だけで棄却される。教材で最も新しい概念のところが、最も手触りが薄い。

**AESだけ再発見が飛ばされている。** Feistelは 946–976行目でやらない夫が式を出し、やる夫が「$F$ が可逆でなくてもよい」を自分でたどるという良い流れになっている。ところがSPNは、やらない夫が方向を示した（1028–1029行目）直後にやる夫が「AESの構造だお。SubBytes、ShiftRows、MixColumns」（1032–1033行目）と名前ごと出してしまう。やらない夫が「名前を暗記する前に役割を言え」（1036行目）と諌めるが、諌める対象の名前を先に出したのは教材自身である。

**できる夫が第9幕まで一度も登場しない。** 人物紹介（12行目）に「投資、法務、事業開発に詳しい」と置かれているのに、初出は2876行目、全体の93%を過ぎた地点。9-2で事業計画を殺す役として有効に働くだけに、中盤で一度も顔を出さないのは配役の遊びが大きい。「普段は忙しい」という一文だけで2800行の不在を説明している。

**物語的な圧力（期限・利害）が事実上ない。** 31行目で「もう投資家とは連絡を取り始めてる」と言うが、以後この投資家との日程・締切・資金枯渇は一度も動かない。同リポジトリの熱力学教材の「祭りまであと3日」に相当する時計が存在せず、9幕ぶんの改良が「次はこれもやろう」で連結されている。9-2の破局も、期限に追われた結果ではなく、たまたまできる夫が来たから起きる。

**数式が1箇所壊れている。** 2520–2524行目のディスプレイ数式が `\text{移行開始期限}` ではなく `ext{移行開始期限}`（バックスラッシュtがタブ文字化）になっており、レンダリングが崩れる。367行目でやる夫に「式の中に変な制御文字が見えるお」と言わせるメタネタを仕込んでいる教材で、本物の制御文字混入が残っているのは惜しい。

## 改善案

1. **2626行目の宣言どおり、LWEの玩具問題を実際にやらせる。** 2626行目と2631行目の間に、$q=17$、未知数3個、式3本の連立方程式を置く。まず誤差なしで掃き出し法を実行させて $\mathbf{s}$ を出させ、次に各式へ $\pm1$ を足した同じ組を渡し、やる夫が「近い値へ丸める」（2643行目の案）を実際に試して、$17$ の折り返しで候補が $3^3$ 通りへ分岐し、式を増やしても絞れないことを自分で確かめさせる。20–30行で、第8幕の核心が語彙から体験へ変わる。

2. **第6幕・第7幕の「注意点→言い換え」ペアを、できる子の攻撃1回へ置き換える。** 2021–2051行目の証明書検証の注意点6項目は、できる子が「名前制約を検証しない実装へ、下位CAが発行した別ドメインの証明書を通した」という具体的な一撃に圧縮できる。同様に 2248–2266行目の秘密消去の議論は、できる子が「クラッシュダンプから復号後の企画書を回収した」1件で足りる。この置換だけで数百行の単調区間が消え、しかも情報量は落ちない。

3. **できる夫を中盤に2回出し、コストと時間の圧力を持ち込ませる。** 6-1のPKI（2000行目付近）で証明書の発行・失効運用にかかる費用と人員を突きつけ、8-1の移行計画（2513–2519行目）で「移行10年の見積もりは誰が払うのか」を問わせる。9-2の登場（2876行目）が、初対面の乱入者ではなく「ずっとコストを聞いてきた人物がついに中身を聞いた」になる。

4. **期限を1本入れる。** 31行目を「3か月後にデューデリジェンスで全資料を出す」に変え、各幕の冒頭にできる夫からの残日数の連絡を1行だけ置く（第3幕で残70日、第6幕で残30日、第8幕で残5日）。第9幕の破局が「期限当日に、守るべき中身が無価値と判明する」構図になり、9-2のオチの落差が跳ね上がる。追加は10行程度で済む。

5. **AESを部品から再構成させる。** 1031–1033行目のやる夫の発言から「AESの構造だお」と4つの名前を削り、代わりに 940–943行目で自分が挙げた要求（規則性を消す・鍵の影響を広げる・逆変換できる・速い）を4つの部品へ割り付けさせる。「各バイトを非線形に置換する箱」「位置をずらして列をまたがせる」「列内で混ぜる」「鍵をXORする」を自分で言わせた後、1045行目でやらない夫が名前を与える。Feistelと同じ扱いに揃う。

6. **誕生日限界を実際の運用量へ換算させる。** 1123–1130行目で、96ビットnonceのランダム選択が $2^{48}$ 個で危険になることを示した後、やる夫に「投資家100人へ毎秒10メッセージ送ると $2^{48}$ に何年で届くか」を計算させ、鍵ごとの送信上限（1129–1130行目）を数字で決めさせる。抽象的な「上限を決める」が、運用値になる。

7. **2520–2524行目の壊れた数式を修正し、`scripts/yaruo_lint.py --check` を通す。** タブ文字が混入した `ext{}` を `\text{}` へ戻す。あわせて 2521–2523行目の不等式は、左辺・右辺の向き（移行開始期限が脅威出現時期より前）が読み取りにくいので、直前のやる夫の30年／10年／15年（2518行目）を数値で代入した形を併記するとよい。
