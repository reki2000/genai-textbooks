# やる夫がメモリを自作するそうです ― 0と1を信用できるまでの150年

---
## 登場人物

**やる夫**：
古いPC史と自作PCに詳しいPCオタク。絶対に遊びたい新作ゲームの発売日までに、自分のPCを32GBへ増設しようとしている。

**やらない夫**：
やる夫の友人。秋葉原のPCパーツショップ「やらない電子」の店長。

**できる子**：
「やらない電子」の店員。物理と半導体材料に強く、やる夫の雑な物理解釈を正す。

**できる夫**：
「やらない電子」の店員。性能、価格、市況の数字と店の値札ボードを担当する。

**やらない夫**：

**やる夫**：

これを256Gibitぶん並べれば32GiBだお！

**やらない夫**：
店の32GBと、お前が言った32GiBは同じ表記か。

**やる夫**：
Gはギガだから同じ……じゃない気がしてきたお。

小文字bはビット、大文字Bは8ビットをまとめたバイト。

10進の接頭語なら、1GBは$10^9$バイト。

2進を明記する接頭語なら、1GiBは$2^{30}$バイトで、約1.074GBだお。

だから、

$$32\ \mathrm{GiB}=32\times2^{30}\ \mathrm{B}=256\ \mathrm{Gibit}$$

**やらない夫**：
本書ではどう書き分ける。

**やる夫**：
箱、値札、仕様書に書かれた製品容量は、32GB RAM、1TB SSDのように公表表記を残す。

そのうえで2進計算をするときはKiB、MiB、GiB、TiBを使う。

SSDやSDカードの公称容量は、メーカー表記どおり10進のMB、GB、TB。

DRAMやNANDのチップ名、転送規格は公表表記どおりKbit、Mbit、Gbitを使い、必要なら実ビット数を添えるお。

**やらない夫**：
では、公称1TBのSSDを2進単位で見れば。

**やる夫**：

$$\frac{10^{12}\ \mathrm{B}}{2^{30}\ \mathrm{B/GiB}}\approx931.3\ \mathrm{GiB}$$

箱の1TBが消えたわけではなく、同じバイト数を別の物差しで測っただけだお。

さらに初期化用の管理情報やOS自身の領域が使われると、利用可能量はそれより減るお。[^116]

**やらない夫**：
RAMなら箱どおり全部をOSが使えるか。

**やる夫**：
それも限らないお。

この教材の32GB製品は、価格計算では$32\times2^{30}$バイト、つまり32GiB相当と仮定する。

でも実機ではBIOSや装置用のメモリマップが一部を予約し、OSとアプリが使える主記憶は物理搭載量より少ない場合があるお。[^117]

**やらない夫**：
メガやギガだけでは、基数も利用可能量も決まらない。

単位と文脈を一緒に読め。

**やらない夫**：
じゃあ1を書け。

**やる夫**：
スイッチ入。
光ったお。

**やらない夫**：
入力を外せ。

**やる夫**：
スイッチを離すお。

……消えたお。

**やらない夫**：
さっき何を記憶してた。

**やる夫**：
1だお。

**やらない夫**：
今は。

**やる夫**：
0だお。

……。

記憶してないお！！

**やらない夫**：
お前が作ったのは表示器だ。

**やる夫**：
でも0と1の2状態は作れたお。

**やらない夫**：
それだけでは記憶じゃないということだな。

**やる夫**：
入力を取り除いたあとも、以前の状態が残らないといけない。

……なるほど。

0と1を作るより、
0と1を**残す**ほうが難しいのかお。

**やらない夫**：
店の説明用ホワイトボードを使え。
これから作るすべてのメモリについて、同じ6問を答える。

**やる夫**：
書くお。

| 問い                 | 意味                    |
| ------------------ | --------------------- |
| 状態              | 何の物理状態を0/1と呼ぶ？        |

| 選択             | 大量の中から目的のビットだけどう選ぶ？   |
| 大量生産    | どう大量・安価・高歩留まりで作る？     |
| 製品 / 規格 | 他の機械からどう同じメモリとして使わせる？ |

**やらない夫**：
店の値札用ボードも使え。

**やる夫**：
まだあるのかお。

**やらない夫**：
お前が怒った理由を忘れるな。

**やる夫**：
値札ボード……。

容量、速度、価格を書くお。

今は、

**やる夫**：
**時代の値札：やる夫式電球メモリ**

| 項目 | 値 |
|---|---|
| 容量 | 1ビット |
| 保持 | 入力を外した瞬間0ビット |

### 2-2　真空管という電気の蛇口

**やらない夫**：
1906年、Lee de ForestがAudionと呼んだ3極真空管を作った。
だが初期のAudionは、今から見れば安定した増幅器ではなかった。

その後、AT&TとWestern Electric、Bell系の研究者たちは、
長距離電話に使える高真空管へ改良した。
Harold Arnoldらの仕事を経て1913年には電話中継増幅器が実用化され、
1915年には米国大陸横断電話が開通した。[^2]

**やる夫**：
コンピュータのためじゃない。

ニューヨークとサンフランシスコで人間がしゃべりたかったから、
高速電子増幅器に巨額の研究費が流れたんだお。

**やらない夫**：
3極管をどう理解する。

**やる夫**：
熱した陰極から電子を飛ばす。
正電圧の陽極が電子を引く。

その間に格子を置く。

格子電圧を少し変えるだけで、
陰極から陽極へ流れる大きな電流を制御できる。

蛇口の取っ手を小さく動かして、
大きな水流を変える感じだお。

**やらない夫**：
ではリレーとの違いは。

**やる夫**：
鉄片が動かない。
電子しか動かない。

速い。

そして入力を入/切だけでなく連続的に扱えるお。

### 2-3　増幅器を2個、喧嘩させる

**やる夫**：
でも増幅できても記憶にはならないお。

真空管も入力を消したら出力が消える。

……。

前にリレーでやったことを、
真空管でもやればいいのでは？

出力を入力へ戻すお。

**やらない夫**：
1本だけ戻すと。

**やる夫**：
増幅率が大きすぎれば発振したり飽和したりするお。

じゃあ2個使うお。

**やらない夫**：
Aの陽極出力をBの格子へ、Bの陽極出力をAの格子へ交差して戻せ。

Aに大きな電流が流れたら、Aの陽極電圧とBはどうなる。

**やる夫**：
Aの陽極電圧が下がり、その低い電圧がBの格子を抑える。

Bが弱れば、今度はAを抑える力も弱くなる。

Aがますます勝つお。

**やらない夫**：
Bが先に強ければ。

**やる夫**：
逆にBがAを抑える。

Aが勝っている状態では、
A側が高、B側が低。

Bが勝っている状態では、
A側が低、B側が高。

中間は不安定。

……2つの安定状態ができたお。

**やらない夫**：
片方へ一瞬だけ正の電圧を加えたら。

**やる夫**：
セット端子からAを一押しすれば、交差帰還がBを抑え、入力を戻してもAが勝ったままになる。

リセットではB側を押して、勝敗を逆転させればいい。

これは……1ビットだお！！

**やらない夫**：
William EcclesとF. W. Jordanは1918年ごろ、
2つの真空管を交差結合したトリガ回路を発表した。
後にフリップフロップと呼ばれる回路の祖先だ。[^3]

**やる夫**：
彼らもPC用RAMを作ろうとしてたわけじゃないんだおな。

**やらない夫**：
違う。
増幅器、トリガ、計数器といった電子回路の発展から双安定回路が生まれ、
計算機のレジスタへ利用されていった。

**やる夫**：
系譜が見えてきたお。

電話で声を増幅したい
↓
真空管増幅器
↓
増幅器を帰還させる
↓
双安定
↓
1ビット記憶

メモリを作ろうとして真空管を発明したわけじゃない。

通信産業が作った増幅器を、
計算機屋が記憶へ転用したんだお。

**やらない夫**：
ただし1ビットに複数の真空管が必要だ。

**やる夫**：
100万ビットなら真空管が何百万本。

部屋が暖房になるお。

**やらない夫**：
そこで計算機設計者は気づく。

計算中に今すぐ必要な数十ビット、数百ビットなら双安定回路でいい。

だが何千語、何万語も全部それで持つのは高すぎる。

**やる夫**：
高速な記憶と、
大容量な記憶が分裂する。

……もう記憶階層の芽が出てるお。

**できる夫**：
また数字が出ましたね！！

**時代の値札：真空管式記憶、1940年代**

| 項目 | 値 |
|---|---|
| 典型用途 | レジスタ、カウンタなど数ビット～数百ビット級 |
| 製品単位 | 双安定回路1個＝1ビット。真空管2本前後＋抵抗＋電源＋冷却 |

**やる夫**：

半導体みたいな魔法の面積縮小はまだないんだお。

## 第3幕　1ビットに1個の装置を使うな

---
### 3-1　ビットを場所ではなく時間に置く

**やる夫**：

**やる夫**：

別の方法で電流を制御できないか。

導体を直接つながず、電界で半導体表面の電子を寄せたり追い払ったりする。
それが電界効果だ。
アイデア自体は古かったが、
Si表面の状態が制御を邪魔した。

Mohamed AtallaらのSiO₂による表面不動態化研究が進み、
AtallaとDawon Kahngは1959年に実用的なMOSFETを実現した。[^9]

**やる夫**：
MOSFET……名前からして部品が多いお。

**やらない夫**：
Metal、Oxide、Semiconductorを積んだ構造で電界効果を使うトランジスタ。
頭文字をつないでMOSFET、Metal-Oxide-Semiconductor Field-Effect Transistorだ。

**やる夫**：
名前を展開しても動きが見えないお。
よく分からないから、nMOSを一回作ってみるお。

**やらない夫**：
p型基板へ、高濃度n型のソースとドレインを離して作れ。

**やる夫**：
間はp型のままだから、n型同士がつながらないお。

**やらない夫**：
その隙間の表面へ絶縁体のSiO₂を置き、さらに金属のゲート電極を重ねる。

**やる夫**：
金属、酸化物、半導体。ここがMOSかお。
でも酸化物が絶縁するなら、ゲートから電流は流れないお。

**やらない夫**：
電流は流さなくても電界は届く。
ゲートへ正電圧をかけると、p型表面の正孔が追い払われ、電子が引き寄せられる。
さらに電圧を上げると表面の多数キャリアが反転し、ソースとドレインの間にn型チャネルができる。

**やる夫**：
つながったn型チャネルを電子が流れる！
つまりnMOSという名前なのに、
基板全体がn型なんじゃなくて、ゲート直下にできるチャネルがn型なんだお。

**できる子**：
pMOSは極性を反転。
典型的にはn型基板またはnウェル側に、
負のゲート電圧で正孔チャネルを形成する。

**やる夫**：
BJTは接合を通してキャリアを注入して制御する。

MOSFETは絶縁ゲートの**電界**でチャネルを作って制御する。

同じトランジスタでも物理が違うお。

### 6-4　開いた行をすぐ閉じるな

**やる夫**：
DRAMの読出しを分解する。

行を選んで、微小差を検出増幅器へ出して、1行ぶん確定する。

その後に列を選んで、欲しい部分を外へ渡す。

連続したデータを読むのに、毎回同じ行を閉じて開くのは無駄だお。

じゃあ別の工夫をする。

行を1回開いたら、
検出増幅器群に1行分が乗る。

そこを行バッファとして使う。

同じ行の複数列を連続して読めば、
毎回セルから読み直さなくていいお。

**やらない夫**：
これがページモードだ。
Fast Page Mode DRAMでは、行を開いたまま列アドレスだけを切り替えて連続アクセスを速くした。

**やる夫**：
FPMの次ならEDOだお。

1990年代半ばのPC売り場で、72ピンSIMMの「EDO」「60ns」という札を見た世代もいる。

Extended Data Outだから、前のデータを出力端子へ長く残す方式だお。

**やらない夫**：
カタログ名は正解だ。では何と何を重ねた。

**やる夫**：
次の列アクセスを始めても前のデータを出力端子へ少し長く保持する。

出力と次の内部動作を重ね、非同期DRAMの待ちを減らした。EDOは1990年代半ばにFast Page Modeを置き換えたが、1990年代後半にはSDRAMへ移った。[^27]

FPMは行を開く手間を使い回した。

EDOは前の出力を残したまま次の仕事を始めた。

セルを速くできないから、**仕事を重ねて空白時間を減らした**んだお。

### 6-5　何ビットCPUなら、何ビットずつ運べるのか

**やる夫**：
表では外部データ幅が8ビット、32ビット、64ビットと増えた。

でも「何ビットCPUなら同じビット幅ずつDRAMを読む」は、PCオタクなら8088の時点で踏む罠だお。

内部のレジスタや演算幅、アドレス幅、外部データバス幅は別物だお。

**やらない夫**：
具体例で証明しろ。

**やる夫**：
8088は内部では16ビット系でも、外へは8ビットずつ。

8086と80286は外部16ビット。

386DXと486は外部32ビット。

初代Pentiumは内部の基本レジスタが32ビットのまま、メモリとの外部データバスを64ビットへ広げた。[^39][^45]

同じ「32ビットCPU」という言葉でも、何を32ビットと呼んでいるか確かめないといけないお。

**やらない夫**：
DRAMチップ1個の幅は。

**やる夫**：
初期にはx1、つまり1ビット出力のチップが多かった。

CPUへ8ビット同時に渡すなら、x1チップを8個並べる。

後にはx4、x8、x16のDRAMチップも使う。

64ビットのメモリチャネルなら、x8チップを8個で64ビット。

ECC用にさらに8ビット加えたモジュールなら72ビットぶん載る構成もあるお。

**やらない夫**：
ではバスを毎世代2倍にしろ。

128ビット、256ビット、次は512ビットだ。

**やる夫**：
CPUのピン、基板配線、同時に切り替える電力、信号の到着時刻合わせまで増える。

1本を足せば無料で1ビット増えるわけじゃない。

……外部バスは8→16→32→64ビットと広がったけど、64ビットの次は一本を無限に太くするより、転送回数やチャネル数を増やす方向へ移るんだお。

---
### 6-6　CPUと同じ拍子で運べ

**やる夫**：
次はPC66、PC100、PC133のSDRAMだお。

メモリ側も共通のクロックへ合わせ、クロックに同期してコマンドを出し、バースト転送する。

バンクを複数作れば、別バンクの待ち時間も重ねられるお。

**やらない夫**：
PCオタクの箱書き知識だけで、DDR5-6400を説明してみろ。

**やる夫**：
簡単だお。6400MHzのメモリだお！

**やらない夫**：
いきなり単位を間違えたな。

**やる夫**：
……店頭ではMHzと書かれることも多いけど、DDR5-6400の6400は1ピン当たり毎秒6400M回の転送、6400MT/sだお。

じゃあ、PC趣味でいう「ベースクロック」が3200MHzなのは、なぜ半分なんだお。

**やらない夫**：
DDRは一周期に二回運ぶからだ。

まず、同期DRAMからの代表値を分けて見ろ。FPMやEDOは共通クロックへ同期せず、60nsや70nsのアクセス時間で語られたので表外だ。

同期DRAM（synchronous dynamic random-access memory, SDRAM）から順に分けると、こうなる。

| 規格世代 | PCでの登場目安 | 外部CKクロックの代表範囲 | 1ピン当たり実効転送レート | プリフェッチ |
|---|---:|---:|---:|---:|
| SDR SDRAM | 1990年代半ば | 66〜133MHz | 66〜133MT/s | 1n |
| DDR | 2000年前後 | 100〜200MHz | 200〜400MT/s | 2n |
| DDR2 | 2000年代半ば | 200〜533MHz | 400〜1066MT/s | 4n |
| DDR3 | 2000年代後半 | 400〜1066MHz | 800〜2133MT/s | 8n |
| DDR4 | 2010年代半ば | 800〜1600MHz | 1600〜3200MT/s | 8n |
| DDR5 | 2020年代前半 | 1600〜3200MHz | 3200〜6400MT/s | 16n |

この範囲は各世代の代表的な標準速度を丸めたものだ。同じ世代にも拡張速度、オーバークロック品、用途別規格がある。[^47]

**やらない夫**：
プリフェッチが増えると、何がうれしい。

**やる夫**：
DRAMセル配列を外部I/Oと同じ速さで一個ずつ走らせず、一度に複数ビットを内部で取り出して外へ直列に吐ける。

例えばDDR4-3200は8nだから、単純化すれば内部配列側は1ピン当たり

$$3200\div8=400\text{ M組/s}$$

DDR5-6400は16nだから、

$$6400\div16=400\text{ M組/s}$$

外の転送レートは2倍でも、内部配列が一組を取り出す頻度まで2倍とは限らない。

**内部を同じ倍率で無理に走らせず、まとめ取りとI/Oで外側を速くする**んだお。

**やらない夫**：
ではPC100を計算しろ。

**やる夫**：
SDRAMは1990年代半ばからPCへ広がった。

PC66、PC100、PC133という1990年代後半の名前を店頭で見た者もいるだろう。

末尾の数字は、当時のSDRAMモジュールが同期するクロックの目安だった。

100MHzなら1秒に1億回。

64ビット幅、つまり8バイトを1回ずつ運ぶなら、

$$100\times10^6\times8=800\times10^6\text{ バイト/s}$$

理論上は800MB/s。

だからPC100のモジュールがPC800とは呼ばれなかったのは、クロックと帯域で見ている数字が違うからかお。

**やらない夫**：
同じCKクロックのまま、転送回数を2倍にするには。

**やる夫**：
DDRならクロックの立ち上がりと立ち下がりの両方を使い、1周期に2回転送する。

倍データレート（double data rate, DDR）だお。

PC主記憶では2000年前後からSDR SDRAMとの交代が始まった。

例えば200MHz相当の入出力で両エッジを使い、毎秒400M回転送するDDR-400なら、64ビット幅で、

$$400\times10^6\times8=3.2\times10^9\text{ バイト/s}$$

約3.2GB/s。

だからPC3200という帯域名にもなるお。

**やらない夫**：
ではDDR番号が増えれば、製造プロセスも一段ずつ小さくなるのか。

**やる夫**：
そこは一対一じゃないお。

DDRはインターフェース規格、nmは特定メーカーの特定世代の製造技術だ。同じDDR規格が何回も微細化され、隣のDDR世代とも重なる。

代表的な量産発表だけ並べてもこうなる。

| 年 | 製品例 | 公表されたDRAMプロセス |
|---:|---|---:|
| 2001 | 256Mbit SDRAM | 0.15μm |
| 2007 | 1Gbit DDR2 | 68nm |
| 2007 | 1Gbit DDR3 | 78nm |
| 2014 | DDR3／DDR4 | 20nm |
| 2021 | DDR5 | 14nm、EUV使用 |

同じDDR3だけでも78nmの製品例から20nmの量産例まである。表は業界全体の唯一の対応表ではなく、メーカー発表から拾った代表点だ。[^48][^49]

**やらない夫**：
何のために小さくした。

**やる夫**：
1枚のウェハから多くのビットを取り、容量と消費電力と原価を改善するため。

ただしDRAMはコンデンサの電荷量を残さなければならない。CPUロジックと同じ縮小則、同じ工場設備で進むわけではない。この物理と工場の違いは第8幕で解剖するお。

**やらない夫**：
DDR2、DDR3、DDR4、DDR5と世代が続くにつれ、プリフェッチ、バンク構成、信号方式、電圧、モジュール側の仕組みも変わる。

ただし、その名前は1T1Cセルの新しい物理現象を指してはいない。

**やる夫**：
中のセルが電荷をためて、読めば壊れて、リフレッシュされる骨格は残る。

DDRは主に**セル配列とCPUの間で、どう大量に運ぶかという境界の進化**なんだお。

### 6-7　一番MHzの大きいメモリを買う

**やる夫**：
では1999年のPC雑誌と店頭広告だけを信じる買い手を演じるお。

商品箱で一番MHzが大きい物を採用すればいい。

Rambusだお！！

**やらない夫**：
何と比べる。

**やる夫**：
1990年代末から2000年代初めのPC主記憶候補。

一方は幅の広いバスを両エッジで動かすDDR SDRAM。

もう一方はRambus社のDirect Rambus DRAM、RDRAM。

RDRAMを載せたモジュールがRIMMだお。[^32]

**やらない夫**：
両方の小さな模型を作れ。

**やる夫**：
模型DDRは64ビット、8バイト幅で毎秒266M回転送。

$$8\times266=2128\text{ MB/s}$$

模型Rambusは16ビット、2バイト幅だけど毎秒800M回転送。

$$2\times800=1600\text{ MB/s}$$

あれ。

800という大きな数字だけ見たRambusが、266というDDRより必ず大帯域とは限らないお。

**やらない夫**：
数字が何を数えているかを無視したからだ。

Rambusの狙いは、狭い配線を高い転送レートで動かし、信号の到着時刻を厳密に管理する高速チャネルだった。[^33]

IntelもPentium IIIとIntel 820チップセットを組み合わせたRDRAMプラットフォームを強く推した。[^34]

**やる夫**：
ではDDRの勝ち、Rambusは無意味……。

いや、待つお。

さっき自分でやった。

幅と転送回数の組合せ次第で結果が変わる。

連続転送の帯域だけでなく、最初のデータが来るまでの遅延、短いランダムアクセス、価格、発熱も見る必要がある。

さらにRIMMだけ買っても、RDRAM対応のメモリコントローラと基板配線がなければ挿さらないお。

**やらない夫**：
Intel 820で通常のSDRAMを使うためのMemory Translator Hubには信号ノイズの問題が起き、Intelは2000年に対象マザーボードの交換を発表した。RDRAM搭載機はその変換部品を使わないため対象外だった。[^35]

**やる夫**：
異なるメモリ方式を変換器1個で雑に橋渡しすればいい、でもなかった。

Rambus案は高い転送レートという本物の長所を持っていた。

それでもPC主記憶の商品としては、モジュール価格、レイテンシ（待ち時間）、チップセット、DRAMメーカー、マザーボードまで揃った生態系で競う。

**一番大きなMHzだけでは、規格の勝敗は決められない**んだお。

**やらない夫**：
そのRIMM、次の幕でもう一度使うぞ。

今度は電気方式でなく、利用者が手に持つモジュールとしてだ。

### 6-8　規格は完成品へ貼る名前ではない

**やる夫**：
待つお。

SDRAM、DDR、RDRAMと名前を並べたけど、方式を発明しただけでは他社のCPUやマザーボードにつながらない。

PCオタクがメモリを買えたのは、ピン、電圧、コマンド、タイミング、モジュール形状の約束が先にあったからだお。

**やらない夫**：
では「規格化」はいつ始まった。

**やる夫**：
一つの年を答える問題じゃない気がするお。

一社の機械の中を揃えることと、他社製部品まで交換できることは違うお。

**やらない夫**：
互換性を作る範囲と、約束を決める主体がどう変わったか、年代順に置くぞ。

| 時期 | 例 | 互換性を作った方法 | 互換性の範囲 |
|---:|---|---|---|
| 1964年 | IBM System/360 | IBMが同一系列の命令体系と周辺機器を計画 | 一社の製品ファミリー |
| 1981年 | IBM PC | 技術資料を公開し、他社製拡張カードや互換機が増える | デファクトなPC生態系 |
| 1990年代以降 | SDRAM／DDR | JEDECで参加企業が電気・論理・モジュールの境界を標準化 | 複数のCPU、DRAM、モジュール企業 |
| 1990年代末 | Direct RDRAM | Rambusのライセンスと対応企業群でチャネルを統一 | 契約で参加する製品生態系 |

System/360は互換性の歴史では大事件だが、公開された汎用DRAM規格ではない。IBM製品系列の中を揃えた。[^36]

IBM PCは回路図やインターフェースを含む技術資料が公開され、第三者がメモリ拡張カードや互換機を作る余地を広げた。[^42]

さらに部品メーカーが増えると、一社の完成機仕様だけでは足りない。

JEDECはDDR SDRAM、HBM、メモリモジュール構成などの公開された業界標準を策定している。[^46]

**やらない夫**：
ではPC66、PC100、PC133も、DDRも、全部まったく同じ種類の規格か。

**やる夫**：
違うお。

DRAMチップの電気的・論理的な約束、DIMMの配線と形、SPDの内容、CPUやチップセットが要求する動作条件、メーカーの適合試験、店頭の速度表示が重なっている。

PC100という商品名が読めても、それだけで任意の100MHz対応チップを任意の基板へ挿せるわけじゃないお。

**やらない夫**：
Rambusは独自方式だから、規格化の反対か。

**やる夫**：
それも違う。

RDRAM、RIMM、制御装置、コネクタを複数企業で揃えなければ製品にならない点では、Rambusも規格化をしたお。

**やらない夫**：
ただし、業界団体で合意する標準と、技術企業が知的財産をライセンスして統率する方式では、参加条件と利益配分が違う。[^32][^33]

**やる夫**：
規格があるかないかだけでなく、誰が約束を決め、誰がどんな条件で参加できるかも見るのかお。

**やらない夫**：
規格書は、最高のDRAMが完成してから書けばいいな。

**やる夫**：
それでは遅いお。

**やらない夫**：
CPUとチップセット、DRAM、モジュール、マザーボードを各社が同時に設計する。

試作品を持ち寄り、起動条件と余裕を詰める作業も規格化の一部だ。

**やる夫**：
だから、標準化は発明の後に名前を貼る事務作業じゃない。

**別々の会社が、完成前から同じ境界へ向けて設計するための工学**なんだお。

この幕では、規格化が必要になった理由と決め方までにする。

次の幕でSIMM、DIMM、RIMM、ECC、Registered、SPDという、PCやUNIXサーバーの保守現場で実際に触る名前を解剖するお。

### 6-9　帯域を増やしても、最初の1バイトは早く来ない

**やる夫**：
DDRなら安心だお。

DDR、DDR2、DDR3と転送レートを倍々にすれば、CPU待ちは消えるお。

**やらない夫**：
次の二つを測れ。

(1) 連続した1GiBを読む時間。

(2) 離れた場所から8バイトを1回だけ読む時間。

**やる夫**：
(1)は毎秒運べる量、帯域幅（bandwidth）が効く。

(2)は要求してから最初のデータが来るまでの遅延、レイテンシが効く。

バスが1回に大量に運べても、行を開き、センスし、列を選ぶ最初の待ちは残る。

DDRの世代番号だけで、両方が同じ倍率で改善するわけじゃないお。

**やらない夫**：
CPU性能の伸びがDRAMの待ち時間改善を上回り、キャッシュにないデータを待つ割合が増える問題は、1990年代にメモリウォール（memory wall）と呼ばれた。[^28]

**やる夫**：
だから対策が一つじゃない。

キャッシュでDRAMへ行く回数を減らす。

行バッファとバーストで、一度開いた行からまとめて運ぶ。

複数バンクの仕事を重ねる。

プリフェッチで必要になる前に取りに行く。

チャネルを増やして並列に運ぶお。

**やらない夫**：
CPUのピンは無限か。

**やる夫**：
違う。

チャネルを増やせば配線、消費電力、基板面積が増える。

複数CPUなら、自分に近いメモリと別CPUに近いメモリで距離まで違う。

一様メモリアクセスだと思っていた住所空間が、物理的には非一様メモリアクセス、NUMAになる。

……あっ。

**メモリの速さはセル単体の数字じゃない。CPUから何本の道で、何段を通り、どれだけ遠くへ取りに行くかまで含む**んだお。

**やらない夫**：
なら次に作る物は決まったな。

**やる夫**：
DRAMチップだけでは商品にならない。

CPUと決めた幅、電圧、時刻で会話できて、利用者が交換できる単位へまとめる。

次はメモリモジュールだお。

## 第7幕　DRAMチップを、PCとUNIXサーバーが買える部品にする

---
### 7-1　64本のチップを1個ずつ挿したくない

**やる夫**：
64ビットのメモリチャネルが欲しい。

x1のDRAMを64個、マザーボードへ直接挿すお。

1個壊れたら、その1個だけ交換できて経済的だお！！

**やらない夫**：
64個の向きと型番を確認して、64個のソケットへ挿すのか。

**やる夫**：
……指がつるお。

配線も長さがばらばらになる。

増設のたびに店員がDRAMチップを数えるPCなんて売れないお。

**やらない夫**：
なら、何を交換単位にする。

**やる夫**：
複数のDRAMと配線を小さな基板へ先に載せる。

利用者は基板を1枚挿すだけ。

チップのDIPから、ピン付きのSIPP、カード端子のSIMMへ進む理由はこれだお。

**やらない夫**：
PCオタクなら幅まで言えるだろ。

**やる夫**：
30ピンSIMMは8ビット、72ピンSIMMは32ビット、168ピンDIMMは64ビットだったはずだお。

だからCPU側の幅と組み合わせれば、必要枚数が出るお。

**やらない夫**：
パリティ付きなら順に9、36、72ビット級だ。1997年の市場資料にも、30／72ピンSIMMから168ピンDIMMへ移る姿が出ている。[^32]

では32ビットバスの386DXや486に、30ピンSIMMを使うなら。

**やる夫**：
8ビット幅を4枚で32ビット。一組4枚だお。

72ピンSIMMなら486は1枚、外部64ビットのPentiumなら2枚で一組。

168ピンDIMMなら64ビットあるから、Pentium世代の幅を1枚で満たせるお。

**やらない夫**：
SIMMとDIMMの違いは、チップを片面と両面へ載せることか。

**やる夫**：
違うお。

SIMMは基板の表裏に端子があっても、対応する表裏の接点が同じ信号につながる。

DIMMは表裏の接点が別信号だから、同じ長さでも多くの信号を出せる。

小型PCにはSO-DIMM、前幕のRDRAMにはRIMMもある。

**チップをまとめただけに見える板が、CPUのバス幅と交換作業をつなぐ製品境界**になったんだお。

### 7-2　形が同じなら動くはずだ

**やる夫**：
YARU-DIMMを作ったお。

市販DIMMと同じ長さ、同じ切り欠き、同じピン数。

物理的に挿さった。勝ったお！！

**やらない夫**：
電源を入れてみろ。

**やる夫**：
画面が真っ黒だお。

挿さったのに起動しない……。

**やらない夫**：
波形で、ACTIVATEから読出しまでを測ってみるか。

**やる夫**：
コントローラは3サイクル後に読出しを出した。

でもYARU-DIMMは、その時点で行をまだ開き終えていない。

形を合わせても、電圧、ピンの役割、クロック、コマンド、待ち時間が違えば会話にならないお。

**やらない夫**：
他社のCPU、DRAM、モジュールが、完成前から何を共有すればいい。

**やる夫**：
許される電圧と波形。

ACTIVATE、読出し、書込み、REFRESHの意味。

コマンド間に必要な時間。

パッケージとモジュールの配線。

第6幕で見たJEDECの標準は、ここまで境界を決めるためにあるお。[^46]

**やらない夫**：
ならDDR5は、1T1Cを捨てた第5世代セルか。

**やる夫**：
そうじゃないお。

中では電荷をため、読めば再生し、リフレッシュする骨格が残る。

DDR5は主に、**CPU側から見える電気・コマンド・タイミングの境界を世代更新した名前**だお。

同じ形にするだけでなく、同じ時刻に同じ意味の信号を交換して、初めて「互換」と言えるお。

### 7-3　この1枚は何者なのか

**やる夫**：
JEDECの範囲へ合わせた。

今度は起動したお！

容量違いのDIMMも挿すお。

……また黒画面だお。

**やらない夫**：
規格書は、その1枚が16GBか32GBかまで決めてくれるのか。

**やる夫**：
決めないお。

規格は許される容量、構成、タイミングの範囲を作る。

この製品がどの値を選んだかは、1枚ごとに違う。

なら小さなEEPROMをモジュールへ載せ、自分で名乗らせるお。

**やらない夫**：
何を名乗る。

**やる夫**：
容量、DRAMチップの構成、Rank数、対応速度、CASレイテンシ、電圧、メーカー情報。

BIOSやファームウェアが起動時に読めば、安全なタイミングを選べるお。

**やらない夫**：
それが直列存在検出（Serial Presence Detect, SPD）だ。

Micronも、SPDがモジュールの電気的・物理的特性をEEPROMへ持ち、BIOSがSMBus経由で読む仕組みだと説明している。[^50]

**やる夫**：
中古屋で拾ったラベルを読むお。

`32GB 2Rx8 DDR4-3200 PC4-25600 CL22`。

DDR4-3200は1ピン当たり3200MT/s。

64ビット、8バイト幅なら、

$$3200\times8=25600\text{ MB/s}$$

だからPC4-25600は理論帯域約25.6GB/s。

2Rは2つのRank、x8は各DRAMチップのデータ幅、CL22は読出しからデータ開始までのクロック数を表すお。

**やらない夫**：
ラベルとSPDは同じ物か。

**やる夫**：
ラベルは人間が買うための要約。

SPDは機械が設定するための構造化データ。

**規格は許される範囲、SPDはこの一枚が選んだ自己紹介**なんだお。

---
### 7-4　誤りを見つけただけでは業務は続かない

**やる夫**：
自宅PC用の安いUDIMMをUNIXサーバーへ山ほど挿すお。

同じDDRなら、メモリ容量だけ安く増えるお。

**やらない夫**：
夜中に1ビットだけ反転した。

**やる夫**：
パリティを付けておけば見つかる。

偶数パリティなら、`10110010`には1が4個だからパリティビットは0。

1ビット反転すれば奇数になって検出できるお。

**やらない夫**：
検出した後、データベース処理を続けられるか。

**やる夫**：
どのビットが正しかったか分からない。

「壊れました」と報告して業務停止……それでは足りないお。

2ビットが同時に反転すれば偶数へ戻り、単純パリティでは見逃す場合まであるお。

**やらない夫**：
なら、余分なビットを何に使う。

**やる夫**：
誤り位置まで絞れる検査ビットを作る。

典型的なECC DIMMなら64ビットのデータに8ビットを加えた72ビット幅で、1ビット訂正と2ビット誤り検出を行う構成がある。

さらに1個のDRAMチップ故障へ耐えるには、符号の各部分を複数チップへ分散するChipkillのような設計を使うお。

**やらない夫**：
訂正できるなら、放置してよいか。

**やる夫**：
同じ場所へ次の誤りが重なる前に、定期的に読み、訂正し、書き戻すメモリスクラビングが要る。

故障が増えた領域を予備へ逃がすスパリング、同じ内容を別系統へ二重に書くミラーリングもある。

IBMの業務サーバーでも、Chipkill、巡回訂正、二重化を重ねて停止を減らしていたお。[^51]

**やらない夫**：
家庭用PCより高い理由は。

**やる夫**：
ビットが上等だから、だけじゃない。

**誤りを検出して終わらず、訂正し、劣化を監視し、故障中も業務を続ける仕組みへ料金を払う**んだお。

---
### 7-5　容量を増やすほど信号が弱る

**やる夫**：
サーバーの空きスロットを全部埋めるお。

DIMMが2倍なら容量も2倍。規格品だから速度はそのままだお。

**やらない夫**：
1本のアドレス線へ、DRAM入力を何個ぶら下げた。

**やる夫**：
DIMMを増やすほど入力容量と配線分岐が増える。

信号の立上りが鈍り、反射と到着時刻のずれも増える。

コントローラの表を見ると、1チャネル1枚では最高速でも、2枚では速度を落とす構成があるお。

**やらない夫**：
容量と速度を両立するには。

**やる夫**：
CPUからのアドレスとコマンドを、モジュール上のレジスタで一度受けてからDRAMへ配る。

それがRegistered DIMM、RDIMMだお。

**やらない夫**：
データ線側の負荷まで緩衝回路で隠すのがLoad-Reduced DIMM、LRDIMMだ。

Micronも、RDIMMはレジスタで信号品質と容量を高め、LRDIMMはデータ負荷をさらに減らして多Rank・高容量を可能にすると説明している。[^52]

**やらない夫**：
では昔の保守棚にある名前を読んでみろ。

**やる夫**：
`PC133 ECC Registered SDRAM`は、133MHz級SDR、ECC、Registered。

`PC3-10600R`の末尾RもDDR3 Registeredだお。

でも`PC2-5300F`のFや、`PC4-2400T-R`のTまでは自信がないお。

**やらない夫**：
FはFully Buffered DIMM、FB-DIMM系。

`PC4-2400T-R`は2400MT/s級、Tはタイミング区分、末尾RがRegisteredを示すサーバー向け表記だ。

DDR5でもECC RDIMMは現役。

**やる夫**：
規格名を一語ずつ分解すれば、世代、速度、誤り訂正、信号負荷の対策まで読めるのかお。

**やらない夫**：
ならRを普通のPCへ挿せ。

**やる夫**：
メモリコントローラがRDIMMへ対応していなければ動かない。

バッファは魔法の加速器じゃなく、**一段の遅延と価格を払って電気負荷を分離し、大容量を成立させる部品**なんだお。

---
### 7-6　JEDEC準拠なら何でも混ぜられる

**やる夫**：
やらない電子の棚から、箱にJEDEC準拠と書いてあるDIMMを4種類選んだお。

DDR4ならメーカー、容量、Rank、速度を混ぜても全部動くお！

四社混載こそ、自作PCの多様性だお！

**やらない夫**：
店の商品を勝手に開封するな。

CPUのメモリコントローラは何世代だ。

**やる夫**：
対応速度の上限がある。

UDIMM用スロットへRDIMMは使えない。

1チャネル当たりのDIMM枚数とRank数を増やすと、速度を落とす規則もある。

容量の並べ方次第でインターリーブ条件も変わるお。

**やらない夫**：
規格があるのに、なぜサーバーベンダーは対応メモリ表を出す。

**やる夫**：
規格は全製品の全組合せを試験した証明書じゃないからだお。

電圧、波形、タイミング、形、SPDという共通の測定点を作り、その範囲でCPUメーカーとシステムメーカーが構成を検証できるようにするお。

**やらない夫**：
手元の4枚が動かなかったら、どう切り分ける。

**やる夫**：
まずCPUの対応表にある同一種類・同一速度の1枚だけで起動する。

次に枚数、チャネル、Rank、速度のうち一条件ずつ変える。

共通規格があるから、闇雲な相性占いではなく、条件を固定した試験にできるお。

**やらない夫**：
なら標準化の価値は、何でも挿せることではないのか。

**やる夫**：
違う。

独自仕様が無限に増える世界を、比較と試験ができる有限の境界へ縮める。

**標準化は組合せ試験を不要にする魔法ではなく、試験可能な境界を作る技術**なんだお。

そして同じ規格のチップでも、容量と価格は世代ごとに増え続けた。

次は、その小ささを物理的に作れるかだお。

---
## 第8幕　小さくすると、DRAMセルは読めなくなる

---
### 8-1　同じ絵を縮小コピーすればいい

**やる夫**：
第6幕で製造プロセスが0.15μmから数十nmへ縮んだ表を見た。

1T1Cの図を縦横半分へ縮めれば、同じ面積へ4倍入るお。

DRAM大容量化、永久に続くお！！

**やらない夫**：
コンデンサの式を書いてみるか。

**やる夫**：
蓄える電荷は、

$$Q=CV$$

容量$C$を半分にし、電圧$V$も低下させれば、信号電荷$Q$まで減る。

仮に30fF、1.2Vなら、

$$Q=30\times10^{-15}\times1.2=36\times10^{-15}\text{ C}$$

電子約22万個ぶん。

同じ材料と厚みのまま面積を半分にして15fFなら、18fC、約11万個ぶんしかないお。

**やらない夫**：
ビット線を0.6Vへプリチャージし、その容量を300fFとする単純な電荷共有模型では、1.2Vを蓄えたセルが作る電圧差はどうなる。

**やる夫**：
30fFのセルなら、

$$\Delta V_{30}=\frac{30\text{ fF}\times(1.2-0.6)\text{ V}}{300\text{ fF}+30\text{ fF}}\approx0.055\text{ V}$$

15fFなら、

$$\Delta V_{15}=\frac{15\text{ fF}\times(1.2-0.6)\text{ V}}{300\text{ fF}+15\text{ fF}}\approx0.029\text{ V}$$

ほぼ半分。

配線雑音、漏れ、検出増幅器のばらつきは都合よく半分にならないお。

**やらない夫**：
4Kbit、16Kbit、64Kbit、256Kbitと増えた歴史は、同じセルを写真縮小しただけか。

**やる夫**：
違うお。

DRAM密度は1973年の4Kbit、1976年の16Kbit、1979年の64Kbitへ進んだが、容量増加のたびに信号量を守る設計が必要だった。[^24]

DDR番号は外部インターフェースの世代で、製造線幅の番号でもない。

**小さくすれば数は増えるが、読める電荷まで一緒に削ってしまう**のがDRAM微細化の壁なんだお。

**やらない夫**：
では微細化を止めるか。

**やる夫**：
止めればビット単価と容量が伸びない。

平面の占有面積は減らしたまま、電気的なコンデンサ面積だけ取り戻す方法を探すお。

---
### 8-2　面積を減らして、面積を増やせ

**やる夫**：
電荷を戻すなら、コンデンサだけ元の面積へ戻すお。

……それではセルが小さくならないお。

**やらない夫**：
平面上の占有面積を増やさず、電極面積$A$を増やす方法は。

**やる夫**：
コンデンサの近似式は、

$$C=\varepsilon\frac{A}{d}$$

$d$を薄くすれば$C$は増えるけど、薄すぎれば漏れと絶縁破壊が増える。

誘電率$\varepsilon$の高い材料へ変える手もある。

そして平面が足りないなら、上へ柱を立てるか、下へ深い穴を掘って、側壁を面積として使うお。

**やらない夫**：
名前を付けるなら。

**やる夫**：
上へ作るスタックドキャパシタ、シリコンへ掘るトレンチキャパシタ。

IBMのDRAM技術史でも、平面構造では容量を保てなくなった4Mbit世代から、溝型と積層型という立体構造が本格化したと整理されている。セル容量は30〜40fF級を保つ必要があったお。[^53]

**やらない夫**：
高さ1μm、幅0.05μmの柱なら、アスペクト比は。

**やる夫**：
$$1\div0.05=20$$

細長い壁の奥まで均一に膜を付けないと、薄い場所から漏れ、厚い場所では容量が減る。

気体原料を一層ずつ反応させる原子層堆積（atomic layer deposition, ALD）なら、高アスペクト比の表面へ薄膜を均一に作りやすいお。

**やらない夫**：
上端だけ膜が2倍厚く、穴の底だけ半分なら合格か。

**やる夫**：
不合格だお。

上端は容量不足、底は漏れや絶縁破壊の弱点になる。

形を立体化しただけでは足りず、見えない側壁の全域を同じ品質に仕上げて初めて面積を使える。

Samsungも20nm DRAMで、微細化後も電荷量を保つ鍵として超薄膜誘電体とALDを挙げている。[^54]

**微細化は同じ図の縮小ではなく、立体構造、材料、成膜法を同時に変える仕事**だったんだお。

---
### 8-3　CPU工場へDRAMの設計図を持ち込む

**やる夫**：
CPUもDRAMもシリコン上のMOSFETだお。

最先端CPU工場へ1T1Cの設計図を渡せば、もっと細いDRAMがすぐ作れるお。

**やらない夫**：
CPU用ロジックが優先する物は。

**やる夫**：
トランジスタのスイッチ速度、リークと動作電力、複雑な配線、多数の金属層。

DRAMが優先するのは、巨大な同一配列、セル面積、保持時間、30fF級の容量、センス余裕、低いビット原価。

同じ「微細化」でも採点表が違うお。

**やらない夫**：
ロジック用の高速トランジスタをDRAMセルへ入れると。

**やる夫**：
漏れが増えれば保持時間が短くなる。

大きなトランジスタや深いキャパシタを足せば、高速ロジックの密度と配線を邪魔する。

IBMが高性能ロジックとトレンチDRAMを統合した研究でも、速度を上げる代わりに保持特性とセル面積が悪化する交換条件が報告されているお。[^55]

**やらない夫**：
では装置は全部別物か。

**やる夫**：
露光、成膜、エッチング、洗浄、イオン注入、検査という装置の大分類は重なる。

でもDRAMには深いキャパシタ加工、均一な高誘電率膜、巨大配列の試験と修復が要る。

ロジックには別のトランジスタ構造と多層配線の工程が要る。

レシピ、工程順、専用チャンバー、検査条件、歩留まり学習が違うから、CPUラインを来月そのままDRAMラインへは変えられないお。

**やらない夫**：
同じnmなら同じ工場能力か。

**やる夫**：
違う。

しかも10nm級のような世代名は、単一部品の実寸をそのまま表す定規でもない。

**CPUとDRAMは共通する道具を使うが、同じ縮小競争でも同じ製品工程でもない**んだお。

---
### 8-4　1ビット不良なら全部捨てる

**やる夫**：
1GbitのDRAMを検査したら、1列に2個だけ書けないセルがあったお。

不良品。1Gbit全部を砕くお。

**やらない夫**：
1024行×1024列の模型で、列417だけに2個の不良がある。

残る正常ビットはいくつだ。

**やる夫**：
ほぼ全部正常なのに、一列のために100万ビット級を捨てる。

容量が増えるほど「欠陥ゼロの巨大配列」へ賭けるのは不利だお。

なら予備列を作り、列417というアドレスを予備列へ付け替える。

行方向の不良には予備行。

検査後にヒューズや不揮発設定で置換を固定するお。

**やらない夫**：
それで出荷後の一時的なビット反転も直せるか。

**やる夫**：
製造時に固定された不良と、稼働中のソフトエラーは別だお。

チップ内では予備行・列で製造欠陥を隠す。Micronの製造教材でも、DRAMへ予備行・列を作り、検査で修復可能なダイを救う流れが示されている。[^56]

モジュールとメモリコントローラではECCで稼働中の誤りを訂正する。

システムでは巡回訂正、予備切替、二重化で劣化と停止へ備えるお。

**やらない夫**：
完全なセルを作るのを諦めたのか。

**やる夫**：
諦めたのは品質じゃない。

欠陥が一つもない偶然へ品質を預けることを諦めたお。

**やらない夫**：
なら予備を半分入れれば、もっと安心だな。

**やる夫**：
そんなに入れたら面積と原価が増え、正常セルを詰めた意味がなくなるお。

想定する欠陥分布と修復率を測り、少ない予備で救える配置にする必要がある。

**セル、チップ、モジュール、システムの各層で、違う種類の誤りを測って吸収する**んだお。

---
### 8-5　発明者が市場を支配するとは限らない

**やる夫**：
DRAMの回路特許を持つ会社が、その後も市場を独占するはずだお。

発明した者が一番強い。当たり前だお。

**やらない夫**：
64Kbit、256Kbitと世代が変わるたび、何をやり直す。

**やる夫**：
新しいマスク、工程、装置、材料、検査。

試作で動くことと、毎月大量に高歩留まりで出すことは別だお。

**やらない夫**：
ウェハ処理まで100万円、取れるダイが1000個の模型で計算してみるか。

**やる夫**：
歩留まり30%なら良品300個。

ウェハ処理費だけで、

$$1{,}000{,}000\div300\approx3{,}333\text{円/良品}$$

歩留まり80%なら良品800個で、

$$1{,}000{,}000\div800=1{,}250\text{円/良品}$$

同じ回路、同じウェハ費でも2.7倍近く違う。

歩留まり、稼働率、検査時間、次世代への立上げ速度が価格を決めるお。

**やらない夫**：
1980年代、量産の主役はどう動いた。

**やる夫**：
回路特許を取った会社が、そのまま永遠に勝ったわけじゃない。

日本勢が64Kbit、256Kbit世代で強くなったお。

**やらない夫**：
日本のVLSI共同研究と企業の量産投資は、64Kbit以上のDRAMで日本勢が優位になる一因になった。[^57]

256Kbit世代では日本企業の存在感がさらに強まり、技術競争が通商問題にもなった。[^24]

1986年の日米半導体協定は、日本市場へのアクセスとダンピング問題を扱い、1991年の協定へ続いた。[^25]

**やる夫**：
回路図だけでなく、工場能力、価格、国家間交渉まで1ビットの市場へ入ってきたのかお。

**やらない夫**：
値札ボードを更新してみるか。

**やる夫**：
記録例の公称1GB DDR2-533 DIMMが\$119。計算では1GiB相当と置くお。[^13]

$$\frac{8\times2^{30}}{119}\approx72{,}000{,}000\text{ ビット/\$}$$

| 項目 | 値 |
|---|---|
| 時代・製品 | 2005年、公称1GB DDR2-533 DIMM |
| 価格 | \$119 |
| \$1で買える記憶量 | 約72Mbit |
| 32GiB換算 | 約\$3808 |
| 注意 | 当時の記録例。名目価格 |

1970年の約100ビットから、とんでもなく増えたお。

**やらない夫**：
ただし、安くなった理由を1T1Cの発明一回へまとめるな。

微細化で苦しくなる電荷を立体構造と材料で守り、不良を予備へ逃がし、工場の歩留まりを上げ、次世代へ巨額投資し続けた結果だ。

**やる夫**：
**発明を、何億個も同じ品質で安く出すところまで運んだ企業が、各世代の主役になる**んだお。

---
## 第9幕　電源を切っても残せ、ただし壊れることは認めろ

---
### 9-1　ROMなら消えない。だから完成だ

**やる夫**：
DRAMは電源を切ると消える。

次は配線そのものを0と1にすればいいお。

つながっている配線を1、切れている配線を0にする。

電荷を置かないから更新もいらない。これで完成だお。

**やらない夫**：
その0を1へ書き換えるには。

**やる夫**：
工場へ戻して、配線を作り直す。

……完成してないお。

**やらない夫**：
二つの能力を一緒にするな。

- 電源を切っても残ること――**不揮発性（non-volatility）**
- 利用者が後から内容を変えられること――**書換可能性（rewritability）**

マスクROMは前者だけを持つ。

**やる夫**：
なら利用者がヒューズを焼くPROMだお。

1970年には、金属ヒューズを切って一度だけ書けるPROMが製品化されたお。[^58]

**やらない夫**：
書き間違えたら。

**やる夫**：
新しいチップを買う。

一度だけ書けるOTPだお。

**やらない夫**：
1971年のEPROMなら、石英窓から紫外線を当てて消せる。

電気で書き、光で全体を消し、また書ける。

**やる夫**：
PCオタクの箱に、窓へシールを貼ったBIOS ROMがあるお。

あれがEPROMか。

でもマザーボードから抜いて消去器へ入れる必要があるお。

**やらない夫**：
次は1970年代後半のEEPROMだ。

電気だけで消去と書込みができる。

**やる夫**：
なら今度こそ完成だお。

**やらない夫**：
EEPROMは細かく書き換えられる代わりに、セルや周辺回路が大きく、まとめて安く保存するには不利だった。

欲しい能力を並べ直せ。

**やる夫**：
電源を切っても残る。

何度も書き換えられる。

しかもDRAMのように小さく、磁気ディスクへ近づけるほど安い。

三つを同時に要求した瞬間、別の妥協が要るお。

---
### 9-2　絶縁体へ閉じ込めれば、電子は永遠に逃げない

**やる夫**：
DRAMはキャパシタの電荷が漏れた。

なら導線につながっていない小さな金属へ電子を閉じ込めるお。

絶縁体で囲めば逃げ道はないお。

**やらない夫**：
その島を浮遊ゲート（floating gate）と呼ぶ。

だが、完全に触れない島の電子をどう書き、どう読む。

**やる夫**：
矛盾したお。

閉じ込められるなら入れられない。

入れられるなら漏れるお。

**やらない夫**：
読む方から考えろ。

MOSFETはゲート電圧がある値を超えるとチャネルが導通する。その境目がしきい値電圧（threshold voltage, $V_\mathrm{th}$）だ。

浮遊ゲートへ電子があると電界が変わり、導通に必要なcontrolゲート電圧も変わる。

**やる夫**：
たとえば電子が少ないセルは2Vで入、電子が多いセルは5Vで入。

3Vをかけて電流が流れれば前者、流れなければ後者。

電子を直接数えず、トランジスタが入になる境目を読むのかお。

**やらない夫**：
そうだ。

書込みと消去では薄い酸化膜へ強い電界をかけ、電子を障壁の向こうへ通す。代表的な仕組みが**Fowler–Nordheimトンネル効果（Fowler–Nordheim tunneling）** だ。セル方式によってはホットエレクトロン注入（hot-electron injection）も使う。[^29]

**やる夫**：
量子力学のトンネルなら、絶縁体を壊さず電子だけ通せる。

これなら永久だお。

**やらない夫**：
強い電界を何度もかけた酸化膜は、何も起きなかった新品へは戻らない。

電荷を捕まえる欠陥が増え、しきい値が揺れ、保持した電子も少しずつ逃げる。

**やる夫**：
「不揮発」は「永久保存」ではないのかお。

**やらない夫**：
電源を切った瞬間に消えない、という分類だ。

実用品には別に、保持期間、書換回数、温度、誤り率という仕様がある。

**やる夫**：
DRAMは弱い電荷を頻繁に更新した。

フラッシュは強い操作で閉じ込める代わりに、書換えのたびに入口が摩耗する。

どちらも「電子を完全に支配した」のではなく、漏れ方と直し方が違うだけだお。

---
### 9-3　1バイトずつ消すのを諦めたら、フラッシュになった

**やる夫**：
EEPROMをそのまま小さく並べれば大容量になるお。

全ビットを個別に読み、個別に書き、個別に消す。

最高に自由だお。

**やらない夫**：
各セルへ個別消去の配線と選択回路を付ける面積は誰が払う。

**やる夫**：
また住所札が住人より大きくなる問題だお。

なら消去単位を大きくする。

64KiBを一群にして、全員まとめて消すお。

**やらない夫**：
その「一瞬にまとめて消す」発想からフラッシュという名が付いた。

東芝は1984年にNOR型フラッシュを発表し、1987年にNAND型フラッシュの動作原理を発表した。1991年には4Mbit NANDを製品化した。[^59]

**やる夫**：
NORとNANDは論理回路の名前と同じだお。

何が違うお。

**やらない夫**：
8セルの模型を作れ。

NOR型では各セルがビット線へ並列に近い形でつながる。狙ったセルを直接選びやすい。

NAND型では複数セルを直列の**ストリング**へ並べ、選ばないセルを通過状態にして目的セルを読む。

**やる夫**：
配線の共有が増えるから、NANDは1ビット当たりを小さくできる。

でも直列の途中1個だけを読むには、周りも制御しないといけないお。

**やらない夫**：
そこで用途が分かれた。

| 構造 | 得意なアクセス | 主な用途 | 妥協 |
|---|---|---|---|
| NOR型フラッシュ | バイト／ワード単位のランダム読出し | 組込みソフト、組込みコード | 面積とビット単価 |
| NAND型フラッシュ | ページ単位の読出し／書込み、ブロック単位の消去 | 写真、音楽、SSDなど大量データ | 細粒度の上書きと管理 |

**やる夫**：
PCのBIOS用NORと、SSD用NANDが別なのは偶然じゃない。

CPUがその場で命令を読むならランダム読出し。

大きなファイルを安く持つなら密度だお。

**やらない夫**：
「全部を細かく自由に書き換える」を捨てたから、大容量の不揮発メモリへ進めた。

ただしブロック消去を選んだ借金は、後で制御装置が返す。

---
### 9-4　0と1を保存するのをやめた

**やる夫**：
1セルへ1ビットなら、1Tbitには1兆セルが要る。

同じ浮遊ゲートへ電子を二倍詰めれば、2ビットにならないか。

電子なしを00、少しを01、もっとを10、満杯を11だお。

**やらない夫**：
今度は正しい。

保存しているのは電子数そのものより、結果として生じる複数のしきい値範囲だ。

**やる夫**：
0〜4Vの読取り窓を均等に割る模型なら、こうなるお。

| 呼称 | 1セルのビット数 | 状態数 | 1状態の理想幅 |
|---|---:|---:|---:|
| SLC | 1 | 2 | 2V |
| MLC | 2 | 4 | 1V |
| TLC | 3 | 8 | 0.5V |
| QLC | 4 | 16 | 0.25V |

状態数は$2^b$。

同じセル数ならQLCはSLCの4倍のビットを売れるお。

**やらない夫**：
その表の電圧は説明用で、実製品の値ではない。

さらに実物のしきい値は一本の線でなく分布になる。製造ばらつき、隣接セルの干渉、保持中の電荷漏れ、書込み／消去の摩耗で山が広がり、動く。

**やる夫**：
QLCは16本の細い箱に16個の山を収める。

隣の山と重なれば、0110を0111と読む。

容量を増やした代金を、速度、耐久性、誤り率で払うのか。

なら読取り境界を理想どおり0.25V刻みへ固定すればいいお。

**やらない夫**：
製造直後と、書換えを重ねた後と、高温で長く保持した後で、山の位置が同じならな。

実際の制御装置は状態に応じて読出ししきい値を変え、失敗すれば別の境界で読出しを再試行する。

**やる夫**：
1セルのビット数だけを4倍にしたのではない。

書込みの精密さ、読取り回数、ECC、管理回路まで増やして4ビットを成立させるお。

**やらない夫**：
Samsungが示す製品世代の一例では、2006年の1ビットSLC、2010年の2ビットMLC、2012年の3ビットTLC、2018年の4ビットQLCへ進んでいる。これは各方式の発明年ではなく、高密度製品が市場へ広がった時期の目安だ。[^60]

**やる夫**：
PCのSSD売場で「TLCだから駄目」「QLCだから全部遅い」と型名だけで断言するのも雑だお。

世代、制御装置、並列数、キャッシュ、用途まで見ないと製品性能は決まらない。

でも物理の出発点として、状態を増やすほど判定余白が狭いのは消えないお。

---
### 9-5　曖昧な電圧から、正しいビット列を再生しろ

**やる夫**：
しきい値の山が狭いなら、一発で狙った電圧まで電子を注入する。

QLCの13番目へぴたりと止めるお。

**やらない夫**：
ばらつくセルへ大きなパルスを一回かけたら、行き過ぎた電子を一セルだけ簡単に戻せない。

**やる夫**：
では小さなパルスをかけ、読む。

まだ目標より低ければ、もう一度パルスをかけ、また読む。

**書込み・検証**を繰り返すお。

**やらない夫**：
それでも未管理データの誤りはゼロにならない。

8ビットのデータへ1ビットのパリティを足すだけでは、奇数個の誤りを検出できても、どのビットを直すか分からない。

**やる夫**：
検査ビットを複数置き、重なる組合せから故障位置を逆算する。

1950年のハミング符号なら、適切な冗長ビットで1ビット誤りを訂正できる。[^61]

複数ビットが壊れるなら、1959〜1960年に成立したBCH符号のような強い符号へ進むお。

**やらない夫**：
さらに高密度NANDでは、1962〜1963年にGallagerが示した**LDPC（Low-Density Parity-Check）符号**が、半世紀後の制御装置で重要になった。

理論が古くても、反復復号を高速に回せる回路と、必要とする媒体が揃う時期は別だ。

**やる夫**：
Hamming、BCH、LDPCを年代順の製品規格だと思ってはいけない。

数学の誕生年と、NANDで主役になる年が違うお。

**やらない夫**：
LDPCにはもう一つ武器がある。

読出し電圧3Vで0か1かだけを返すのが**hard判定**。

2.8V、3.0V、3.2Vと何度か読み、「0寄りだが境界に近い」という確信度まで渡すのが**soft判定**だ。

**やる夫**：
三つのセルを、単なる`1 0 1`でなく、

`1に99% / 0に51% / 1に98%`

としてdecoderへ渡す。

パリティが合わなければ、51%の真ん中を疑えるお。

**やらない夫**：
複数の読出ししきい値から軟判定情報を得てLDPC復号へ使う研究は、硬判定より強い訂正と、追加読出しによる遅延・エネルギーの交換条件を示している。[^62]

**やる夫**：
第1幕の電信と同じだお。

弱った波形をそのまま保存するのではない。

「本当はどの記号だったか」を冗長な規則から再生する。

NANDは石の箱ではなく、雑音のある通信路を内側に抱えたメモリなんだお。

---
### 9-6　不良ブロックがある製品を出荷してよい

**やる夫**：
ECCで直せるとしても、工場で不良ブロックが見つかったチップは捨てるべきだお。

新品に不良があるなんて商品じゃないお。

**やらない夫**：
1024ブロックの試作品で、20ブロックまで使えない可能性があるとデータシートに書いてあったら。

**やる夫**：
良品は最低1004ブロック。

悪いブロックへ書かず、1004以上を保証容量として売ればよい。

……不良があることと、製品仕様を満たさないことは同じではないお。

**やらない夫**：
KIOXIAの未管理NANDデータシートにも、使用不能ブロックが含まれる場合があり、システム側で検出して使わないよう管理すること、ECCと書込み平準化を組み込むことが明記されている。[^63]

**やる夫**：
出荷時の不良ブロックを印で知らせる。

運用中に書込み／消去へ失敗したブロックも退役させる。

予備ブロックへ論理住所を付け替える。

使える容量、訂正できる誤り率、書換寿命を測って等級を分けるお。

**やらない夫**：
DRAMの予備行・列と似ているが、境界が違う。

DRAMではチップ内の修復を外から見えないようにすることが多い。

未管理NANDでは不良-ブロック管理やECCをホスト／制御装置へ要求する製品もある。

**やる夫**：
完全な石を選ぶのではない。

欠陥の場所と増え方を測り、予備と符号で吸収し、外から見える契約を守るお。

**やらない夫**：
では、その未管理NANDを1990年代のデジタルカメラへ直結してみろ。

**やる夫**：
写真を保存するだけなら簡単だお。

……いや、カメラ側がページ、ブロック、不良ブロック表、ECC、論理住所、ファイルシステムを全部知ることになる。

メモリチップを交換しただけで組込みソフトを書き直す羽目だお。

**やらない夫**：
次の発明は、セルではない。

その複雑さを、どちら側へ置くかという境界線だ。

---
## 第10幕　NANDを「カード」という商品に閉じ込める

---
### 10-1　NANDをカメラへ直結すれば最安だ

**やる夫**：
1991年に4Mbit NANDが製品になった。

8個並べれば、

$$4\text{ Mbit}\times8=32\text{ Mbit}=4\text{ MiB}$$

デジタルカメラへ直接はんだ付けするお。

制御装置を省けば安いお。

**やらない夫**：
写真1枚を上書きするとき、NANDのブロック全体をどう扱う。

**やる夫**：
同じブロックの残したいページをRAMへ読む。

ブロックを消す。

新しい写真と残すページを書き戻す。

途中で電池が切れたら……管理表ごと消えるお。

**やらない夫**：
ほかにも必要だ。

- 出荷時と運用中の不良ブロックを避ける
- ページごとにECCを付け、読出し時に訂正する
- 同じブロックだけが摩耗しないよう書込みを分散する
- カメラのファイル名やdirectoryを、NANDの物理ページへ対応付ける
- NAND世代が変わってもカメラ側のソフトウェアを壊さない

**やる夫**：
カメラの組込みソフトがNAND制御装置になった。

新しいチップへ交換するたびページサイズや命令や必要ECCが変わるなら、カメラメーカーが全部追従することになるお。

**やらない夫**：
そこでカードの中へNANDと小さな制御装置を入れ、外には安定したブロック接続規格を見せる。

ホストは「セクタ12345を書け」と頼む。カード内部は、そのセクタをどの物理ページへ置くか決める。

**やる夫**：
NANDの欠陥を消したのではなく、カードの内側へ隠した。

ホストと媒体の境界を決めたのかお。

**やらない夫**：
ただし全カードが同じ境界を選んだわけではない。

制御装置をカード側へ置けば交換互換性を得やすいが、カードは高く厚くなる。

ホスト側へ置けばカードは薄く安くできるが、ホストが媒体差を背負う。

1990年代のメモリカード競争は、形の競争であると同時に、**誰がNANDの面倒を見るか**の競争だった。

**やる夫**：
つまり制御装置を置く場所まで含めてカード構成だお。

単にNANDへプラスチックの殻をかぶせただけではないお。

---
### 10-2　財布に七種類の「標準」を入れる

**やる夫**：
PCオタクの発掘箱から出てきたお。

PC Card、CompactFlash、SmartMedia、MMC、Memory Stick、SD、xD-Picture Card。

全部「標準」なのに、全部形が違うお。

**やらない夫**：
市場が一つの正解へ瞬時に収束すると思うな。

年代と設計思想を並べろ。

| 登場時期 | 形式 | 外から見せるもの／管理の置き場所 | 狙った市場 |
|---:|---|---|---|
| 1990年代前半 | PC Card ATA Flash | PC Card／ATA。制御装置はカード側 | ノートPC PC、業務機器 |
| 1995〜1996年 | CompactFlash | 小型化したPC Card／PATA。制御装置はカード側 | デジタルカメラ、PDA |
| 1995年ごろ | SmartMedia | 薄いcontrollerlessカード。フラッシュ管理はホスト側 | 薄型カメラ、音楽機器 |
| 1997年 | MMC | 少ピンの直列接続規格とカード内管理 | 携帯機器 |
| 1998年 | Memory Stick | SonyのAV／PC生態系 | カメラ、音楽、PC |
| 2000年 | SD | MMCに近い小型シリアルカードを業界規格化 | カメラから携帯機器全般 |
| 2002年 | xD-Picture Card | 小型カメラ向けの専用色が強い形式 | Olympus／Fujifilmカメラ |

**やる夫**：
PC Card ATAとCompactFlashは、PCから見ると小さなIDEドライブに近い。

CF内部の制御装置がNAND、ECC、defectを処理し、外へATA命令を見せる。[^64]

SmartMediaは逆に制御装置を省き、カメラや読み取り機がフラッシュを管理する。

薄く安くできるが、大容量世代へホストを追従させる負担が残るお。

**やらない夫**：
Memory Stickは1998年、4MBが3300円、8MBが4400円で発売された。PC Card組まで用意し、AV機器とPCで画像・音・データを交換する構想だった。[^65]

xD-Picture Cardは2002年、16／32／64／128MBから始まり、カメラの小型化と大容量化を掲げた。[^66]

**やる夫**：
どれも当時の要求には理由がある。

大きいがPC互換性の高いCF。

薄いSmartMedia。

自社AV製品をつなぐMemory Stick。

カメラをさらに小さくするxD。

後から勝者だけ見て「最初からSDでよかった」と言うのは歴史を逆再生しているお。

なら万能カードリーダーを一台作り、変換器で全部SD相当に見せれば統一できるお。

**やらない夫**：
接点の形を変えるだけで、ATAとシリアル命令とホスト管理型未管理フラッシュを同じ会話にできるか。

変換器自身が複数通信規約と媒体管理を実装するなら、それは単なる変換器でなく制御装置だ。

**やる夫**：
形の変換だけで規格差は消えない。

互換性とは、物理形状、電気信号、命令、容量表現、管理責任をどこまで共通化したかだお。

**やらない夫**：
では主流になった線を追え。

1997年のMMCは小型のシリアルカードを示した。その延長上でPanasonic、SanDisk、東芝が2000年1月にSD Associationを設立し、競合各社が使えるSD規格を整備した。[^67]

**やる夫**：
規格化はピン数と命令を紙に書くだけじゃない。

カードメーカー、カメラメーカー、PC用カードリーダー、OS、ファイルシステム、ロゴ、適合試験が同じ境界を守る必要がある。

1社の良いカードより、複数社のカードと複数社のホストが入れ替わる生態系の方が強いお。

---
### 10-3　同じ形なら、古い読み取り機でも読める

**やる夫**：
SDカードの外形はほとんど同じだ。

2GBの古いカードが読める読み取り機なら、2TBも読めるはずだお。

住所が増えるだけだお。

**やらない夫**：
住所の表し方とファイルシステムが変わらなければな。

**やる夫**：
また「形」と「通信規約」と「容量」が別の層だったお。

**やらない夫**：
SD Associationが定める容量区分を並べろ。[^68]

| 規格 | 規格上の容量範囲 | 標準ファイルシステム | 登場の節目 |
|---|---:|---|---:|
| SD | 2GB以下 | FAT12／FAT16 | 2000年 |
| SDHC | 2GB超〜32GB | FAT32 | 2006年 |
| SDXC | 32GB超〜2TB | exFAT | 2009〜2010年 |
| SDUC | 2TB超〜128TB | exFAT | 2018年 |

**やる夫**：
`SDXC`は単に「容量の大きいSD」という商品名ではない。

アドレス指定とファイルシステムを含むホストとの契約だお。

FAT16しか知らない2001年のカメラへ64GB SDXCを挿しても、同じ接点だから読めるとは限らないお。

**やらない夫**：
互換性には向きがある。

新しいSDXCホストは通常、SDXCだけでなくSDHCとSDも扱う。

古いSDホストは、後から定義されたSDHCやSDXCを理解しない。[^69]

**やる夫**：
後方互換性（backward compatibility）は「新しい側が古い約束も話す」ことだお。

古い側へ未来の単語を理解させる魔法ではないお。

**やらない夫**：
さらに、市販容量と規格上限も区別しろ。

初期SD規格の上限は2GBだったが、2000年に市場へ出たカードは8MB級だった。[^70]

規格が2GBの住所を用意しても、その日に2GB NANDを安く量産できるわけではない。

**やる夫**：
逆にNANDだけ大容量になっても、住所とファイルシステムとホストが追いつかなければ商品にならない。

セルの大容量化と、外部規格の大容量化は別々に進み、製品で合流するお。

---
### 10-4　最大170MB/sなら、25MB/sの動画は必ず撮れる

**やる夫**：
カードの箱に最大170MB/sと書いてある。

25MB/sで記録する動画なら6倍以上余裕だお。

**やらない夫**：
その170MB/sは読出しか書込みか。瞬間最大か最低保証か。専用読み取り機が必要か。

**やる夫**：
小さい字は読まない主義だお。

……録画停止の原因を自分で作る主義だったお。

**やらない夫**：
カメラに必要なのは、撮影中ずっと下回らない**最低連続書込み速度**だ。

SDの速度classはそこを記号にした。[^71]

| ロゴ | 最低連続書込み速度 |
|---|---:|
| C2／C4／C6／C10 | 2／4／6／10MB/s |
| U1／U3 | 10／30MB/s |
| V6／V10／V30／V60／V90 | 6／10／30／60／90MB/s |

**やる夫**：
25MB/sの動画なら、C10やU1の10MB/s保証では足りない。

U3かV30なら30MB/s以上を保証するから条件を満たす。

箱の「最大読出し170MB/s」だけでは判定できないお。

**やらない夫**：
一方、スマホでアプリをカードへ置くと、小さなファイルをばらばらに読む。

連続動画と違い、ランダム読出し／書込み回数が体感を左右する。

**やる夫**：
そこで2016年のA1、2017年のA2という**Application Performance Class**か。

A1はランダム読出し1500 IOPS、ランダム書込み500 IOPS、逐次10MB/s以上。

A2は4000／2000 IOPSと10MB/s以上。ただしA2ホストの支援が必要だお。[^72]

**やらない夫**：
一枚のカードに、容量規格、バス規格、最低連続速度、アプリケーション性能が別々に印刷される理由が分かったか。

**やる夫**：
`SDXC UHS-I U3 V30 A2`は呪文ではない。

- SDXC――容量とファイルシステムの世代
- UHS-I――ホストとのバス方式
- U3／V30――最低連続書込み30MB/s
- A2――ランダムアクセスの最低性能と対応ホスト条件

別の問いへの答えを一行へ重ねているお。

### 10-5　接点を増やさず、SSD並みに速くしろ

**やる夫**：
SDの9接点を高速クロックにすれば、永遠に速くできるお。

同じ信号線へ毎秒何兆回でもビットを流すお。

**やらない夫**：
信号波形、電圧、雑音、消費電力が許さない。

SDのdefault speedは12.5MB/s、2004年のHigh Speedは25MB/sだった。

2010年ごろのUHS-Iは1列目の接点を使いながら最大104MB/sへ上げた。[^73]

**やる夫**：
その先は二列目の接点を足す。

2011年のUHS-IIが最大156または312MB/s。

2017年のUHS-IIIが最大624MB/s。

外形を保ちつつ、裏面の通信路を増設したお。

**やらない夫**：
では2018年のSD Expressで、また独自バスを伸ばし続けたのか。

**やる夫**：
違う。

PCのSSDで普及したPCI ExpressとNVMeをカードの二列目へ持ち込んだ。

現行概要ではPCIe Gen4×2まで用い、理論上3940MB/s級へ進んでいるお。[^73]

**やらない夫**：
古いホストへ挿したら。

**やる夫**：
一列目のlegacy SD接続規格へfallbackする。

ただしSD ExpressカードはUHS-IIモードを兼ねるわけではない。同じ二列目に見えても、そこで話す通信規約が違うお。[^74]

**やらない夫**：
また形だけでは判断できないな。

**やる夫**：
しかも3940MB/sはバスの上限。

NANDの並列数、制御装置、発熱、カード容量、書込み状態が実効速度を決める。

DDRでMT/sと待ち時間を分けたのと同じで、接続規格の看板と媒体の実力を分ける必要があるお。

**やらない夫**：
ここで見ているのはNANDセルの改良ではない。

外へ見せる標準接続規格が、直列SDからUHS、さらにPCIe／NVMeへ進んだ歴史だ。

**やる夫**：
大容量化にはセル、使いやすさには制御装置、交換可能性には規格、高速化にはバス。

一枚のカードでも、別々の発明が積み重なっているお。

### 10-6　4MiBで\$2万から、爪先の1TBへ

**やる夫**：
値札ボードへ戻るお。

Masuokaの証言にある初期カメラ試作は、4Mbit NANDを8個使った4MiB級で、システム全体が約\$2万だった。[^15]

記憶部分だけの価格ではないけれど、カメラを成立させるシステム価格として割ると、

$$\frac{4\times2^{20}\times8}{20{,}000}\approx1{,}678\text{ ビット/\$}$$

\$1で約1700ビットだお。

**やらない夫**：
その値を現在のカード単価と同じものとして比較してよいか。

**やる夫**：
駄目だお。

試作カメラシステムと量産メモリカードでは、含むものも時期も違う。

ここでは桁がどう動いたかを見る粗い物差しだお。

**やらない夫**：
市販品の節目も置け。

**やる夫**：
PCパーツの年表みたいに、容量と規格名を分けて並べればいいお。

**やらない夫**：
2000年の初期SDは8MB級。

2002年のxDは16〜128MBで登場。

2005年の初期microSDは32／64／128MB。

2019年には1TB microSDXCが発表され、SanDisk Extreme 1TBの希望小売価格は\$449.99だった。[^75]

**やる夫**：
では2019年の値札を、10進表記の公称1TBで計算するお。

$$\frac{8\times10^{12}}{449.99}\approx17{,}800{,}000{,}000\text{ ビット/\$}$$

値札を表にするお。

| 時代・製品 | 製品単位 | 価格 | \$1で買える記憶量 | 注意 |
|---|---|---:|---:|---|
| 1990年代初頭の試作カメラ | 4MiB級 | 約\$2万 | 約1.7Kbit | システム全体の価格 |
| 2019年microSDXC | 公称1TB | \$449.99 | 約17.8Gbit | 10進容量の量産カード |

**やらない夫**：
1990年代初頭の試作システム比で1000万倍級か。

**やる夫**：
しかも爪ほどのカードの中に、NANDダイ、制御装置、ECC、不良-ブロック管理、通信規約が入る。

安くなったのはセルだけのおかげじゃない。

微細化と多値化でビットを増やし、工場の歩留まりを上げ、制御装置が不完全なNANDを商品へ変え、標準化が大市場を作ったお。

**やらない夫**：
では、写真を持ち運ぶカードが、電話の中へ常駐したら何が変わる。

**やる夫**：
カメラなら撮影時に連続書込み、後でPCへ複製すればよかった。

スマホはOS、アプリ、写真、動画、通信キャッシュを一日中読み書きする。

着脱カードだけでなく、基板へ直接載せるeMMCやUFSが欲しくなるお。

**やらない夫**：
2007年以後、NANDは「デジタルフィルム」から、常時動く携帯コンピュータの内蔵記憶装置へ役割を広げる。

次は、その境界を作り直す。

## 第11幕　スマホがDRAMとNANDを再会させる

---
### 11-1　PC用DDRを小さく載せればよい

**やる夫**：
2007年のiPhoneは4GBまたは8GBの記憶装置で登場した。[^76]

中身はPCの小型版だお。

SO-DIMMを短く切り、DDR2を載せればよいお。

**やらない夫**：
切るな。

まず電池で動かせ。

**やる夫**：
PCなら壁の差込口がある。

スマホは画面を消した待機中にも、着信、時計、ネットワークを生かす。

DRAMが速くても、I/Oと終端へ電流を流し続けたら電池が先に尽きるお。

**やらない夫**：
基板も見ろ。

SIMカード、無線回路、カメラ、電源回路、アプリケーションプロセッサ、電池の間にDIMM差込口を置く場所があるか。

**やる夫**：
ない。

交換用差込口、長い配線、終端抵抗まで、携帯機器では面積と電力の負債になる。

PC用DDRを低いクロックで使うだけでは、待機電力と実装面積を解けないお。

**やらない夫**：
そこで低消費電力DDR（Low-Power Double Data Rate, LPDDR）は、電圧を下げ、細かな電力状態を持ち、短い一対一配線でSoCへつなぐ方向へ進んだ。

代表的な節目を並べる。ただし、何年を表す表だ。

**やる夫**：
規格公開年と、その規格を使った代表製品の発表年を混ぜずに書くお。

同じ世代名でも、規格と製品が同じ日に出るわけじゃないお。

**やらない夫**：
その留保を付けた代表例がこれだ。

| 年 | 世代・出来事 | 代表的な1ピン当たり転送レート | ここで増えたもの |
|---:|---|---:|---|
| 2009年 | Mobile DDR製品例 | 400Mbit/s | 携帯向けの小容量・低電力化 |
| 2011年 | LPDDR2製品例 | 1066Mbit/s | 高速化と低電圧化 |
| 2012年 | LPDDR3製品例 | 1600Mbit/s | カメラ・動画処理向け帯域 |
| 2014年 | LPDDR4規格・製品世代 | 3200Mbit/s級 | チャネル分割と省電力 |
| 2016年 | LPDDR4X製品世代 | 4266Mbit/s級 | I/O電圧をさらに低下 |
| 2018〜2019年 | LPDDR5開発・量産製品 | 6400Mbit/s級 | 深い休止状態と帯域効率 |
| 2021〜2022年 | LPDDR5X開発・検証製品 | 8500Mbit/s級 | 携帯機器AI向け帯域 |
| 2025年 | LPDDR6規格公開 | 規格で次世代化 | 2副チャネル、効率・信頼性 |

Samsungの代表製品史とMicronの資料では、LPDDR4／4Xは4266Mbit/s級、LPDDR5は6400Mbit/s級へ進み、LPDDR4XはLPDDR4の1.1V I/Oに対して0.6V I/Oを使う。2025年7月にはJEDECがLPDDR6規格を公開した。[^77]

**やらない夫**：
表のMbit/sを、そのままDRAMセル配列の基準クロックだと思うな。

**やる夫**：
DDR5-6400の店頭表示を分解した第6幕と同じだお。

これは主にピン当たりの実効転送レートで、内部配列の動作速度そのものではない。

LPDDRは世代ごとにクロック方式や先読み数、チャネル構成も変わるから、単純に2で割って全世代共通の基準クロックにはできないお。

**やらない夫**：
電圧低下の効果だけなら、簡単な模型で見られる。

I/Oの切替エネルギーを$E\propto CV^2$とし、同じ容量を1.1Vから0.6Vへ振るなら。

**やる夫**：
$$\left(\frac{0.6}{1.1}\right)^2\approx0.30$$

約3割だお。

ただし実機の総電力が7割減るという意味ではない。

別の電源配線、周波数、終端、配線容量、制御装置の動作もあるお。

**やらない夫**：
その留保まで含めて正解だ。

**やる夫**：
携帯機器用メモリは、PC用DRAMを遅くしたものではない。

**眠っている時間を安くしながら、起きた瞬間の帯域を増やすDRAM**へ設計の重心を変えたんだお。

### 11-2　microSDだけを本体記憶装置にする

**やる夫**：
NANDは第10幕でカードになった。

スマホにもmicroSD差込口を付け、OSもアプリも写真も全部そこへ置けばよい。

容量不足なら差し替えられる最強設計だお。

**やらない夫**：
地図アプリがデータベースを書換えている最中に、利用者がカードを抜いた。

**やる夫**：
ファイルシステムと更新中のデータが壊れる。

では「抜かないでください」と背面へ赤字で……。

**やらない夫**：
利用者をねじで固定するな。

同じmicroSDという表示でも、ランダムアクセス、制御装置、NAND世代、摩耗状態が違う。

OSの起動時間をカード売場の選び方へ委ねるのか。

**やる夫**：
カメラの交換媒体なら、撮影して後で抜く設計でもよかった。

OSの内部記憶装置は、常時接続、予測可能な機能、電源管理、組込みソフト更新を本体側で管理したい。

交換可能性と引換えに、基板へ直接はんだ付けする理由が出たお。

**やらない夫**：
MMCの接続規格と管理機能を、組込み用パッケージへ閉じ込めたのがeMMC、組込みMultiMediaCardだ。

中にはNANDと制御装置があり、外には標準化されたブロック装置として見える。[^78]

**やる夫**：
未管理NANDならSoC側がページサイズ、ECC、不良ブロックを知る。

eMMCならパッケージ内の制御装置がそれを隠し、ホストはlogicalブロックを読む。

第10幕のカード制御装置を、抜けないチップへしたようなものだお。

**やらない夫**：
年代を置け。

**やる夫**：
eMMCは2000年代後半から携帯機器で普及し、2013年のeMMC 5.0、2015年2月公開のeMMC 5.1へ進んだ。

5.1では命令待ち行列も導入されたが、基本は8ビットの並列バスを共有するお。[^78]

**やらない夫**：
本体へ固定したため、失ったものは。

**やる夫**：
利用者が容量を増設できない。

NANDだけ故障してもパッケージ交換、場合によっては基板修理になる。

だが小さく、接触不良がなく、ホストとメモリの組合せをメーカーが検証できる。

**交換可能性を捨てた代わりに、実装面積と制御可能性を買った**んだお。

### 11-3　eMMCの一本道へ仕事が詰まる

**やる夫**：
eMMC 5.1に命令待ち行列があるなら完成だお。

カメラで4K動画を書きながら、写真を読み、アプリを更新しても制御装置が並べ替えるお。

**やらない夫**：
荷物を予約できても、橋が一車線ならどうなる。

**やる夫**：
eMMCは並列のデータ線を読出しと書込みで共有する。

書いている間は読めず、向きを切り替える待ちもある。

SoCが速くなり、カメラとアプリが同時に要求を出すと、一本の会話が詰まるお。

**やらない夫**：
では線を128本にするか。

**やる夫**：
第6幕でバス幅を増やし続けられないとやった。

ピン、配線、電力、パッケージ面積が増える。

携帯機器で欲しいのは、少ない線で速く、複数の仕事を待たせない接続規格だお。

**やらない夫**：
Universal Flash Storage、UFSは差動直列接続を使い、送信側と受信側の経路を分け、命令待ち行列で複数要求を扱う。

eMMCとUFSの違いは、NANDセルの種類ではなく、ホストとの会話の設計にもある。[^79]

**やる夫**：
規格公開年と採用製品の年を分けた年表が要るお。

**やらない夫**：
では、規格と代表製品を同じ列へ書くときは、その区別を明記する。

| 年 | 規格または製品の節目 | 読み方 |
|---:|---|---|
| 2011年 | UFS 1.0規格 | 携帯機器向け直列記憶装置の土台 |
| 2013年 | UFS 2.0規格 | 高速化と待ち行列処理 |
| 2015年 | 128GB UFS 2.0量産製品、Galaxy S6採用 | 規格が旗艦スマホへ入る |
| 2018〜2020年 | UFS 3.0から3.1 | 接続高速化と書込み性能管理 |
| 2022年 | UFS 4.0規格・対応製品 | 2レーンで世代更新 |
| 2025年 | UFS 4.1規格 | 4.0互換を保ち機能改善 |
| 2026年 | UFS 5.0規格 | 2レーンで約10.8GB/s級の接続規格へ |

**やらない夫**：
2015年の実物を一台置け。

**やる夫**：
Galaxy S6だお。

**やらない夫**：
Galaxy S6は公称3GB LPDDR4と、32／64／128GBのUFS 2.0記憶装置を採用した。[^80]

Samsungの同社製品例では、eMMC 5.1の逐次読出し250MB/sに対し、2019年のUFS 3.0は2100MB/s、2020年のUFS 3.1も読出し2100MB/s級とされた。[^79]

これは各規格の保証上限ではなく、特定世代の製品値だ。

**やらない夫**：
2025年と2026年の行も、店に並んだ台数を表すのではない。

**やる夫**：
規格が公開された年だお。

**やらない夫**：
2025年1月のUFS 4.1、2026年2月のUFS 5.0は、対応制御装置、SoC、検証済み製品が普及する時期とは分けて読む。[^81]

**やる夫**：
規格年表と店頭製品史は、同じ時間軸でも一段ずれるんだお。

**やらない夫**：
では、この高速化でTLCがSLCへ戻ったのか。

**やる夫**：
戻っていない。

**NANDセルを変えなくても、直列接続、待ち行列、同時読出し／書込み、制御装置の処理順制御で外から見える性能を上げられる**。

第10幕のSD Expressと同じく、媒体と接続規格は別の改良軸だお。

### 11-4　DRAMとNANDを一つの黒い箱へ押し込む

**やる夫**：
LPDDRパッケージとUFSパッケージを基板へ並べれば完成だお。

小さなチップを二つ置くくらい、誤差だお。

**やらない夫**：
その誤差を150mm²取り戻せたら、メーカーは何を置く。

**やる夫**：
大きな電池、カメラ、アンテナ。

スマホでは1mm²が商品機能へ変わる。

DRAMと記憶装置を近づけるパッケージの工夫が要るお。

**やらない夫**：
似た略語を分けろ。

**やる夫**：
PoP、eMCP、ePoP、uMCP。

名前が似すぎて、PCのメモリ型番より悪質だお。

**やらない夫**：

- PoP、Package on Package――アプリケーションプロセッサの上へ主にDRAMパッケージを積む
- eMCP、組込みMulti-Chip Package――DRAMとeMMC系NANDを一つのパッケージへ収める
- ePoP、組込みPackage on Package――DRAMとeMMCをまとめ、さらにプロセッサ上へ積める形にする
- uMCP、UFS型複数チップパッケージ――LPDDRとUFSを一つのパッケージへ収める

プロセッサまで積層構造へ含むか、DRAMと記憶装置だけを束ねるかが違う。[^82]

**やる夫**：
略語を覚えるより、**何を同じ交換単位へ閉じ込めたか**を見ればいいのかお。

**やらない夫**：
2015年のePoP例を測れ。

**やる夫**：
Samsungの公称3GB LPDDR3＋32GB eMMC ePoPは、別パッケージ構成の374.5mm²から225mm²へ実装面積を縮めた。

$$374.5-225=149.5\text{ mm}^2$$

約40%の削減だお。[^82]

**やらない夫**：
一つにしたら、DRAMとNANDも同じメモリになったか。

**やる夫**：
ならない。

LPDDRはCPUの作業中のデータをns級で繰り返し読む揮発性メモリ。

UFSは電源を切っても残す記憶装置で、内部では制御装置がNANDを管理する。

黒いパッケージを共有しても、アドレス空間、通信規約、待ち時間、寿命は別だお。

**やらない夫**：
統合の代償は。

**やる夫**：
片方だけを増設できない。

故障時の交換単位が大きくなり、熱、パッケージ歩留まり、調達の組合せも厳しくなる。

**短い配線と小さな面積を得るほど、修理と構成変更の自由をパッケージへ渡す**んだお。

---
### 11-5　同じGBなら、RAM不足を記憶装置で埋められる

**やる夫**：
いまや1TBスマホがある。

ならRAMは2GBで十分だお。

足りない作業データを1TB側へ置けば、合計1002GBメモリだお。

**やらない夫**：
PCオタクがその足し算をするな。

写真を撮るアプリ、画像編集アプリ、browserを同時に開け。

**やる夫**：
2GB RAMが埋まる。

OSが背景アプリを終了させ、戻るたびUFSからcodeとデータを読み直す。

写真は残るが、編集中の展開画像や実行状態を同じ速度では保持できないお。

**やらない夫**：
三つの節目を比較しろ。

**やる夫**：

| 年・製品 | 主記憶 | 内蔵記憶装置 | 注記 |
|---|---:|---:|---|
| 2007年 初代iPhone | 公式発表では容量記載なし | 4／8GB | スマホ市場の出発点 |
| 2015年Galaxy S6 | 公称3GB LPDDR4 | 32／64／128GB UFS 2.0 | LPDDR4とUFSが同居 |
| 2024年Galaxy S24 Ultra | 公称12GB | 256／512GB／1TB | 携帯機器AI世代の一例 |

AppleとSamsungの公式発表で確認できる値だけを置いた。[^76][^80][^83]

初代iPhoneのRAM容量は別資料で推定せず、公式発表にないと明記したお。

**やらない夫**：
仮想メモリやswapなら、記憶装置をRAMに見せられるだろう。

**やる夫**：
見かけのアドレス空間は広げられる。

でもUFSアクセスはDRAMより桁違いに遅く、NANDには書換寿命と消去単位がある。

OSが圧縮、ページ退避、アプリ再起動を使っても、12GB LPDDRを2GB LPDDR＋10GB UFSへ等価交換したことにはならないお。

**やらない夫**：
では、同じGBは何を数えている。

**やる夫**：
保存できるバイト数だけだお。

**主記憶のGBは「いま何を同時に働かせられるか」、記憶装置のGBは「電源を切って何を持ち帰れるか」を主に買っている**。

スマホはLPDDRとNANDを同じ基板、時には同じパッケージへ再会させた。

それでも二つの役割は溶けなかったお。

---
## 第12幕　SSDは小さなコンピュータだった

---
### 12-1　住所100番は、物理ブロック100番に置く

**やる夫**：
メモリカードを大きくしてPCへ挿せばSSDだお。

ホストがLBA 100へ書いたデータは、NANDの物理ブロック100へ置く。

住所が同じなら制御装置も要らないお。

**やらない夫**：
同じlogファイルを1000回更新しろ。

**やる夫**：
ブロック100だけ1000回消去され、ほかの99ブロックは新品のまま。

100ブロックへ順番に逃がせば、単純化した模型では各ブロック10回で済む。

$$\frac{1000\text{ 回}}{100\text{ blocks}}=10\text{ 回/ブロック}$$

住所を固定すると、利用者の書込みの偏りが物理寿命の偏りになるお。

**やらない夫**：
しかもNANDはページをその場で自由に上書きできない。

新しい場所へ書き、古いページを無効にし、後で有効ページを集めてブロックを消す。

**やる夫**：
ならホストの論理ブロックアドレス、LBAと、NANDの物理ページアドレスを対応表で分ける。

これがFlash Translation Layer、FTLだお。

**やらない夫**：
FTLが引き受ける仕事を並べろ。

**やる夫**：
住所変換、別の場所への更新、摩耗と不良の回避……まだあるのかお。

**やらない夫**：

- 論理／物理アドレス変換――LBAを空いている物理ページへ割り当てる
- 別場所更新（out-of-place update）――更新データを別ページへ書き、旧ページを無効化する
- 書込み平準化――消去回数が偏らないよう配置を動かす
- 不良ブロック管理――出荷時・運用中の不良ブロックを避ける
- GC（garbage collection）――有効ページを移し、無効ページの多いブロックを消して再利用する
- TRIM――OSが不要になったLBAをSSDへ知らせ、移動すべき有効データを減らす

実装方式は製品ごとに違うが、論理住所と物理場所を分けてNANDの制約を隠す点は共通する。[^84]

**やる夫**：
セルを丈夫にした機能一覧じゃない。

**壊れ方と消し方を知る制御装置が、住所の意味を守っている**んだお。

**やらない夫**：
電話交換の選択は、行と列の交点を選んだ。

DRAMは行と列でセルを選んだ。

FTLでは何を選ぶ。

**やる夫**：
LBA 100という名前から、制御装置がその時点の物理ページを選ぶ。

更新のたびに場所が変わってよい。

**選択の到達点は、指定された住所にビットが物理的に存在する必要すらないこと**だお。

---
### 12-2　データを書けば、停電しても書込み完了だ

**やる夫**：
FTL表はDRAMへ置けば速い。

`LBA 100 → 物理ページ7`を`物理ページ91`へ更新し、データBを書けばよい。

NANDは不揮発だから停電にも強いお。

**やらない夫**：
順番を試せ。

現在はページ7にAがある。

まずページ91へBを書き、対応表を変える前に電源を切る。

**やる夫**：
再起動後の表はページ7を指す。

BはNANDに残っているのに、最新データとして見つけられない。

では先に表をページ91へ変えるお。

**やらない夫**：
表を変えた直後、Bの書込み途中で切る。

**やる夫**：
今度は表が未完成ページを指す。

順番を逆にしただけでは、どちらかの窓で壊れるお。

**やらない夫**：
何を「書込み完了」と呼ぶかが足りない。

**やる夫**：
データページだけでなく、再起動後に最新の対応を選べる管理情報まで、矛盾なく残った状態だお。

世代番号と検査和を付けた記録、更新履歴、古い対応を残す書込み時複製（copy-on-write）、起動時走査などを組み合わせる。

制御装置固有の方式は違っても、途中状態から最後の整合した世代を選べる必要があるお。

**やらない夫**：
企業向けSSDで、コンデンサを載せる理由は。

**やる夫**：
突然外部電源が消えても、電源断保護（power-loss protection, PLP）が短時間だけ制御装置とNANDを動かし、揮発性キャッシュや管理情報の処理を完了させるためだお。

すべての消費者向けSSDが同じPLPを持つわけではないお。[^85]

**やらない夫**：
第1幕では、書込みはスイッチを入にすることだと思っていた。

**やる夫**：
SSDではもっと長い。

**書込みとは、再起動後にも論理データを再構成できる状態まで契約を守ること**だお。

不揮発なセルがあるだけでは、不揮発なシステムにはならないお。

---
### 12-3　NANDを8個並べれば8倍になる

**やる夫**：
SSDを高速化するのは簡単だお。

NANDチャネルを8本にし、同時に8ページ読めば8倍だお。

**やらない夫**：
やる夫SSDの模型を測った。

1チャネルを100とすると、8チャネルで340だった。

**やる夫**：
3.4倍。

詐欺性能測定だお。

**やらない夫**：
お前の組込みソフトだ。

同じチャネルのbusyなダイへ順番に命令を投げ、書込み完了を待ってから次へ進んでいる。

裏ではGCも同じチャネルを塞いでいる。

**やる夫**：
空いているチャネルとダイへ読出しを先に出す。

一方が書込みパルスと検証を繰り返す間に、別ダイのページを転送する。

ホスト要求、GC、管理情報更新を依存関係の許す範囲で並べ替えるお。

**やらない夫**：
再測定は690だ。

**やる夫**：
6.9倍。

この100→340→690は処理順制御効果を見る架空の模型で、市販SSDの測定値ではない。

理想の800へ届かないのは、チャネル競合、制御装置処理、NANDの読出し／書込み／消去時間、GCが残るからだお。

**やらない夫**：
制御装置メーカーがNANDを替えるたび、ピンと命令を全部作り直すのか。

**やる夫**：
それを避ける境界がOpen NAND Flash Interface、ONFIだ。

2006年12月のONFI 1.0は共通の電気接続規格、命令、parameterページを定め、最大50MB/s級から始まった。

2026年のONFI 6.0は4800MT/sを標準化したお。[^86]

**やらない夫**：
50MB/sと4800MT/sを同じ単位のように割るな。

**やる夫**：
前者はバイト転送率、後者は接続規格のtransfer回数で、世代間に信号方式もある。

ここで見るのは倍率ではなく、NANDと制御装置の境界が2006年から2026年まで更新されたことだお。

**やらない夫**：
ONFIはPCとSSDの規格か。

**やる夫**：
違う。

ホスト――SSD間がSATAやNVMe。

SSD制御装置――NAND間がONFIの担当だお。

**セルを変える高速化と、命令順・チャネル・ダイ並列性で速くする高速化を分離できた**お。

---
### 12-4　SATAへつなげばHDDより速い

**やる夫**：
SSDはPCへつなぐのだからSATAでよい。

HDDと同じコネクタならOSもBIOSもそのまま使える。

互換性こそ正義だお。

**やらない夫**：
正義だが、無料ではない。

SATA 6Gbit/s系は実効上限が約600MB/s級で、AHCIのNative Command Queuingは1装置当たり最大32命令だ。[^87]

8コアが大量の小さなI/Oを出すとどうなる。

**やる夫**：
一つの短い列へ集まり、driverと制御装置がlockを奪い合う。

NAND側に8チャネルあっても、ホスト側の受付がHDD時代の狭い窓だお。

**やらない夫**：
そこでPCI Express上の不揮発メモリ向けに、NVM Express、NVMeが作られた。

NVMe 1.0は2011年3月に公開された。[^88]

**やる夫**：
submission待ち行列、SQへホストが命令を書く。

待ち行列のtailが進んだとdoorbellレジスタで制御装置へ知らせる。

制御装置はダイレクトメモリアクセス、DMAで命令とデータを運び、完了を完了キュー、CQへ書く。

interruptをコアへ振り分ければ、多数の待ち行列を並行に扱えるお。

**やらない夫**：
数の桁は。

**やる夫**：
NVMe構成は最大64K級のI/O待ち行列と、各待ち行列最大64K級の命令を扱える設計だ。

実製品が常に上限まで実装する意味ではないが、AHCIの1装置当たり32命令とは発想の桁が違うお。[^88]

**やらない夫**：
NANDセルのしきい値分布は変わったか。

**やる夫**：
変わらない。

**メモリの進歩が、セル、制御装置、バスを越え、OSとCPUコアが仕事を渡す入口まで来た**んだお。

互換性のためSATAを使うSSDと、並列性を生かすNVMe SSDが、同じNANDを別の性格の商品にするお。

---
### 12-5　箱の最高速度で100GBを複製する

**やる夫**：
発売日前に新作ゲームの100GBを導入するお。

箱に逐次書込み2000MB/sとあるから、50秒で終わるお。

導入画面を見ている間に飲み物を取りに行く暇すらないお。

**やらない夫**：
最初の20GBは2000MB/s、その後は400MB/sだった。

計算し直せ。

**やる夫**：
最初は、TLCやQLCの一部を1ビット/セルのように使うSLCキャッシュへ入る。

20GBを2000MB/sなら約10秒。

キャッシュが埋まった後の80GBは、

$$\frac{80\text{ GB}}{0.4\text{ GB/s}}=200\text{ s}$$

合計210秒、平均は、

$$\frac{100\text{ GB}}{210\text{ s}}\approx476\text{ MB/s}$$

箱の数字から4倍以上ずれたお。

**やらない夫**：
この20GBと速度は仕組みを見る架空の例だ。

実際のキャッシュ容量や速度は製品、空き容量、組込みソフト、温度で変わる。

**やる夫**：
短い性能測定の間はSLCキャッシュがバーストを受ける。

長い書込みでは多値セルへ移す速度が表へ出る。

さらにGCが有効ページを移し、空きブロックを作る仕事も競合するお。

**やらない夫**：
連続負荷で制御装置とNANDが熱くなった。

**やる夫**：
温度上限へ近づけば、動的な熱制御が性能を段階的に下げてデータ信頼性を守る。

Samsungの消費者向けSSD説明にも、SLCキャッシュ、数百GB級の転送時の性能抑制、熱制御が明記されているお。[^89]

**やらない夫**：
故障か。

**やる夫**：
必ずしも故障ではない。

キャッシュ、GC、温度という内部状態で、同じドライブの速度が時間とともに変わる。

SDカードで最大読出しとV30の最低持続書込みを分けたのと同じだお。

**最大帯域幅だけでなく、瞬間性能と持続性能を別々に問わないと、実際の仕事時間は読めない**お。

---
### 12-6　1TBより多いNANDを隠している

**やる夫**：
1TB SSDを分解したら、利用者に見えない容量がある。

買ったNANDを隠す容量詐欺だお。

**やらない夫**：
まず単位を揃えろ。

架空の「やる夫SSD」は、物理側に1TiB、利用者へ10進の1TBを見せるとする。

**やる夫**：
$$2^{40}=1{,}099{,}511{,}627{,}776\text{ バイト}$$

利用者の$10^{12}$バイトとの差は、

$$1{,}099{,}511{,}627{,}776-1{,}000{,}000{,}000{,}000=99{,}511{,}627{,}776\text{ バイト}$$

user容量を分母にした予備領域率率は約9.95%。

未管理容量を分母にすれば約9.05%だお。

**やらない夫**：
その領域で何をする。

**やる夫**：
不良ブロックの代替、GC中の逃し場所、書込み平準化、制御装置の管理情報、製品設計によってはECC用領域を支える。

空き場所がなければ、1ページ更新するたび有効データを何度も移し、性能と寿命が悪化する。

**隠した容量は、見える1TBを長く同じLBAとして見せる作業場**なんだお。

**やらない夫**：
ただし市販の「1TB」という表示だけから、必ず1TiBのNANDが載るとは断定できない。

**やる夫**：
ダイ容量、製造時の不良ブロック、ECCの置き方、可変SLCキャッシュ、組込みソフト予約領域は製品ごとに違う。

さっきの1TiB→1TBは予備領域率を計算する模型で、全製品の部品表ではないお。

**やらない夫**：
値札ボードを更新しろ。

**やる夫**：
2008年9月のIntel X25-Mは80GBのMLC SATA SSDで、1000個購入時の公表価格が\$595だった。

$$\frac{80\times10^9\times8}{595}\approx1.08\times10^9\text{ ビット/\$}$$

値札はこうなるお。[^90]

| 時代・製品 | 製品単位 | 価格 | \$1で買える記憶量 | 注意 |
|---|---|---:|---:|---|
| 2008年Intel X25-M | 公称80GB SSD | \$595 | 約1.08Gbit | 1000個購入時の公表価格 |
| 2019年microSDXC | 公称1TBカード | \$449.99 | 約17.8Gbit | SSDとは保証性能が異なる |

同じ年のPC用ドライブとしては高価だが、250MB/s級読出し、10チャネル、書込み平準化を含む制御装置と組込みソフトまで商品だったお。

**やらない夫**：
2019年の1TB microSDは約17.8Gbit/\$だったな。

**やる夫**：
単純なビット単価なら約16倍だが、11年の差があり、カードとSSDでは接続規格、並列度、耐久設計、性能保証が違う。

容量だけで価格を裁けないお。

**やらない夫**：
SSDの中に何が入った。

**やる夫**：
複数チャネルのNAND、制御装置コア、SRAMやDRAM、ECC、FTL、処理順制御器、GC、書込み平準化、PLP、SATAまたはNVMe接続規格、組込みソフト。

**SSDはNANDを箱へ入れただけではない。NANDの不都合を隠し、LBAという約束を守る専用コンピュータだった**お。

**やらない夫**：
その小さなコンピュータでも、平面のセルを縮め続ければ容量は増やせるか。

**やる夫**：
第9幕のQLCはしきい値窓を16分割した。

横へ縮めればセル間干渉と漏れが増え、判定余裕がさらに狭くなる。

土地が足りないなら――次は上へ積むしかないお。

## 第13幕　平面を諦め、上へ積む

---
### 13-1　平面のセルを、もう半分に縮める

**やる夫**：
SSDの次世代機は簡単だお。

平面NANDの縦横を0.7倍にすれば、セル面積は約0.49倍。

同じ面積へ約2倍置ける。

これを毎世代繰り返せばよいお。

**やらない夫**：
第9幕の0〜4V模型へ、QLCの16状態を置き直せ。

隣り合う代表値の間隔を単純化して0.25Vとする。

**やる夫**：
セルが十分大きいとき、製造ばらつき、書換え劣化、保持中の電荷移動をまとめた分布幅が、代表値から左右0.08Vだったとする。

隣との空きは、

$$0.25-0.08\times2=0.09\text{ V}$$

まだ判定境界を置けるお。

**やらない夫**：
縮小して電荷量が減り、隣接セルとの干渉が強くなり、幅が左右0.15Vになった。

**やる夫**：
$$0.25-0.15\times2=-0.05\text{ V}$$

分布が0.05V重なる。

この数値は実製品のしきい値仕様ではなく、余裕が消える構造を見る模型だお。

**やらない夫**：
面積だけなら約2倍だ。

だが読めるビット数も約2倍になったか。

**やる夫**：
書込み・検証を細かくし、soft判定とLDPCを強くすれば救える。

でも読出し回数、待ち時間、制御装置の仕事が増える。

**平面を縮めて得た面積を、狭くなった電圧余裕の補修費が食べ始める**お。

**やらない夫**：
土地の区画を細くする以外に、同じ土地へ部屋を増やす方法は。

**やる夫**：
……上へ建てる。

平屋を顕微鏡で縮め続けるのではなく、高層住宅へするお。

NANDセルを垂直方向へ並べれば、平面寸法を同じ率で縮めなくてもビットを増やせる。

これが3D NANDの出発点だお。

---
### 13-2　24階から300階を超える

**やる夫**：
平面NANDを完成させ、その上へもう一枚、その上へもう一枚貼る。

完成チップを321枚接着すれば321層だお。

**やらない夫**：
高さだけで冷蔵庫になるぞ。

完成ダイを重ねるHBMとは作り方が違う。

3D NANDでは、まず多数の薄膜をウェハ上へ交互に積み、まとめて深い穴を開ける。

**やる夫**：
穴の中央へ垂直チャネルを通す。

穴の側壁と各ワード線が交わる高さごとに、電荷を蓄えるセルを作る。

一本のチャネルストリングへ、縦方向に何十、何百セルも並ぶのかお。

**やらない夫**：
Samsungが2013年に量産開始を発表した最初のV-NANDは、24層、128Gbitだった。[^91]

2024年にはSK hynixが321層、1Tbit TLC NANDの量産開始を発表し、2025年には321層、2Tbit QLC品の量産開始を発表した。[^92]

**やる夫**：
層数だけなら、

$$\frac{321}{24}=13.375$$

約13.4倍だお。

では同じダイ面積なら容量も必ず13.4倍だお。

**やらない夫**：
周辺回路、層間接続、dummy層、横方向のセル密度、TLC／QLC、plane数は同じか。

**やる夫**：
違う。

24層と321層の比は高さの目安で、製品ビット密度の倍率ではないお。

積層数が増えても、穴を分割して接続する境界や、使えない端部、周辺回路の面積が増えるお。

**やらない夫**：
2026年のKIOXIAの技術説明は、400層超へ増やす案と比べ、332層を選ぶほうがウェハ原価、電力、セル信頼性の均衡で有利だという自社推定を示した。[^92]

**やる夫**：
「最大積層数」がそのまま「最小ビット原価」ではないのか。

高い建物ほど家賃が下がるなら、東京は無料住宅だお。

**やらない夫**：
そんなわけねぇだろ、常考。

**やる夫**：
3D NANDは一人が一つの構造を発明して終わった話でもない。

電荷捕獲型、周辺回路をセル配列の下へ置く方式、別ウェハで作って接合する方式、複数回に分けて穴をつなぐ方式を、各社が異なる名前と工程で競っている。

**上へ増やす自由を得た代わりに、何層をどう作ると最も安く歩留まりよくなるかが新しい設計問題になった**お。

### 13-3　300階を一本の穴で貫く

**やる夫**：
321層分の膜を積み、上からdrillで一発。

真っすぐな穴を開ければ量産完成だお。

**やらない夫**：
上の直径を1とし、下へ行くほど0.2%ずつ細くなる架空の食刻を、300段続けろ。

**やる夫**：
単純な掛け算なら、

$$0.998^{300}\approx0.549$$

底は上の約55%しかない。

セルごとのチャネル形状が高さで変わり、読出し電流としきい値も揃わないお。

**やらない夫**：
実際の欠陥は単純な指数形だけではない。

上広がり、穴の湾曲、途中の曲がり、穴ごとの傾き、マスク消耗、底へ反応種が届かない問題が重なる。

**やる夫**：
第8幕でDRAMコンデンサの深い側壁を原子層堆積、ALDで覆った。

3D NANDでも、深い穴へ均一な膜を作る成膜と、高aspect ratioの深掘り食刻が主役になる。

最先端とは、細線を描く競争だけではなかったお。

**やらない夫**：
Lam Researchは2024年、10μmまでのメモリチャネルを上下の寸法偏差0.1%未満で加工する将来向け極低温エッチングを発表し、400層以降を対象に挙げた。[^93]

では、300層を一度に掘ることだけが解か。

**やる夫**：
複数の短い積層群に分けて穴を掘り、位置を合わせて電気的につなぐストリングstackingがある。

SK hynixの321層品は三回の接続部工程を接続し、低応力材料とalignment補正を使う。[^92]

ただし接続回数を増やすと、今度は積層群同士のずれと接続抵抗が増えるお。

**やらない夫**：
セル配列とCMOS周辺回路を同じウェハへ順番に作る必要もあるか。

**やる夫**：
別々のウェハで最適条件を使って作り、最後に接合するウェハ接合もある。

KIOXIAのCBAは、CMOS回路ウェハとメモリセル配列ウェハを別工程で作って接合する構成だお。[^94]

**やらない夫**：
膜を何百層も積めば、各膜の応力は。

**やる夫**：
ウェハ全体で足し合わさって反る。

焦点と重ね合わせがずれ、次の穴と配線が合わなくなる。

裏面へ補償膜を付けて反りを抑える仕事まで必要になる。[^93]

**高さを増やすこと自体が、穴形状、接続ずれ、膜応力、ウェハ反りという次の製造誤差を増やす**。

上へ逃げても、量産の壁は上まで追いかけてきたお。

### 13-4　1本を100Gbit/sにすればHBMはいらない

**やる夫**：
NANDは容量のために上へ積んだ。

DRAMも同じだお。

GPU用DRAMは積まず、基板上のデータ端子を1本100Gbit/sにすればよいお。

**やらない夫**：
長い基板配線を高速に振るほど、反射、漏話、タイミングのずれ、I/Oエネルギーはどうなる。

**やる夫**：
厳しくなる。

第6幕でバス幅を増やし続けられず、第11幕で携帯機器の配線を短くした。

なら今度はメモリをGPUのすぐ隣へ置き、一本を魔法の速度にせず、短い線を大量に並べるお。

**やらない夫**：
DRAMダイを薄くし、シリコンを縦に貫くシリコン貫通電極（through-silicon via, TSV）で積み、基準ダイを介して1024ビット級の広い接続規格を外へ出す。

GPUや演算加速器とはシリコン中間基板などの微細配線で結ぶ。

これが高帯域幅メモリ（High Bandwidth Memory, HBM）だ。

**やる夫**：
2019年発表、2020年量産のHBM2E例を計算するお。

1ピン当たり3.6Gbit/s、1024 I/Oなら、

$$\frac{3.6\times1024}{8}=460.8\text{ GB/s}$$

公表値の460GB/s超と一致するお。[^95]

**やらない夫**：
2024年のHBM3E 12H例は、1024 I/O、10Gbit/s級だ。

**やる夫**：
$$\frac{10\times1024}{8}=1280\text{ GB/s}$$

1積層体で1.28TB/s、公称容量36GBだお。[^96]

**やらない夫**：
2025年に公開されたHBM4規格は、接続規格を2048ビットへ倍増し、規格上8Gbit/sまでとした。

**やる夫**：
$$\frac{8\times2048}{8}=2048\text{ GB/s}$$

2TB/s級だお。

規格公開年と、特定メーカーの量産・顧客採用年は別に読むお。[^97]

**やらない夫**：
3D NANDとHBMは、どちらも縦に積む。

同じ発明か。

**やる夫**：
違う。

3D NANDは、一つのウェハ内に垂直セルストリングを作り、主にビット密度と容量を増やす。

HBMは、別々に作ったDRAMダイをパッケージ工程で積み、主に短く極端に広い接続規格で帯域を増やす。

**NANDは容量のため、HBMは帯域のために上へ積む**。

積むという外見が同じでも、作る場所と解く律速箇所が違うお。

### 13-5　良品率95%を8枚積めば760%だ

**やる夫**：
良品率95%のDRAMダイを8枚積む。

95%が8枚だから、景気よく760%の超良品HBMだお！！

**やらない夫**：
確率を足すな。

無作為に取った8枚が全部良品である確率を掛けろ。

**やる夫**：
$$0.95^8\approx0.6634$$

約66.3%しかない。

1枚なら95%売れたダイを、検査せず積むと3積層体に1積層体近くがダイ不良を含む模型になるお。

**やらない夫**：
実際のHBM歩留まりを66.3%と断定してよいか。

**やる夫**：
駄目だお。

95%は架空の独立確率で、実際には不良の相関、修復、基準ダイ、組立歩留まり、検査精度がある。

だから積層前に検査し、良品判定済みダイ（Known Good Die, KGD）を選ぶお。

**やらない夫**：
KGDを選べば100%か。

**やる夫**：
検査で見逃す潜在不良がある。

ダイthinningで割れ、TSVやmicro-bumpがopen／shortになり、接合にvoidが入り、積層体全体が反り、熱が抜けにくくなる。

積層後にも検査と修復が要るお。

**やらない夫**：
2024年のSamsung HBM3E 12Hは、24Gbitダイを12枚積んで公称36GBとし、8段品と同じパッケージ高さへ収めるためダイ間を7μmまで縮め、反りと放熱を接合材料と突起配置で扱った。[^96]

**やる夫**：
セル配列を作ったら完成ではない。

ウェハ検査、良品選別、薄化、TSV、接合、アンダーフィル、熱設計、積層後検査まで続く。

**HBMには、DRAMセル工場の後ろにもう一個の工場がある**お。

3D NANDでもセル工程が立体化し、HBMでは後工程が立体化する。

立体化は、面積を節約する魔法ではなく、製造工程を別の方向へ増やす選択だったお。

### 13-6　値札のないHBMを1ビット単価にする

**やる夫**：
値札ボードへHBMを追加するお。

通販で公称80GB HBMを一個買って、価格を容量で割る。

……商品ページがない。

**やらない夫**：
HBMは一般DIMMのように単体小売される部品ではなく、演算加速器メーカーとのパッケージ設計と顧客契約へ組み込まれる。

正確な取引価格がないなら、どうする。

**やる夫**：
でっち上げるお。

**やらない夫**：
帰れ。

**やる夫**：
……仮定を明記し、答えを一点でなく範囲にするお。

架空のAI演算加速器を\$3万、搭載HBMを公称合計80GBとする。

製品価格のうちHBMへ割り当てる仮定を、6分の1から3分の1まで振るお。

**やらない夫**：
計算しろ。

**やる夫**：
HBMへ割り当てる額は\$5000〜1万。

80GBを公称10進容量とすれば、

$$\frac{80\times10^9\times8}{10{,}000}=64{,}000{,}000\text{ ビット/\$}$$

$$\frac{80\times10^9\times8}{5{,}000}=128{,}000{,}000\text{ ビット/\$}$$

中間の4分の1、\$7500なら約85.3Mbit/\$だお。

**やらない夫**：
これはHBMの市場価格か。

**やる夫**：
違う。

演算加速器価格もHBM原価比も架空の感度分析だお。

値札ボードには、仮定を列として残すお。

| 時代・製品 | 容量の仮定 | HBM割当額の仮定 | \$1で買える記憶量 | 注意 |
|---|---:|---:|---:|---|
| 現代のHBM搭載演算加速器 | 公称80GB | \$5000〜1万 | 推定64〜128Mbit | 製品価格からの感度分析。市場価格ではない |

**やらない夫**：
第12幕のIntel SSD価格とは何が違う。

**やる夫**：
X25-Mは公表された製品価格から計算した。

HBMは公開小売価格がないため、製品全体から仮に配賦した。

**正確な値が出ないとき、仮定を隠して精密な数字を作るのではなく、仮定を振って結論の桁が変わるかを見る**。

ビット単価の安さでは負けても、HBMはビットを演算器へ1秒で何回届けられるかを買うメモリだお。

## 第14幕　CPUの隣だけでは容量が足りない

### 14-1　AI演算加速器にはHBMだけ載せる

**やる夫**：
HBMは1積層体で1.28TB/s級。

もうDDR5は全部捨てて、サーバーのメモリをHBMだけにするお。

速いものだけ残すのがPC自作の基本だお。

**やらない夫**：
架空の演算加速器へ、公称36GB HBM3Eを8積層体載せる。

容量と理論帯域を出せ。

**やる夫**：
$$36\text{ GB}\times8=288\text{ GB}$$

$$1.28\text{ TB/s}\times8=10.24\text{ TB/s}$$

実効帯域は制御装置やアクセスパターンで下がるが、看板値は圧倒的だお。

**やらない夫**：
500GBの模型の重みと、200GBのKVキャッシュを同時に置け。

**やる夫**：
合計700GB。

288GBへ入らない。

HBMを20積層体に増やせば公称720GBだお。

**やらない夫**：
演算加速器ダイの周囲へ20積層体を置く面積、中間基板配線、パッケージ歩留まり、消費電力、熱は。

**やる夫**：
計算器よりメモリパッケージが外周を占領する。

HBMは速いが、容量を無限に増やす最安の置き場ではないお。

**やらない夫**：
一方、公称128GB DDR5 RDIMMを24枚載せる架空のホストなら。

**やる夫**：
$$128\text{ GB}\times24=3072\text{ GB}$$

3TB級だお。

Micronは32Gbitダイを使う公称128GB DDR5 RDIMMを製品化しており、サーバー基盤にはさらに大容量の3DS RDIMM構成もあるお。[^98]

**やらない夫**：
ではDDR5だけに戻るか。

**やる夫**：
それでは大量の演算器がメモリを待つ。

頻繁に使う重みと中間データをHBMへ置き、大きいが相対的に冷たいデータをホストDDR5へ置く。

必要に応じて階層間を運ぶお。

**HBMは大帯域、DDR5 RDIMMは大容量を主に担当し、二つで記憶階層を作る**。

最高のメモリ一種類へ統一するより、異なる高価さを適材適所へ置くほうがシステム全体を成立させるお。

### 14-2　DIMMの形は永遠に変わらない

**やる夫**：
PCメモリの形は決着したお。

desktopはUDIMM、サーバーはRDIMM、ノートPCはSO-DIMM。

DDR5になってもチップだけ速くし、基板はDDR4を色違いで使えばよいお。

**やらない夫**：
DDR5モジュールをDDR4差込口へ挿してみろ。

**やる夫**：
切欠きもピン配置も違う。

破壊動画の撮影は中止するお。

**やらない夫**：
形だけでなく、モジュール境界で何が変わった。

**やる夫**：
DDR4の64ビットデータチャネル一つから、DDR5ではモジュールを二つの独立32ビット副チャネルへ分けた。

ECC RDIMMなら各副チャネルに追加8ビットが付き、40ビットずつになる。

電圧調整器の仕事もマザーボード側から、モジュール上の電源管理IC、PMICへ寄せたお。[^99]

**やらない夫**：
オンダイECCが入ったから、サーバー用ECC DIMMは不要か。

**やる夫**：
オンダイECCはDRAMチップ内部の128ビットに8ビットのパリティを持ち、内部の単一ビット誤りを読出し時に訂正する。

だがチップからCPUまでのデータ線、コネクタ、別チップ故障は保護範囲外だ。

**製造微細化を支えるon-ダイECCと、システム全体を守るECC DIMMは同じ名前でも階層が違う**お。[^99]

**やらない夫**：
SO-DIMMも永遠か。

**やる夫**：
薄型ノートPCでは差込口の高さと配線長が邪魔になる。

LPDDRをはんだ付けすれば薄く低電力だが、交換不能になる。

そこで基板へ水平に圧着し、低背と交換性を両立するCAMM2が出るお。

**やらない夫**：
年代と状態を分けろ。

**やる夫**：

| 年 | 名称 | 主な狙い | 2026年時点での読み方 |
|---:|---|---|---|
| 2020年 | DDR5規格公開 | 2副チャネル、PMIC、オンダイECC | PC／サーバーで量産普及 |
| 2023年 | CAMM2規格公開 | DDR5またはLPDDR5/5Xを低背・交換可能に | コネクタ共通でも両者の端子配列は別 |
| 2024年 | LPCAMM2量産製品 | LPDDR5Xを公称16〜64GBの交換モジュールに | ノートPC向け製品が登場 |
| 2024〜2026年 | MRDIMM製品・標準化作業 | ランクを多重化しサーバー帯域を増やす | 製品名とJEDEC標準の進行を区別 |

JEDECは2023年にJESD318 CAMM2を公開し、Micronは2024年にLPDDR5X LPCAMM2を公称16〜64GBで製品化したお。[^100]

**やらない夫**：
MRDIMMの行が曖昧だな。

**やる夫**：
製品名として先に使われたMRDIMMと、複数企業間の相互運用標準が同じ段階なのか分からないお。

**やらない夫**：
2024年には8800MT/s級の製品がMRDIMM名で出た一方、JEDEC MRDIMM標準はまだ策定中だった。

2026年4月にJEDECはデータ緩衝回路標準を公開し、第2世代モジュール標準は完成へ向けて進行中、12,800MT/sを目標と説明した。[^101]

**やる夫**：
同じ略語でも、特定基盤で動く製品と、業界標準として相互運用できる段階を混ぜてはいけないお。

**やらない夫**：
DIMMの歴史は終わったか。

**やる夫**：
終わらない。

**モジュールは単なるDRAMチップの台ではなく、電源、信号バッファ、管理情報、冷却、交換性の境界**だお。

CPU、筐体、用途が変われば、最適な形もまた変わるお。

### 14-3　差込口が足りなければマザーボードを広げる

**やる夫**：
12チャネルに128GiB RDIMMを一枚ずつ挿せば1.5TiB。

2TiB必要なら、差込口を外側へ延長し、巨大マザーボードを作るお。

**やらない夫**：
CPUから最遠差込口まで50cmになった。

DDR5の多数の並列線を、その距離で同じタイミング余裕に揃えられるか。

**やる夫**：
信号品質が崩れ、基板層数、コネクタ、ピン数も増える。

CPUパッケージが持つメモリチャネル数も固定だ。

DIMMを置く面積だけ増やしても、CPU側の入口が増えないお。

**やらない夫**：
第12幕でPCIeへNVMeをつないだ。

同じ物理層の系譜を使いながら、ブロックI/Oでなく読込み／書込みに近いメモリの意味体系を運べないか。

**やる夫**：
CPUが`アドレスXを読み込め`と要求し、遠いDRAMをシステムメモリの一部として読む。

PCIe差込口の先をSSDとしてファイルI/Oするのではない。

メモリ制御装置の外へ、キャッシュ整合性を保つメモリ通信規約を伸ばすお。

**やらない夫**：
それがCompute Express Link、CXLだ。

CXL.ioは装置発見と管理、CXL.memはホストから装置メモリへの読込み／書込み、CXL.cacheは対応演算加速器がホストメモリをキャッシュする用途を担う。

DRAMを載せるType 3装置は主にCXL.ioとCXL.memを使う。[^102]

**やる夫**：
CXLの規格年表を、製品普及年と分けるお。

| 公開年 | 規格 | 主な追加 |
|---:|---|---|
| 2019年3月 | CXL 1.0 | CPUと装置を直接接続し、キャッシュ整合性を維持 |
| 2020年11月 | CXL 2.0 | スイッチ、メモリプール化、活線接続 |
| 2022年8月 | CXL 3.0 | 接続網、多段切替、メモリ共有 |

### 15-2　消えないなら、DRAMとSRAMを追放できる

**やる夫**：
最初の候補は強誘電体RAM（ferroelectric RAM, FRAM）だお。

強誘電体の分極を右向きと左向きへ切り替え、電界を外した後も向きを残す。

電荷を浮遊ゲートへ押し込むNANDより低エネルギーで速く書け、高い書換え耐久性を狙える。[^106]

これをDRAMの1T1Cへ入れれば、更新不要DRAMの完成だお！！

**やらない夫**：
従来型1T1C FRAMを読め。

既知の電圧を加えて分極が反転したか、流れた電荷差で判定する。

保存状態と逆向きの電圧を加えたセルはどうなる。

**やる夫**：
読むために分極を反転させた。

……また破壊読出しだお。

読んだ値を検出amplifierで判定し、書き戻す必要がある。[^106]

磁気コアとDRAMで見た構造が、材料を替えて帰ってきたお。

**やらない夫**：
容量は。

**やる夫**：
強誘電体コンデンサ、選択トランジスタ、検出回路が要る。

同時代のNANDと同じビット単価を、速さと耐久性だけからは導けない。

FRAMは状態と書込みで強くても、読出し方式、セル面積、工程統合まで無条件に勝つわけではないお。

**やる夫**：
なら磁気抵抗RAM（magnetoresistive RAM, MRAM）だお。

固定層と自由層を絶縁膜で挟むMTJ（magnetic tunnel junction）を作る。

日本語では磁気トンネル接合だお。

磁化が平行なら低抵抗、反平行なら高抵抗。

読んでも磁化を反転させなければ非破壊だお。

**やらない夫**：
自由層の磁化を、熱揺らぎに対してどれだけ安定させる。

**やる夫**：
エネルギー barrierを$E_b$、絶対温度を$T$とすれば、熱安定性の目安は

$$\Delta=\frac{E_b}{k_B T}$$

だお。

$\Delta$を40から60へ上げた模型なら、熱で障壁を越える頻度は$e^{20}$、約4億8500万分の1へ下がる。

保持には圧倒的に有利だお。

**やらない夫**：
その障壁を、書込み時にはどうする。

**やる夫**：
スピンの揃った電流で自由層へ角運動量を渡す、スピン移行トルク（spin-transfer torque, STT）を使う。

だが保持のため障壁を高くすると、短時間で確実に反転させる電流とエネルギーも厳しくなる。[^107]

**消えにくくした同じ壁を、書込みだけは越えなければならない**お。

**やらない夫**：
DRAMとSRAMを追放するか。

**やる夫**：
用途の容量、書込み頻度、待ち時間、温度、原価を入れてから判定する。

FRAMもMRAMも“不揮発で速い”は本当だが、その一文は選択と工場と価格を免除する合格証ではないお。

### 15-3　抵抗を二つ作るだけなら、セルは一素子でよい

**やる夫**：
コンデンサも磁石も面倒だお。

材料の抵抗を高低二状態にすれば、交差する二本の線の間へ一素子を置くだけでよい。

まず相変化RAM（phase-change memory, PCM）。

結晶状態を低抵抗、急冷して作る非晶質状態を高抵抗にする。

Joule加熱のパルスでセットとリセットを切り替えるお。[^108]

**やらない夫**：
高抵抗値は十年同じ場所に止まるか。

**やる夫**：
非晶質状態の抵抗は時間とともにdriftする。

二値なら余裕を取れても、多値化して判定窓を詰めれば隣へ近づく。

QLC NANDで見た、**状態は二つ以上作れても境界余裕が商品寿命を決める**問題だお。[^108]

しかも書込みは局所加熱だから、電流、熱拡散、隣接セル、耐久性も見る必要があるお。

**やる夫**：
次は抵抗変化RAM（resistive RAM, ReRAM）だお。

絶縁膜の中に導電filamentを作れば低抵抗、切れば高抵抗。

縦横配線の交点へ置くcross-point配列なら高密度だお。

**やらない夫**：
選んだセルを10kΩ、1Vで読む模型にしよう。

選択電流は。

**やる夫**：

$$I_{selected}=\frac{1\ \mathrm{V}}{10\ \mathrm{k\Omega}}=100\ \mathrm{\mu A}$$

余裕だお。

**やらない夫**：
選ばないセルを通る二素子直列の経路が63本あり、各経路を20kΩとする単純模型なら。

**やる夫**：
一本50μA。

63本で

$$I_{sneak}=63\times50\ \mathrm{\mu A}=3.15\ \mathrm{mA}$$

選択セルの31.5倍が脇道を流れるお！！

読みたい100μAが埋もれる。

これは実配列全体をそのまま表す回路ではないが、配列を増やすほど回り込み電流（sneak current）の候補も増える構造は分かるお。

**やらない夫**：
修正案は。

**やる夫**：
各抵抗素子へ非線形な選択素子を直列に置き、半選択電圧では流れず、選択電圧でだけ大電流を通す。

一素子で済むはずのセルが1S1Rになった。

選択素子にもドライブ電流、漏れ、耐久性、速度、CMOS工程との互換性が要るお。[^109]

**やらない夫**：
何が失敗原因だった。

**やる夫**：
単体セルの断面だけを見て、配列中の電流経路を消していた。

**セルを簡単にしても、選択の複雑さは消えず、別の場所へ移るだけ**だお。

**やる夫**：

$$Y\approx e^{-DA}$$

良品率$Y=0.62$、$A=1\ \mathrm{cm^2}$なら、

$$D=-\frac{\ln 0.62}{1\ \mathrm{cm^2}}\approx0.478\ \mathrm{個/cm^2}$$

という模型になるお。

実際の欠陥はclusterし、全欠陥が即死でもないから、これは面積効果を見る概念式だお。

**やらない夫**：

$$Y_{論理}=e^{-0.20\times4}\approx0.449$$

だから約45個。

$$Y_{メモリ}=e^{-0.20\times1}\approx0.819$$

だから約328個だお。

同じウェハ面積でも、大きいダイは一個が欠陥を踏む確率が高いお。

**やる夫**：
違う。

人間が境界を決めた。

境界のこちら側を0、あちら側を1と呼んだ。

でも呼ぶだけでは、揺らぎが境界を越えるお。

**やらない夫**：
越えそうになったら。

**やる夫**：
増幅して作り直す。

読み壊したら書き戻す。

時間で薄れたら更新する。

誤ったら訂正し、不良なら予備へ逃がす。

規格で外から見える意味まで揃える。

……0と1は材料の名前じゃない。

**連続で壊れ得る物理の上に、何層もの補正で維持している約束**なんだお。

### F-4　2748億ビットを買う

**やらない夫**：
それで、自作32GB製品の見積りはできたか。

**やる夫**：
できたお。

最初に決めた単位で、状態の数をもう一度書くお。

$$32\ \mathrm{GiB}=32\times2^{30}\ \mathrm{B}=256\ \mathrm{Gibit}$$

単位でまとめれば256Gibit。

でも1ビットずつ数えれば、274,877,906,944ビット――約2748億個だお。

普段なら大きな容量はGibitで書く。

ここだけは、工場が相手にする状態の数を隠さないために、あえて2748億ビットと呼ぶお。

**やらない夫**：
工場は。

**やる夫**：
露光、成膜、食刻、注入、洗浄、研磨、測定。

配線、切断、選別、封止、最終検査。

前工程だけでも1000を超える段階があり、Intelが示す典型的な工場例では製造装置約1200台、附帯設備約1500台、建設費約\$100億、完成まで3〜5年だったお。[^111]

**やらない夫**：
お前は最初、工場をどう見積もった。

**やる夫**：
砂へ0と1を印刷する機械を一台買えば終わると思ったお。

実際には、1ビットの曖昧さを小さくする工程を、2748億個へ同じように繰り返さなきゃいけない。

欠陥を測り、良品を選び、予備で直し、規格どおりの部品にして、何年も供給するところまでが製品だったお。

**やらない夫**：
店の5万5000円の公称32GB製品を、最初に決めた32GiB相当の模型で計算するなら、1円でどれだけ買える。

**やる夫**：

$$\frac{256\ \mathrm{Gibit}}{55{,}000\ \mathrm{円}}\approx5.0\ \mathrm{Mbit/円}$$

約5.0Mbitだお。

高い時点の小売例なのに、1円で500万個の状態と、その補正の仕組みまで買える。

……悔しいお。

値札に腹が立って始めたのに、市販品が異常に安いことまで分かってしまったお。

**やらない夫**：
最初の問いへ答えろ。

**やる夫**：
0と1を置くだけなのに、なぜ高いのか。

そう聞いたお。

でも、物質の中に最初から0と1が置いてあるわけじゃなかった。

**0と1が高いんじゃない。曖昧な物質を、0と1として信用できるところまで持っていく仕組みが高いんだお。**

**やらない夫**：
自作メモリは完成したのか。

**やる夫**：
完成させないお。

メモリ工場は3〜5年。ゲームの発売日は待ってくれない。

やらない電子の店長、最初に見せてくれた公称32GB組を売ってくれお。

いま確保すれば、発売日に間に合うかお。

**やらない夫**：
間に合う。

友人としては150年分も遠回りした客に呆れている。

店長としては、対応規格を確認してから買う客で助かっただろ。

**やる夫**：
……買ったお。

箱を開けたら、ただの黒いチップにしか見えなかったお。

でも今は、その何も見えない中に、150年分の失敗と約束が折り畳まれてるのが見える気がするお。

**やらない夫**：
まずは発売日にゲームを動かせ。

その後は、そのメモリで次の疑問を調べろ。

それが一番正しい使い方だろ。
