# 改訂記録：database-design（sol56-medium）

## 改訂方針

`review-opus-medium.md` の指摘を、既存の三原則・SQL・数式を崩さずに本文へ反映した。
追加人物の口調は、既存教材の `chemical-plant`、`periodic-table`、
`birthrate-and-aging`、`public-rulemaking` などを `rg` で横断して確認した。
できる子は「推測より測定値・記録・期限を短く置く」、できる夫は
「理解が速く技術案を勢いよく広げ、反例を受けて修正する」という傾向だった。
本作では総務の実運用を示す役にできる子を採用し、役割が重なるできる夫は追加しなかった。

## 具体的な変更

1. できる子をカモメ製作所の総務担当として登場人物欄へ追加した。
   2-3の口座聞き込みを想像上の問答から本人との会話へ変え、
   「複数口座は0人」「手動振込を足す社員は1人」という回答のずれから、
   質問の切り口が運用例外を発見する過程を見せた。

2. 物語上の圧力を追加した。グループ統合の切替を来年4月1日とし、
   組織改編と同日で延期不能とした。5-3では当日17時の再集計期限と
   総務2人・半日の手作業、7-1では税務調査の提出期限と銀行記録との差額説明を、
   できる子が数字で示す構成にした。第1幕にも切替と将来の税務調査を予告した。

3. 4-1のJSONB反例を二段階に分けた。最初のSQLは
   `SELECT DISTINCT key` だけを実行し、表記ゆれでキーが4種類になる事実を表示する。
   次のSUMでは `"10,000"` のnumeric変換エラーを表示し、結果表は出さない。
   これにより「集計結果が出た後に同じ集計がエラーになる」という矛盾を除いた。

4. 6-1の到達を一往復遅らせた。やる夫は退職フラグを戻し、再入社用の列を
   足す案にいったん固執する。その結果、社会保険の資格取得届が前回雇用の
   資格喪失と混線して差し戻される実害を置き、列追加では雇用単位の出来事を
   分離できないと自分で認識してから、人と雇用の分離へ到達するようにした。
   教師が「到達が速すぎる」と構成を説明する台詞は削除した。

5. 3-4へ有効期間照会の索引設計を追加した。排他制約が作るGiST索引に合わせて
   `daterange(...) @> 日付` と書き、`EXPLAIN (ANALYZE, BUFFERS)` で実行計画を
   確認する流れにした。社員単位では別索引が有利な場合もあるため、
   制約用索引の流用を決め打ちせず、実データで判断する注意も残した。

6. 4-2へNULLの三値論理を追加した。`grade = 5` だけでなく
   `grade <> 5` でもNULL行が落ちる実害を示し、意味を定めたうえで
   `IS DISTINCT FROM` などを選ぶ必要を説明した。

7. 6-2のUUID比較を定量化した。100万行INSERTの測定例として連番・UUIDv4・
   UUIDv7の時間と索引サイズを並べ、v7でも16バイト索引のコストは残るが、
   v4のランダム挿入コストは緩和されることを示した。値は環境依存なので、
   本番相当の書き込み量・キャッシュ・索引本数で再測定する条件を明記した。

8. 終幕の「使い方6箇条」は削除し、判断基準を各幕へ分散した。
   第2幕へ運用の隅と痛みの非対称性、第3幕へ質問からの逆算と期間索引、
   第6幕へ業務が同一性を決めることを置いた。最終幕は答え合わせ表と
   三原則に絞った。

9. やらない夫の「反例をやる」「攻撃する」「判定してもらう」という反復を、
   制約の穴、期間の閉じ忘れ、外部公開時の事情など、場面固有の問いへ置き換えた。
   追加・削除したやる夫の発言と、やらない夫の応答は対で見直した。
   ト書きや括弧書きの舞台指示は追加していない。
